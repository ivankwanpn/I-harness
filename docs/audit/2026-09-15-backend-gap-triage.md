**Funnel to real gaps.** Steps 1–4 remove the generator's own deliberate non-proposals; step 5 removes rows where IH demonstrably *has* the capability; step 6 is what is left to argue about. The arithmetic is deliberately sequential, not a set of independent subtractions.

1. **344** IH-less rows.
2. **−24 `路線差異`** — the generator's own note that the row exists but IH implements it in a different shape or in another domain. 7 of these literally say so in the rationale ("`ripgrep-backed-file-and-text-search-tools` … IH 已於 tools 域提供", "`instruction-file-ingestion` … IH 已於 context 域實作", "`user-question-request-surface` … IH 已於 service 域提供"). The rest are deliberate architecture differences (`no-os-level-sandbox-permission-only-confinement`, `canonical-turn-event-log`, `session-scoped-todo-store`, `settings-namespace-registry-and-file-persistence`).
3. **−9 `不做`** — the generator already ruled these out. 8 of the 9 also collide with the §5 policy (see §4); the ninth is `gated-delegation-modes-and-task-stubs`, excluded as an unreachable stub, not a capability.
4. **−62 `遠期`** — real capability, explicitly product-level or scale-dependent ("產品級，緩辦", "暫緩"). Deferred, not free.
5. **= 249 active rows** (`reuse` 51 + `rewrite` 198) — these are the rows the generator is actually proposing IH act on.
6. **−16 of those 249 that I verified as false gaps** — IH has the capability, filed under another domain or under a different mechanism name. They are listed below; each is a subset of the 249, so this step subtracts from step 5 and not from 344.
7. **= ~233 rows I would call genuine, unverified-by-hand gaps.** (249 − 16 = 233.) *Not* 249 + 16: the two subtractions are nested, which is the single easiest arithmetic error to make with this report.

**Where I could not tell.** The 16 false gaps are the ones I checked; they are not a complete list. I read the inventory's 65-package coverage table and the nine cross-package mainlines in full, then grepped ~40 targeted terms, but I did **not** re-derive each of the 249 active rows against the inventory line by line — that is a multi-day audit, not a memo. The residual error is one-directional: my 233 is **more likely to over-count than under-count**, because the row name in the report and the IH mechanism name in the matrix often differ (see the verified list) and I could only catch the pairs I happened to grep. **Confidence: high on 344 and on the per-domain table; medium-high on 249 actives; low-to-medium on 233 — treat that last figure as "225–245", not a precise count.**

**The 16 rows I verified as false gaps.** Twelve are exact or near-exact pairs; the IH mechanism named below is quoted from the inventory.

- **loop** `durable-inbox-projection-and-claim` → `four-tier-input-admission-with-durable-inbox-projection`: "The Inbox is a replay-once projection over three log events… a cold resume rebuilds pending from the log alone. - **session** `durable-task-notification-outbox` → `durable-notification-outbox-with-injectable-admission`.
- **session** `durable-projection-checkpoint-and-restore` → `derivemessages-wire-shape-enforcement` + `durable-restore-without-re-append`. IH never caches a derived projection; it recomputes from the log, so there is nothing to checkpoint. dsh and opencode need the cache because their projection is expensive — IH's design choice removes the row.
- **context** `deferred-tool-context-economy` → `deferred-tool-exposure-with-search-driven-promotion`.
- **tools** `tool-output-spill-with-head-tail-preview` → `two-layer-output-retention-and-spill` ("a pure byte-budget text retainer that keeps a head and/or tail… and a spill store"). The real remnant is that retention is opt-in at the shell boundary rather than uniform across every tool.
- **subagent** `durable-cancellation-tree` → `durable-delegated-task-protocol-with-identity-cas` plus spawn/interrupt/close/resume. **Partial:** IH has cancellation of an agent, not a rooted cascade with an admission window — counted as half a gap, not a full one.

- **retrieval** `cross-session-reference-snapshot-injection` → the session domain's `cross-session-reference-snapshot`; the same mechanism, filed twice in the matrix.
- **tools** `parallel-tool-execution-with-ordered-commit` → `ordered-tool-batch-commit-lane-with-bounded-concurrency`. The ordered commit lane exists; only the pool width may differ.

## 2. Themes, not rows

Eight themes cover the genuine active gaps that are worth ranking. Sizes are row counts after the §1 subtractions; "best source" is the source the report's own `who has it` line names. **The eight themes account for ~73 of the ~233 genuine rows; the other ~160 are named in §4 and §5 rather than themed here, because they are product decisions or already-excluded rows rather than engineering.**

**T1 — Durable turn state & crash adjudication (~11 rows: loop, session, subagent).** The turn is durable at its *ends* but not *within*: there is no attempt record with a lease/generation, no write-ahead checkpoint before the model or a tool is invoked, and no startup sweep that re-drives input accepted-but-never-run. IH has `durable-delegated-task-protocol-with-identity-cas` for *subagent tasks* and a tail-only log repair, which is exactly why the child side looks solved and the parent turn does not. Rows: `durable-turn-attempt-state-machine`, `durable-turn-runner-loop`, `pre-side-effect-durability-checkpoint`, `session-startup-recovery-of-admitted-input`, `initiator-causal-attribution-scope`, `turn-boundary-state-projection`, `pending-turn-coordinator-with-wake-coalescing`, `request-error-recovery-waterfall`, `stop-hook-continuation-loop`, `pre-step-injection-waterfall`. (The matrix also lists `seq-contiguity-and-branded-sequence-types`, a §1 false gap: the contiguity assertion on load exists, only the branded type is absent.) **Best: opencode-fork** (`durable-turn-attempt-state-machine`: 租約世代圍籬與崩潰裁決). *IH gains: a killed process stops being an ambiguous "did that tool run?" and becomes a recorded, resumable fact.*

**T2 — Context & prompt-cache continuity (~10 rows: context, model, hook seam).** IH has no concept of a prompt cache anywhere — grep for `cache` in the inventory returns instruction-file stat caches, discovery caches and Windows ACEs, and nothing about the request prefix. The session log *is* stable and append-only, which is the right substrate, but nothing tracks whether the bytes actually sent were the same as last call, and nothing tells the user when they stopped being. Rows: `canonical-request-epoch`, `prompt-cache-break-detection`, `api-facing-prompt-series-and-surface-generation`, `provider-reported-token-accounting`, `time-and-api-triggered-cache-aware-tool-result-clearing`, `post-compaction-derived-state-invalidation`, `hook-lifecycle-event-engine-and-control-effects` (a vendor-dialect hook firing per step is a cache-break source), `retained-tail-and-window-preserving-compaction`, `full-replace-compaction-with-transcript-pointer`, `context-epoch-generation-replacement`. **Best: dsh** (`canonical-request-epoch`, `api-facing-prompt-series-and-surface-generation`), with **cc-custom** owning the detection half (`prompt-cache-break-detection` "快取斷點偵測器未接通"). *IH gains: long sessions stop silently paying full price after every compaction.*

**T3 — Operator evidence & audit (~10 rows: ops, session, safety, model).** Telemetry exists as a host-side stream with a closed 20-row manifest and sink isolation, but there is no OTLP export, no in-process metrics registry, no structured local diagnostic log, no crash report, and no secret redaction on the way out. `retention-and-secret-redaction` and `secret-redaction-before-log-and-sink` are the same missing filter seen from two domains. Rows: `otlp-telemetry-export-with-span-attribution`, `local-structured-diagnostic-logging`, `in-process-diagnostics-metrics-registry`, `fail-loud-crash-handling-and-graceful-shutdown`, `session-telemetry-record-capture`, `retention-and-secret-redaction`, `secret-redaction-before-log-and-sink`, `timestamped-and-timed-tracing-macros`, `cli-self-diagnostics-command-surface`, `token-and-cost-accounting`. **Best: dsh** (broadest), **grok** for the redaction half. *IH gains: a failed run stops requiring re-reading a JSONL log by hand.*

**T4 — Tool execution pipeline hardening (~11 rows: tools, plus extension hooks).** The gaps that survive §1 are narrower than the theme name suggests: IH has guard-timeout/guard-retry/guard-repeat-tool, atomic writes, fs-lock, spill and retention. What it lacks is a *uniform* pipeline: tool-result schema validation, cancellation that cascades to sibling calls instead of failing the batch, the streaming executor (`streaming-tool-executor-mid-stream-start` "閘門恆假實為未接線"), the per-message aggregate budget (`per-message-aggregate-result-budget` "旗標恆假尚未生效"), and `formatter-dispatch-by-project-config`. Rows: `tool-execution-pipeline-with-hook-interception`, `tool-schema-definition-and-input-validation`, `tool-owned-semantic-precondition-validation`, `tool-call-cancellation-with-sibling-cascade`, `streaming-tool-executor-mid-stream-start`, `per-message-aggregate-result-budget`, `blocking-sleep-command-guard`, `backoff-ladder-with-server-signalled-doom-loop`, `pre-main-process-hardening`, `formatter-dispatch-by-project-config`, `repeated-identical-tool-call-guard` (IH's version is *advisory only* — the matrix cell is `repeat-call-nudge-guard-observational-never-blocking`). **Best: dsh** (pipeline + schema), **cc-custom** (the flags that were compiled out). *IH gains: one place where every tool call is validated, bounded and cancellable.*

**T5 — Wake, continuation & deferred autonomy (~7 rows: loop, subagent).** IH can be *told* things durably; it cannot *start itself*. `idle-wake-and-self-tick-initiation` ("閒置觸發須有來源與上限"), `proactive-self-tick-loop` ("實作完整但全站未接線"), `seven-input-auto-wake-suppression-gate` ("喚醒前七項抑制條件並存疑即不喚"), `mid-turn-injected-input-framing`, `turn-budget-ladder`, `early-stdin-capture-before-mount`, `durable-input-queue-with-steer-promotion` (IH has the durable inbox; what it lacks is promotion semantics that differ from steer). **Best: codex** (wake with a bound) and **grok** (the seven suppression conditions — the *safety* half, which matters more than the feature). *IH gains: scheduled/self-directed work that cannot turn into an unattended loop.*

**T6 — Agent-writable durable memory (5 rows: retrieval, context, extension).** There is no memory package in `packages/` (65 packages, none is memory). IH's continuity today is *files the human owns*: AGENTS.md/CLAUDE.md injection, skills, workspace documents, session-query over past logs. Nothing lets the agent write a durable fact that comes back next session. Rows: `durable-cross-session-memory-store`, `memory-recall-ranking-and-freshness`, `background-memory-extraction-and-consolidation`, `team-shared-memory-with-secret-guard`, `magic-doc-auto-update`. **Best: grok** (`/remember` + MEMORY.md) with **cc-custom** for recall ranking. *IH gains: the agent stops re-learning the same project facts — but see §3 item 5 and §4.*

**T7 — External interface & config hardening (~12 rows: service, interface, ops, retrieval).** The service domain is dominated by deferred product work (14 of its 36 rows are `遠期`: remote attach, relay, workspace routing, webhooks, sidecar supervision). The active subset is a real hardening cluster: connection handshake/capability gate, outbound backpressure, Basic auth with public-path exemptions, service self-auth, and `http-fetch-with-public-address-pinning` (IH ships a `webfetch` tool with a trust-notice envelope but the report's point is that it has "缺位址釘選" — no SSRF address pinning). Rows: `連線初始化握手與能力閘門`, `連線輸出背壓與過載控制`, `服務 Basic 認證與豁免規則`, `服務自身認證（啟動權杖）`, `瀏覽器來源信任圍籬`, `NDJSON 行完整性防護`, `單向 JSONL 輸出與退出碼契約`, `使用者訊息重播與去重`, `http-fetch-with-public-address-pinning`, `回環就緒狀態與日誌診斷端點`, `settings-seam`, `operator-config-layer-stack`. **Best: codex** (handshake + backpressure, both one-liners in the report: "值得做"), **dsh** for the config seams — and the config rows are the real prize here, because 2026-09-14's compaction-wiring bug was a *settings/assembly contract* failure, not a compaction failure. *IH gains: a web host that stays correct under a slow client and an untrusted page.*

**T8 — Plugin, skill & MCP ecosystem depth (~13 rows: extension, service, retrieval, context).** IH's plugin story is deliberately static (never executes plugin code, which is a *strength* here), so most of this theme is about the ecosystem surface around it: skills need catalog/guidance injection and implicit invocation, MCP needs transport variants, catalog ingest hardening, elicitation, and resources, and the host has no MCP *server* mode. Rows: `filesystem-skill-discovery-and-root-precedence`, `skill-registry-layered-precedence-and-caching`, `skill-catalog-and-guidance-injection`, `explicit-and-implicit-skill-invocation`, `bundled-skill-registry-with-lazy-extraction`, `mcp-transport-variants-and-startup-negotiation`, `mcp-tool-catalog-ingest-and-exposure-hardening`, `mcp-elicitation-and-server-initiated-input`, `mcp-resource-retrieval-tools`, `以 MCP 伺服器模式暴露自身` (json `mcp-server-mode-over-stdio`), `plugin-runtime-state-and-readiness-reporting`, `workspace-instruction-baseline-and-change-projection`, `subagent-bundle-cache-with-user-edit-preservation`. **Best: dsh** (skills + plugin state), **codex/grok** (MCP ingest). *IH gains: MCP and skills stop being shallow integrations.*

## 3. Ranked short list — the next five threads

Ranked by (real gap) × (leverage) ÷ (cost). A ranking where everything is important is not a ranking, so each entry names what it beats and why.

**1. Durable turn state machine and crash adjudication (T1).**
*Evidence:* `durable-turn-attempt-state-machine` is IH-less while the *subagent* task protocol is not — the matrix's IH cell for the delegated case is `durable-delegated-task-protocol-with-identity-cas` with crash recovery by log classification, so the parent turn is the side with no lease/generation. `pre-side-effect-durability-checkpoint` is described in the report as "極小但值得自建", and `durable-restore-without-re-append` shows IH already knows how to restore a log without re-appending it. This is the only theme where a crash produces a *wrong answer* rather than a missing feature.
*Cost:* small-to-medium, and unusually well-contained — `core-agent` (attempt record + checkpoint emit), `core-session` (event types), `session-persistence` + `session-persistence-jsonl` (flush before side effect; both already have fsync/rename discipline), `session-executor` (startup sweep). No new package needed.
*Unlocks:* honest resume, and it is the prerequisite for T5 (a self-tick with no attempt record is an unattended loop generator).

**2. Context and prompt-cache continuity (T2).**
*Evidence:* `prompt-cache-break-detection` ("快取斷點偵測器未接通") and `canonical-request-epoch` ("快取連續性可當持久事實") have no IH counterpart — grep for `cache` across the inventory returns instruction-file stat caches, model-discovery caches and Windows ACEs, and nothing about the request prefix. `provider-reported-token-accounting` is real: `token-meter`'s rule is `chars/4` heuristics, and `token/usage` exists as a telemetry event but is not the accounting basis. `post-compaction-derived-state-invalidation` ("壓縮後清快取避免陳舊"). The timing is the argument: compaction was only wired into shipped hosts on 2026-09-14, so the moment it starts firing, IH starts invalidating request prefixes it has never measured.
*Cost:* medium — `llm-seam` (epoch/cache-key vocabulary), the five `llm-*` adapters (cache-usage fields), `provider`/`provider-runtime` (cache pricing metadata), `token-meter` (a second accounting axis), `compaction` (invalidation on rewrite).
*Unlocks:* measured cost per session and a visible answer to "why did this turn cost 3× the last one".

**3. Tool pipeline uniformity (T4).**
*Evidence:* three rows that are not "missing code" but "code that is false" — `streaming-tool-executor-mid-stream-start` ("閘門恆假實為未接線"), `per-message-aggregate-result-budget` ("旗標恆假尚未生效"), `blocking-sleep-command-guard` ("檢查被編譯掉未生效"); plus `tool-call-cancellation-with-sibling-cascade` and `tool-schema-definition-and-input-validation`. IH already has the guard chain (`tools/pre-execute` waterfall, `tools/execute` cascade, `tools/post-execute`) — this thread lands inside an existing seam instead of creating one.
*Cost:* small-to-medium — `core-tools` (validation stage), `core-agent` (sibling cancellation), `guard-*` (the three dead flags), `output-retention` (aggregate budget). Mostly wiring.
*Unlocks:* one honest contract for "what a tool call may consume", instead of four partial ones.

**4. Operator evidence (T3).**
*Evidence:* `fail-loud-crash-handling-and-graceful-shutdown` ("IH 無崩潰處理；可補事後報告"), `local-structured-diagnostic-logging`, `otlp-telemetry-export-with-span-attribution` (the report's `who has it` line names **all six** other sources: dsh+codex+opencode+opencode-fork+grok+cc-custom — it is the closest thing in the matrix to a universal capability IH lacks), `retention-and-secret-redaction` + `secret-redaction-before-log-and-sink`.
*Cost:* small, and it is the one theme with a *single* natural home: `ops` is not a package — the surface is `telemetry` (manifest + sinks already exist) plus `apps/cli`. Additive, no engine change.
*Unlocks:* the feedback loop for every other thread on this list. Ranked below 1–3 only because it makes failures *legible* rather than *impossible*.

**5. Plugin/skill/MCP ecosystem depth (T8).**
*Evidence:* the largest active cluster after safety (13 rows), and IH's own foundation is already good (`plugin-event-kernel-with-four-extension-channels`, `skill-md-deferred-retrieval-with-a-shadow-selector`, `mcp-client-with-generation-based-reconnection-and-oauth`) — which is exactly why the remaining rows are shallow gaps rather than structural ones.
*Cost:* medium and incremental — `skills`, `mcp-client`, `plugin-registry`, `hooks`, `tool-search`.
*Unlocks:* third-party harnesses can consume IH (MCP server mode) and skills become discoverable rather than merely loadable.

**Deliberately not in the top five: T5 (wake/autonomy)** — genuinely useful, but it multiplies whatever the turn state machine can guarantee, so it is ranked 6th *by dependency*, not by value. **T6 (memory)** is 7th and is a product question first (§5). **T7 (interface hardening)** is cheap; I would take the two "值得做" rows (handshake, backpressure) plus `settings-seam`/`operator-config-layer-stack` as opportunistic work alongside thread 4, and leave the rest of the service domain as deferred product scope. **This ranking is a floor, not a ceiling:** it deliberately does not attempt to order the ~160 genuine rows I verified as gap-shaped but did not group into a theme, because almost all of them are deferred product scope (§4) rather than engineering.

## 4. What is probably NOT worth doing

`docs/superpowers/specs/2026-09-14-backend-permission-sandbox-design.md` §5 is a **constraint, not a menu** ("本節是約束，不是建議… 要推翻必須先改這份文件並說明理由"). Three themes collide with it:

1. **The permission-rule-engine cluster is already excluded, and it is the single biggest block in the safety domain.** §5 rules out a configurable rule ladder because it creates two sources of truth: "規則說可以、沙箱說不行". Rows that are therefore *not* proposals: `permission-rule-evaluation-and-precedence`, `core-permission-service-with-pending-ask-and-uninterruptible-assert`, `permission-ask-queue-with-remembered-approvals`, `permission-ask-plugin-seam`, `session-permission-ruleset-persistence`, `permission-ruleset-v1-to-v2-migration`, `permission-preset-bundling-over-mode-and-approval-knobs`, `dangerous-allow-rule-stripping`, `permission-rule-shadow-detection`, `permission-profile-model-with-requirement-catalog`. That is **10 of safety's 33 active rows** — the domain is a third smaller than "45" suggests once the policy is applied. Same treatment for the enterprise layer (`managed-policy-layer-with-root-owned-pin`, `macos-mdm-forced-managed-preferences`, `signed-policy-at-rest-fail-closed-arm`, `bypass-permissions-organization-killswitch`: "取了會是儀式而非安全") and `auto-mode-llm-danger-classifier` ("IH 已經有 guardian… 方向相反，同時裝會互相抵消"). §5's own ordering (§6) already sequences what remains; nothing in this memo should be read as re-opening it.
2. **Any theme that would make IH execute foreign code is excluded.** §5's rule ladder ban plus the plugin policy (`plugin-lifecycle-that-never-executes-plugin-code`) mean these are not gaps to close: `plugin-package-execution-in-vm-realm`, `sandboxed-code-execution-substrate`, `code-mode-javascript-host`, all tagged `不做` with the same rationale ("執行模型程式碼違反 IH 原則"). `ptc-tool-collapse-and-generated-sdk` is the same family.
3. **T6 as "build a memory subsystem" is not yet justified.** IH's continuity is deliberately file-based and human-owned (AGENTS.md injection, skills, workspace docs). A first-class agent-writable memory store would add a second place where durable agent state lives, next to the session log — the same two-sources-of-truth failure §5 rejects for permissions, and it would need exactly the trust gate §5 flags as an open question (`build-provenance-folder-trust-gate`). Cheaper substitutes already exist: `session-query`'s `session_search`/`lineage` over past logs, and workspace documents. **Recommendation: do not start T6 in this cycle; answer §5's project-trust question first.**

Also low value, with reasons: **most of `service`** — 14 of its 36 rows are `遠期` product-level (remote attach, relay, workspace routing, sidecar supervision, PTY tickets, voice dictation) with no consumer yet; `service-controller-remote-facade` and `cross-session-reference-snapshot` are large and unlock nothing IH currently ships. **`origin-scoped-transport-prewarm`** — a latency optimisation, "非核心". **`remote-sandbox-execution-backends`**, **`host-tool-definition-compat-shims`** ("IH 無舊定義相容包袱"), **`plugin-v1-compatibility-bridge`** ("IH 無舊帳") — all backward-compatibility scaffolding for debts IH does not have. **`early-stdin-capture-before-mount`** — TUI plumbing, real but tiny.

## 5. Open questions for the human

1. **Is an idle/self-tick agent a product goal at all?** T5's rows are implementable, but `idle-wake-and-self-tick-initiation` ("閒置觸發須有來源與上限") and `seven-input-auto-wake-suppression-gate` are *policy* rows masquerading as engineering. Without an answer, any T5 work is speculative.
2. **Does IH need cross-session memory, or is file-based continuity (AGENTS.md + workspace docs + session search) the intended answer?** This decides whether T6 is a thread or a non-goal, and it is the same question as §5's project-layer trust gate ("牽涉產品定位，我沒有足夠資訊下判斷").
3. **Who is the second consumer?** `以 MCP 伺服器模式暴露自身` (json `mcp-server-mode-over-stdio`), typed RPC surfaces and the remote-service rows are only worth their cost if something other than IH's own TUI drives IH. Nothing in the repo answers this.
4. **Is operator observability in scope for a single-developer host?** T3 is cheap, but OTLP export in particular is only useful if there is a collector to export to; a local structured log may be the whole win.
5. **What is the budget for prompt-cache work given multiple providers?** The cache semantics differ per wire protocol (Anthropic explicit breakpoints vs OpenAI automatic prefix matching), so "one epoch concept" may be the wrong abstraction — this is a design decision the human should make before the thread is sized.
6. **Is `terminal` PTY supposed to work under confinement?** ~~§6 defers this as a product call ("TUI 的 PTY 功能在受限模式下會消失。這是**產品決定**，不是技術決定"). It blocks a clean answer for part of T7.~~ **CLOSED on 2026-09-15 — the premise was wrong, and the question is not a product call.** `node-pty` is a **devDependency** of `tui` and `tui-core` (test harness only); `packages/tui/src` spawns editors and pagers with plain `child_process.spawn`, and the TUI does not use `terminal/service` at all. The only production PTY consumer is `packages/terminal` — the **model's** tools. So the impact is "can the model open a PTY", not "does the TUI lose a feature", and the answer is the engineering one the spec already gives: refuse the capability-creating calls under a confined mode. See `docs/superpowers/specs/2026-09-14-backend-permission-sandbox-design.md` §3.4 (corrected) and `docs/superpowers/plans/2026-09-15-terminal-confinement-refusal.md`.
