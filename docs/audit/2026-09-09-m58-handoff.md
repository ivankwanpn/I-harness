### 精確性規則（本切片的核心，spec §3）

`unseen` ≠「git 髒檔案」。git 髒檔案裡有 **agent 自己未提交的記錄**——那引擎其實「知道」。故以日誌的 `afterHash` 作解釋器：

| 情況 | 處置 |
|---|---|
| 在目標回合的 files | 跳過（plan 已以 clean/conflict/op 分類） |
| 在 `unTracked`（後續回合記錄／orphan） | 跳過（已列出） |
| 曾在**更早**回合記錄 → 取最新 `afterHash` vs 現盤 hash | 相等 → 跳過（recorder 最後看到後未變＝自己的未提交工作）；不同（或記錄為刪除後重現）→ **unseen** |
| 從未被任何回合記錄 | **unseen** |

## 3. 裁定與取捨

1. **顯式注入，不默認開**：`RewindServiceOptions.gitProbe` 缺席＝關。理由：引擎保持純日誌、單元測試零 spawn、呼叫點顯式組合（與 store/recorder 同風格）。產品兩處（TUI embedded / CLI）已注入。
2. **只列不修**：`unseen` 的路徑永不進 `ops`（與 M54 orphanedTurns 同款：引擎不還原它沒捕捉過的東西）。
3. **R 改名報兩條**（新=modified、舊=deleted），C 只報新——兩者都是現盤事實。
4. **TUI 呈現不在本切片**：先例＝M54 `orphanedTurns` 同樣只進引擎 plan、未進 TUI/wire。已進 SDK wire 型別（外部契約加性），TUI 呈現列後續。
5. **不新增依賴**：只用 Node 內建。

## 4. 已知殘留（刻意或範圍外）

- **TUI 不顯示 `unseen`**：資料已到 `BackendClient.rewind.plan` 的回傳物件，view 未渲染——後續小切片（confirm 相位加 `? {path} (unseen)` 列）。
- **B 案（git checkpoint 引擎）不做**：能覆蓋 shell/外部變更的「還原」需要寫 git 物件/覆蓋 agent 沒寫過的東西——m52 調研判為需產品需求 + `RewindBackend` 抽象；**C 案（動使用者 repo）never**。
- **多 session 歸屬未解**：同一 workspace 兩個 session 各自的 journal 互不知情（m52 §1.2 缺口 2）——git 只是讓它更可見，沒有修。
- **`.gitignore` 內的檔案不會出現**：git status 尊重 ignore——這是特性（使用者已聲明不關心），也意味「被 ignore 的 shell 變更」仍隱形。
