# Desktop workflow capability gaps — 2026-09-28

This is a source-level scope check for the remaining Desktop workbench UI. It distinguishes an implemented domain package from a capability mounted by the current Desktop host. The current evidence is the `codex/desktop-workbench` tree; it is not a claim that every historical session lacks these events or that another host cannot enable them.

| Surface | Existing implementation | Current Desktop composition | UI decision |
| --- | --- | --- | --- |
| Todo | `@i-harness/todo` supplies `todo_write` and a last-snapshot fold. `session-executor` mounts the tool. | The new `desktop/session/work-state` reads the full live/cold session log. A real playground session contains `todo/write`. | Implemented in **任務** with completed count, bounded paging and accessible statuses. |
| Live subagent/job/workflow tasks | `SessionAssembly.tasks()` projects live task rows, and SDK `session/tasks` serves them. | Desktop already reads `session/tasks`; the Tasks pane displays and can cancel rows according to backend `canCancel`. A cold session honestly returns no live rows. | Existing UI stays the active-task authority. Do not infer persisted task completion from its empty response. |
| Durable background job history | `@i-harness/jobs` folds `job/status` events. Subagent persistence can emit those events when `jobStatusEvents: true`. | The Desktop host's `createSessionService` options do not set `jobStatusEvents`; the playground active-session inventory found no `job/status` events. | A durable job-history panel needs an explicit host composition decision and tests before UI. |
| Agent team roster/task board | `@i-harness/agent-team` has `foldTeam`, roster/task tools and `mountAgentTeams`. Assembly mounts them only when `opts.team` is defined. | The Desktop host does not pass `team` in its service options; the playground active-session inventory found no `team/*` events. | Do not fabricate a teammate/task board in Desktop. Enabling the backend needs tool-name/conflict and lifecycle review first. |
| Goal | `@i-harness/goal` folds and validates `goal/change` snapshots. | The new Desktop read endpoint can display an existing event, but source search found no normal Goal mutation tool or Desktop route; the playground active sessions have no Goal event. | Keep the banner read-only and conditional. Goal editing needs a real producer and authority contract. |
| Plan mode | `@i-harness/plan-mode` defines `enterPlanMode` and `exit_plan_mode`; the CLI calls `enterPlanMode` for `--plan-mode`. | No Desktop route enters Plan Mode in a selected session. | A Plan Mode switch needs a backend admission/control path, so no UI toggle is shown. |
| Agent browser control | Desktop has a user-operated WebContentsView with scoped IPC. | No Agent browser-control tool is mounted by the Desktop session runtime. | Keep the human browser pane; defer Agent browser-control settings, as requested. |
| Approval defaults | Per-call approval and sandbox escalation are wired. `AgentSettings` saves `sandboxMode` and `autoCompaction`. | No global approval-policy setting is present in the current settings schema or Desktop adapter. | Do not show a ZCode-style approval-default control backed by invented state. |

Other explicit deferrals remain: keyboard-shortcut settings, data/statistics pages, and Provider account usage/reset/OAuth. The next workbench UI pass should target verified live host data or first establish the missing composition contract in a separate backend change; an event type or a domain package alone is insufficient proof of a usable Desktop feature.

Evidence locations: `packages/session-executor/src/assembly.ts` (`opts.team`, `jobStatusEvents`), `packages/desktop-gateway/src/host.ts` (Desktop service options), `packages/sdk/src/server.ts` (`session/tasks`), `packages/goal/src/index.ts`, `packages/plan-mode/src/index.ts`, and the read-only playground inventory at `D:\frontend-research\desktop-session-event-inventory.mjs`.
