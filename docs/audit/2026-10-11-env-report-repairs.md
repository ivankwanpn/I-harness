# Environment report repair audit

This audit tracks the repairs based on `I-HARNESS-ENV-TEST-REPORT.md`, whose
tested baseline was c434332e. The report's analysis-only instructions describe
the original test. The subsequent user request authorizes these repairs and
requires IH's existing formats and unified runtime representation to remain.

The implementation is on `codex/env-report-repairs`, targeting Desktop 0.1.6.
Live user settings, history, installed plugins and stored indexes are read-only
evidence. Tests use isolated fixtures and explicit mock or loopback providers.

## Unified representations and plugin fixtures

Existing source discriminators (`git-subdir`, `url`, `github`, `git`, `directory`,
`file`) and string shorthands feed `RuntimeInputs`. Skills, Commands, MCP,
Agents and hooks retain their existing consumers. Native v1 and supported
installed Claude hook declarations share `HookHandlerSpec`, current content
grants, mounted authority and tool dispatch. Provider adapters continue to use
the common LLM/session contracts across the five supported model protocols.

Unmodified Apache-2.0 fixtures are pinned to
[claude-plugins-official b8e53f1c](https://github.com/anthropics/claude-plugins-official/tree/b8e53f1c05dff3b6d751297f6527990ffc81c2f4):
explanatory-output-style, feature-dev, Hookify and Ralph Loop. Tests execute real
scripts and actual bounded role tools. Ralph Loop performs another mock-model
step, reads the owned transcript and completes through its promise.

The adapter supports the nine matching synchronous command events. Unsupported
async/rewake/conditional or other handler forms and input/permission/output
mutations receive explicit diagnostics. Native Bash, Python 3, jq or Perl remain
prerequisites where the original plugin needs them. See
[the compatibility matrix](../PLUGIN-COMPATIBILITY.md) for exact coverage.

## Independent review follow-ups

Independent review reproduced and repaired additional lifecycle gaps:

- Shared-index joins and force refreshes checked actual affected source scope
  before gaining a job binding or draining another session's work.
- An owner abort during ordered finalization suppresses later post-tool effects
  while retaining one real completed result.
- Completed tool output survives owner cancellation before/during a post hook;
  genuine hook/policy failures remain loud.
- Actual ephemeral children carry lineage and seed boundaries, so their
  SubagentStop and transcript projection use the owned child suffix.
- Windows hook subprocesses retain a real Job after launcher exit and await
  root, tree, I/O and release settlement; timeout/abort cancel that owned Job.
- Known incomplete I/O wakes failed readers, and incomplete settlement is
  reported after real release acknowledgment without waiting indefinitely for
  streams or an unavailable root observation.
- Native hook command lookup preserves file candidates, child-relative PATH,
  relative cwd, Windows environment casing and empty values.

The hook review closed all five findings on its final revision: 125 hook tests,
21 Desktop integrations and seven CLI integrations passed independently.
Retrieval's final focused set passed 169 tests. These readings are scoped; they
do not replace the final repository verification or native adapter qualification.

The final native review closed all seven findings: output truncation, relative
HOME/PATH fidelity, ANSI config behavior, output EOF before root exit, derived
bytes not read back after staging, blocked-input control/reaping and nonlocal
