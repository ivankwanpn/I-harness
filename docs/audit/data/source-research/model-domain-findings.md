### classifier-driven-retry-ladder

- what: One error classifier drives one retry loop for all three API backends. `RetryPolicy` (`max_retries`, `rate_limit_retry_threshold`, `retry_only_before_output`) is owned by the actor state and cloned per submitted request; `run_request_task` runs the attempt loop, and every failure is funnelled through `classify_error(err, retry_count, max_retries, rate_limit_threshold) -> RetryDecision` (`Retry {backoff}`, `RetryWithBackoff{is_rate_limited}`, `RetryWithImageStrip`, `RetryWithClientRebuild{backoff}`, `EmitToSession`, `Fatal`). `apply_retry_decision` performs the side effects of each decision: increments the budget, emits a `Retrying` event, sleeps cancellably (`sleep_or_cancel`), destructively strips images from the outgoing `ConversationRequest` via `request.strip_images()`, or rebuilds `SamplingClient` with `force_http1 = true` to escape a poisoned HTTP/2 pool. Classification itself is a fixed precedence ladder: auth → encrypted-content → `max_retries == 0` → image/byte-size remediation → retry veto → doom-loop → rate limit → retryable → fatal.
- invariants:
  1. Budget precedence is env > model/per-request > default, and an explicit `0` is preserved as "no retries" rather than being replaced by the default (`config.max_retries.or(Some(retry_policy.max_retries))`, then `if configured_max_retries == Some(0) { 0 } else { resolve_max_retries(..) }`).
  2. The 429 layer is bounded by `max_retries.min(rate_limit_threshold)`, so a rate-limit retry can never consume the full transport budget; `rate_limit_retry_threshold == 0` is remapped to `RATE_LIMIT_RETRY_THRESHOLD`, so a zeroed config cannot disable 429 handling entirely.
  3. `RetryWithImageStrip` with nothing left to strip must upgrade to fatal — otherwise the loop spins forever stripping nothing.
- failurePolicy: **mixed**. Transport/5xx/stream errors are fail-soft (retried with jittered exponential backoff, ceiling 30 s, up to 15 attempts); deterministic request-shaped errors are fail-fast (`Fatal`, no budget spent); auth and encrypted-content errors are never retried by this ladder but handed up with `EmitToSession`. On exhaustion the request terminates as `SamplingEvent::Failed` plus `Err(SamplingError)`, and a `http.retries_exhausted` span is emitted only for true budget exhaustion (a server `x-should-retry: false` is `Fatal` but not "exhausted").
- constants:
  - `DEFAULT_MAX_RETRIES = 15` (`crates/codegen/xai-grok-sampler/src/retry.rs:9`)
  - `RATE_LIMIT_RETRY_THRESHOLD = 2`, `RATE_LIMIT_RETRY_DISABLED = 1` (`crates/codegen/xai-grok-sampler/src/retry.rs:5,7`)
  - `MAX_RETRY_BACKOFF = 30s`, `TRANSPORT_REBUILD_BACKOFF = 200ms` (`crates/codegen/xai-grok-sampler/src/retry.rs:11,13`)
  - env `GROK_MAX_RETRIES` overrides both model and default (`crates/codegen/xai-grok-sampler/src/retry.rs:26`)
- evidence:
  - `crates/codegen/xai-grok-sampler/src/retry.rs:95-163` — `classify_error` body, including the 429 cap at `:132` and the first-retry rebuild at `:150-156`.
  - `crates/codegen/xai-grok-sampler/src/actor/request_task.rs:94-98` — `max_retries` resolution preserving `Some(0)`.
  - `crates/codegen/xai-grok-sampler/src/actor/request_task.rs:453-475` — `RetryWithClientRebuild` arm: `http1_config.force_http1 = true` then `SamplingClient::new(http1_config)`.
  - `crates/codegen/xai-grok-sampler/src/actor/request_task.rs:411-418` — image-strip arm; empty strip set upgrades to fatal.
- notes: Not gated. The shared veto rule lives in `xai-grok-sampling-types` (`is_retry_vetoed` = `x-should-retry: false` OR context-length overflow, `crates/codegen/xai-grok-sampling-types/src/error.rs:562-564`), so the sampler actor and one-shot callers cannot drift. `retry_only_before_output` defaults to `false` (`crates/codegen/xai-grok-sampler/src/config.rs:180`); the shipping shell sets it for token-budgeted/subagent turns and additionally clears `doom_loop_recovery` in that case (`crates/codegen/xai-grok-shell/src/session/acp_session_impl/spawn.rs:1283-1295`).

### doom-loop-detect-and-guided-resample

- what: Opt-in server-side reasoning-loop detection with a guided resample budget of its own. When `SamplerConfig::doom_loop_recovery: Option<DoomLoopRecoveryPolicy>` is set, the streaming Responses request carries `x-grok-doom-loop-check: <window_tokens>` and `x-grok-exact-repetition-check: 64`, and the Layer-1 SSE decoder gets a fresh `DoomLoopSignalCollector` per attempt. `DoomLoopSignalCollector::absorb(event_name, data)` peeks every raw frame through `peek_doom_loop`: it swallows the non-standard `response.doom_loop_check` event (which the typed `async_openai` parser does not know) and records the cumulative trigger set, deduplicated by raw label, capped at 64 signals × 256 bytes. `DoomLoopRecoveryPolicy::is_confident` is deliberately narrow — only `tail_repetition:{t}@thinking` with `t <= max_threshold` counts — and `abort_triggers()` turns a confident signal into a mid-stream abort that surfaces as `SamplingError::DoomLoopDetected`. The retry loop gives doom failures a budget separate from the transport budget; it retains the failed turn's completed wire items (`FailedResponseCapture::take_items`) plus a `RECOVERY_REMINDER` system message, appends them to the request, and resamples. When the resample budget is spent, `disarm_abort()` is called on the next attempt so it completes and is accepted as-is, with a `accepted_after_budget` warning.
- invariants:
  1. Absence of the policy *is* the off state — there is no separate enabled flag to keep in sync, and `None` sends no header and does no per-event peek work.
  2. Doom resamples never debit the transport/empty retry budget; conversely, no classifier change can silently charge a doom failure to the transport budget.
  3. Only the thinking channel at a tight tail-repetition threshold is actionable; `low_logprob`, `exact_repetition`, `@response`, unknown kinds, and looser thresholds are warn-only.
  4. Replay is bounded per turn (`MAX_RECOVERY_REASONING_BYTES` + `MAX_RECOVERY_TEXT_BYTES`), and a turn that made a tool call is dropped whole because an orphaned reasoning item is rejected by the API.
- failurePolicy: **fail-soft**. Every parser in this path is best-effort by construction ("malformed payloads yield `Unknown` kinds or empty trigger sets, never an error. The feature can never fail a stream"). A poisoned capture lock degrades to a reminder-only retry rather than failing the request; a malformed check payload is logged once per attempt and ignored.
- constants:
  - `DEFAULT_MAX_THRESHOLD = 64`, `DEFAULT_MAX_RETRIES = 2`, `DEFAULT_RECOVERY_WINDOW_TOKENS = 1024` (`crates/codegen/xai-grok-sampling-types/src/doom_loop.rs:83-85`)
  - `MAX_RETRIES_RANGE = 0..=5`, `MAX_THRESHOLD_RANGE = 2..=64`, `WINDOW_TOKENS_RANGE = 512..=4096` with out-of-range window **falling back to 4096, not the floor** (`crates/codegen/xai-grok-sampling-types/src/doom_loop.rs:80-87,106-112`)
  - `DEFAULT_EXACT_REPETITION_MIN_TOKENS = 64` (`crates/codegen/xai-grok-sampling-types/src/doom_loop.rs:28`)
  - `MAX_COLLECTED_DOOM_LOOP_SIGNALS = 64`, `MAX_DOOM_LOOP_SIGNAL_BYTES = 256` (`crates/codegen/xai-grok-sampler/src/doom_loop.rs:15-16`); `MAX_RECOVERY_REASONING_BYTES = 8*1024`, `MAX_RECOVERY_TEXT_BYTES = 4*1024` (`crates/codegen/xai-grok-sampler/src/doom_loop_recovery.rs:29-30`)
- evidence:
  - `crates/codegen/xai-grok-sampling-types/src/doom_loop.rs:116-129` — `is_confident` / `confident_triggers`.
  - `crates/codegen/xai-grok-sampler/src/client.rs:1366-1373` — the two opt-in headers actually set on the streaming Responses request.

### credential-seam-and-401-attribution

- what: `xai-grok-auth` is a dependency-inversion seam, not an auth implementation. It exposes `HttpAuth::apply` (header construction, implemented in `xai-grok-shell` by `GrokAuthCredentials`), `AuthCredentialProvider` (`snapshot() -> CredentialSnapshot`, `async refresh_after_unauthorized() -> bool`, `needs_token_auth_header()`, `has_usable_credential()`), and a single shared truncation helper `bearer_suffix`/`BEARER_SUFFIX_LEN = 12` used by every 401-attribution site. The sampler consumes it in exactly two places: `SamplerConfig::bearer_resolver` makes the resolver the *sole* auth source in `SamplingClient::post` (it deletes any construction-time `Authorization`/`x-api-key` and re-stamps from `current_bearer()`, sending no credential at all when the resolver returns `None`), and `SamplerConfig::attribution_callback` is invoked at each of the six 401 arms with the bearer tail that actually went on the wire, captured at build time into `SentRequest::sent_bearer`. The 401 error carries `SentCredential` provenance (`Sent`/`Missing`/`Unknown`) derived from that fragment.
- invariants:
  1. `snapshot().token` MUST mirror the bearer `HttpAuth::apply` puts on the wire, or 401-attribution prefixes stop matching the real request.
  2. 401 attribution must read the build-time captured fragment, never a record-time re-resolve — re-resolving races the refresh the 401 itself triggers.
  3. `SentCredential::Unknown` is the fail-closed default: retry policies treat it like `Sent`, i.e. terminate rather than retry forever.
- failurePolicy: **fail-closed on credentials, fail-soft on telemetry**. A wired resolver returning `None` strips the credential rather than sending a stale seed key; the transport ladder never retries a 401 (`is_auth_error` → `EmitToSession`); the attribution callback is optional and `None` makes every 401 site silent, so a deserialized config that lost the callback silently loses attribution rather than failing. `apply_auth_header` logs a warning and sends no Authorization if the header value is un-buildable.
- constants:
  - `BEARER_SUFFIX_LEN = 12` (`crates/codegen/xai-grok-auth/src/bearer_fragment.rs:6`)
  - `AuthRetryMiddleware::new(credentials, max_retries)` — the 401 retry count is constructor-supplied, not fixed (`crates/codegen/xai-grok-auth/src/retry_middleware.rs:36-41`); call sites pass `1` or `0`.
  - 12-char truncation for the logged `x-api-key` prefix and 20-char for `Authorization` in the sampling log (`crates/codegen/xai-grok-sampler/src/client.rs:694-701`)
  - `env_http_headers` (header name → env var) are resolved into request headers at client build and deliberately never persisted (`crates/codegen/xai-grok-sampler/src/client.rs:553-558`)
- evidence:
  - `crates/codegen/xai-grok-auth/src/auth_provider.rs:34-57` — the trait, including `needs_token_auth_header` defaulting to `true` and `has_usable_credential` defaulting to `true`.
  - `crates/codegen/xai-grok-sampler/src/client.rs:674-692` — resolver-authoritative precedence: remove `AUTHORIZATION` + `x-api-key`, then re-insert only if `current_bearer()` yields a value.
  - `crates/codegen/xai-grok-sampler/src/attribution.rs:50-58` — `Auth401AttributionCallback::record_401(consumer, sent_bearer_suffix)` with the truncation contract.
  - `crates/codegen/xai-grok-sampling-types/src/error.rs:86-131` — `SentCredential` with `#[default] Unknown` documented as fail-closed, plus `from_sent_fragment`.

### shared-transport-pool-and-prewarm

- what: A process-wide HTTP transport with a warm-up dial. `shared_http.rs` holds two `OnceLock<reqwest::Client>` singletons — an HTTP/2 pooled client (`SHARED_H2`) and a pool-less HTTP/1.1 fallback (`SHARED_HTTP1`) — built through `xai_grok_extra_ca::build_reqwest_client` with `pool_max_idle_per_host`, `pool_idle_timeout`, `connect_timeout`, `tcp_nodelay`, and h2 keepalive (15 s ping / 5 s timeout / alive while idle). Sharing is safe because the builders take no config-derived input: auth, extra headers, base URL and User-Agent are applied per request in `SamplingClient::post`. `prewarm_transport(base_url)` dials the origin once per pool-idle window through the pooled client, carrying no credentials and not following through on body size (drains at most 64 KiB), tracked in a process-global `WARM_STATE` map with `InFlight`/`Warmed` states and an RAII `OriginClaim` that releases the origin on every non-`Warmed` outcome. The shell spawns it detached at session create/resume whenever the finally-resolved model base URL differs from the provisional one.
- invariants:
  1. The shared client builders must stay config-free; anything session-specific must be applied per request in `post()`.
  2. A prewarm dial must carry no credentials (it is a bare `GET` on the origin).
  3. Build failures are never cached: on `Err` the `OnceLock` stays empty so the next call retries; a racing loser's client is dropped.
  4. Only `Warmed` commits the claim; `Truncated`, `Failed` and `TimedOut` must release it so a later dial can retry.
- failurePolicy: **fail-soft**. Prewarm never returns an error — every failure mode is a `PrewarmOutcome` enum value recorded on a `session.sampler_transport_prewarm` span (`no_origin`, `client_unavailable`, `already_claimed`, `tracker_full`, `truncated`, `failed`, `timed_out`, `sharing_disabled`, `warmed`). A disabled or failed shared client falls back to building a fresh client per call.
- constants:
  - kill switch `GROK_SAMPLER_SHARED_CLIENT=0|false` (latched once per process) (`crates/codegen/xai-grok-sampler/src/shared_http.rs:17-32`)
  - `GROK_POOL_IDLE_TIMEOUT_SECS` default `90`; `GROK_POOL_MAX_IDLE` default `2`; `GROK_CONNECT_TIMEOUT_SECS` default `10` (`crates/codegen/xai-grok-sampler/src/shared_http.rs:78-81,94-101,118-121`)
  - `PREWARM_TIMEOUT = 15s`, `DRAIN_CAP_BYTES = 64 * 1024`, `MAX_TRACKED_ORIGINS = 32` (`crates/codegen/xai-grok-sampler/src/prewarm.rs:12,14,16`)
  - h2 keepalive `15s` interval / `5s` timeout (`crates/codegen/xai-grok-sampler/src/shared_http.rs:109-111`)
- evidence:
  - `crates/codegen/xai-grok-sampler/src/shared_http.rs:53-55` and `:93-113` — `client()` / `build_http_client()` with the pooling and keepalive knobs.
  - `crates/codegen/xai-grok-sampler/src/prewarm.rs:63-128` — `prewarm_transport` outcome mapping; claim release at `:144-150`.

### dual-deadline-stream-watchdog

- what: Every Layer-2 stream transform enforces two independent liveness deadlines per attempt. The outer one is `tokio::time::timeout(idle_timeout, stream.next())`, which catches a transport that stops yielding frames at all; the inner one is a `last_content_chunk_at: Instant` that is only reset when a frame carried *content*, checked after every frame as `last_content_chunk_at.elapsed() > idle_timeout`. The second timer exists because some inference engines emit keepalive or empty-delta SSE events that satisfy the outer timer while making no progress. Both deadlines produce `SamplingError::IdleTimeout { elapsed_secs }` and a terminal `SamplingEvent::Failed`. The identical structure is implemented independently in all three backend transforms.
- invariants:
  1. Only content resets the content deadline — a keepalive/usage/progress frame must not.
  2. `IdleTimeout` must stay non-retryable: the model or network path is stuck, so replaying the same request would stall again. `classify_error` therefore maps it to `Fatal`.
  3. The sampler's compiled default is a floor for callers that pass nothing; the shipping shell overrides it per model/remote settings.
- failurePolicy: **fail-closed**. The attempt terminates with `Failed{IdleTimeout}` and is not retried; the elapsed seconds are carried into the user-facing message ("Model stopped responding after {elapsed_secs}s…").
- constants:
  - `DEFAULT_IDLE_TIMEOUT_SECS = 300` in the sampler, used only when the caller supplies none (`crates/codegen/xai-grok-sampler/src/actor/request_task.rs:41,88-92`)
  - shell-side `resolve_inference_idle_timeout_secs` = per-model, else remote, else `600`, clamped `.max(10)` (`crates/codegen/xai-grok-shell/src/agent/mvp_agent/mod.rs:1257-1268`)
  - per-model config key `inference_idle_timeout_secs` (`crates/codegen/xai-grok-shell/src/agent/config.rs:1077`)
- evidence:
  - `crates/codegen/xai-grok-sampler/src/stream/chat_completions.rs:82-95` — outer timeout; `:218-229` — content-progress deadline with the explanatory comment at `:75-78`.
  - `crates/codegen/xai-grok-sampler/src/stream/responses.rs:263-276` and `:580-591` — same two deadlines on the Responses backend.
  - `crates/codegen/xai-grok-sampler/src/stream/messages.rs:122-127` and `:461-472` — same on the Anthropic Messages backend.
  - `crates/codegen/xai-grok-sampling-types/src/error.rs:183-186` — `IdleTimeout` variant documented as NOT retryable.
- notes: Not gated, wired: the shell sets `sampler_config_initial.idle_timeout_secs = Some(inference_idle_timeout_secs)` at session spawn (`crates/codegen/xai-grok-shell/src/session/acp_session_impl/spawn.rs:1281`).

**Explicit answer: does `xai-grok-auth` have an external/enterprise auth gate, token refresh, or API-key precedence?**

- **External auth gate: NO, not in `xai-grok-auth`.** `crates/codegen/xai-grok-auth/src/` is 5 files / ~440 lines with no reference to an external provider, enterprise mode, or admin policy. External auth lives in the shell: `crates/codegen/xai-grok-shell/src/auth/external_auth.rs` (`EXTERNAL_AUTH_REFRESH_TIMEOUT: Duration = Duration::from_secs(7)` at `:44`, `run_external_refresh` at `:49-89`, `refresh_with_command` at `:92-96`) and `crates/codegen/xai-grok-shell/src/auth/flow.rs` (`run_external_auth_provider` at `:176`). The UI gate is a pager boolean `has_external_auth_provider` (`crates/codegen/xai-grok-pager/src/app/app_view.rs:692`) that hides `/usage` and billing.
- **Token refresh: the trait lives in `xai-grok-auth`; the implementation does not.** `AuthCredentialProvider::refresh_after_unauthorized()` is declared at `crates/codegen/xai-grok-auth/src/auth_provider.rs:43` and called by the middleware at `crates/codegen/xai-grok-auth/src/retry_middleware.rs:81`; `StaticAuthCredentialProvider` hard-returns `false` (`crates/codegen/xai-grok-auth/src/auth_provider.rs:100-102`). The real implementation is the shell's `ShellAuthCredentialProvider::refresh_after_unauthorized` → `auth_manager.try_recover_unauthorized(RecoverySource::Background)` (`crates/codegen/xai-grok-shell/src/auth/credential_provider.rs:106-113`), which returns `false` unconditionally for deployment-key auth (`:107-109`).
- **API-key precedence: not in `xai-grok-auth`.** It is split across two levels: the sampler makes a live `bearer_resolver` authoritative over the construction-time `api_key` (`crates/codegen/xai-grok-sampler/src/client.rs:674-692`), and the shell orders `deployment_key` (bare `Bearer`) above `user_token` (Bearer plus `X-XAI-Token-Auth`) inside `GrokAuthCredentials::apply` (`crates/codegen/xai-grok-shell/src/util/grok_auth_credentials.rs:97-112`). `AuthCredentialProvider::needs_token_auth_header()` (`crates/codegen/xai-grok-auth/src/auth_provider.rs:48-50`) is the flag that distinguishes the two schemes, and the shell overrides it to `deployment_key.is_none()` (`crates/codegen/xai-grok-shell/src/auth/credential_provider.rs:114-116`).
- **`needs_token_auth_header` / `has_usable_credential` are genuinely consumed**, not inert: `crates/codegen/xai-grok-telemetry/src/otel_layer/mod.rs:246-247` gates OTLP export on `credentials.has_usable_credential()` and `:257-260` attaches the `X-XAI-Token-Auth` header only when `needs_token_auth_header()`; `crates/codegen/xai-file-utils/src/queue.rs:2158-2160` uses `resolver.has_usable_credential()` to decide whether a parked upload wakes for another wire attempt (that crate's own `has_usable_credential` at `:86-88` is a default-`true` trait method).
