本文件是**機制層**的七源對比。姊妹文件 `docs/audit/2026-09-11-sevenway-command-matrix.md`（D2）答的是**命令層**——哪個 harness 有 `/compact`、怎麼實作、我們該怎麼辦。本文件答的是**後端設計本身**：agent 迴圈長什麼形狀、子代理協定怎麼保證耐久、沙箱到底圍堵了什麼、壓縮是改寫還是投影。**兩者互補，不重複。**

## 為什麼列是「機制」而不是「模組」

七源的模組數從 **36 到 267**，而且**不可比**：

| 源 | 模組數 | 說明 |
|---|---|---|
| dsh | **267** | `packages/<area>/<package>`，大量是 Cordis 管線 |
| codex | **102** | 含 `ansi-escape`、`async-utils`、`build-info` 這類基建 |
| opencode-fork | 99 | 引擎在 `packages/core/src/*` |
| opencode | 97 | 同上 |

模組對模組的表會**同時太吵又誤導**：`ansi-escape` 有沒有，跟一個 harness 能不能做事無關。所以**列是能力**——「四級輸入准入」「耐久任務協定與 recovery-required 分類」「啟動即套用的 OS 沙箱，寧可拒絕啟動也不裸跑」。

模組清單仍然存在，但它的角色是**讓「什麼都盤到了」變成可檢查的主張**：Phase 0 機械列出每個源的每一個模組，每個源的盤點代理必須**逐一交代**每個模組貢獻哪些機制、或為什麼不貢獻能力。組裝時這是一道**硬閘**——有任何模組沒被交代就拒絕產出文件並點名。

## 方法與驗證

1. **Phase 0（腳本，不經 LLM）**：`extract-mechanisms.mjs` 列出七源的每一個模組並依關鍵字歸域，產出 `2026-09-11-d3-modules.json`。分類器的提示**不是權威**——它被實測證明會在整個域裡把某個源判成空的（見下），所以各源代理必須更正它，更正內容列於附錄 B。
2. **Phase 1（六個代理，涵蓋七源）**：每源橫跨 12 域產出機制清單（機制／不變量／失敗策略／常數／`file:line`），**並逐一交代每個模組**。硬規則：**無 `file:line` 即標未驗證**。
3. **跨源對帳**：七個獨立代理對同一能力的命名必然分歧（「append-only 影子投影」vs「surface-replace 壓縮」）。硬用名字聯集會產生數百個單源列，讓矩陣**宣稱七個 harness 幾乎沒有共通點——那是方法造成的假象，不是事實**。因此列的來源是**顯式 crosswalk**，任何未被認領的機制**自成一路並進未對帳附錄**：寧可列出「這兩者可能同一個東西但我沒把握」，也不要靜默合併。
4. **對抗式驗證**：無利益關係的獨立代理抽樣重讀原文，判定引註是否真的支撐主張。

### Phase 0 分類器的四個缺陷（都已修，全部會讓某個源在整個域裡看起來是空的）

記錄於此，因為它們是「為什麼機器分類不足以做這件事、必須有人讀原始碼」的直接證據：

| 缺陷 | 後果 |
|---|---|
| 把 `codegen` 當成基建關鍵字 | grok 的 crate 都在 `crates/codegen/` 下，**82 個模組有 81 個被判成基建** |
| 用了裸 `core/` 關鍵字 | opencode 整個引擎（`packages/core/src` 的 26 個子模組）**全被歸進 agent loop** |
| `session` 只寫了複合詞（`core-session`、`session-persistence`…）**沒有裸 `session`** | 名叫 `core/session` 的模組**什麼都對不上**，整個 session 域在該源消失 |
| 子字串比對不吃複數 | `credentials` 對不上關鍵字 `credential`，**憑據處理從三個源消失** |

修正後：改為**詞段比對＋複數/動名詞容忍**，並把 test helper／util／schema 這類**基建另立一桶**，使「unmapped」代表「真的有能力模組沒歸位」。unmapped 從 **156 降至 32**（多為 `core`、`protocol` 這類容器模組），每個源橫跨 12–13 個域。

**證明強度聲明**：本盤點的所有機制主張來自**閱讀原始碼**，未執行任何程式碼。這是靜態審計，不是行為測試。
