feat(audit): D3 seven-way backend mechanism matrix

docs/audit/2026-09-11-sevenway-backend-mechanisms.md -- 360 KB, 424 rows across
the 12 domains, every row carrying a disposition with its rationale, plus four
appendices (module coverage, 149 classifier corrections, unreconciled, fork
deltas).

Rows are CAPABILITIES, not modules and not commands. The seven sources ship 36 to
267 modules and the counts are not comparable -- codex's 102 crates include
ansi-escape and async-utils, grok's 82 include its whole renderer -- so a
module-to-module table would be simultaneously noisy and misleading. The module
inventory exists to make "everything that exists was surveyed" checkable:
752/752 modules across all seven sources are accounted for, enforced by a gate
that refuses to write the document otherwise.

Coverage is exact: 806 mechanisms from Phase 1, placed 806 times across the 424
rows, zero duplicates and zero unplaced.

Three defects in my own briefing surfaced during the crosswalk and are recorded
in the document rather than hidden, because each produced a systematic false
negative that a reader would otherwise mistake for a finding:

1. A mechanism may occupy only one row, so a composite mechanism's other aspects
   vanish from the matrix. IH's three-stage tool dispatch spans registry +
   pipeline + dispatch but sits in the registry row, leaving the pipeline and
   parallel rows with no IH member; codex's unified_pty_exec is both its default
   shell tool and a PTY, so the shell row has no codex member. Four domain agents
   raised this independently.
2. A row may cite only mechanisms from its own domain, so an I-harness capability
   filed under another domain cannot be a member and the row reads as a gap. The
   retrieval agent listed four such mechanisms, the extension agent eight; both
   marked those rows as design differences rather than falsely claiming absence.
3. An empty inventory array is not an absence. grok's model, service and ops
   arrays are empty because its Phase 1 pass emitted no citable mechanisms there,
   while grok's own moduleCoverage names xai-grok-models, xai-grok-http and
   xai-grok-telemetry as belonging to those domains. Three agents raised it. The
   matrix renders those cells as a question mark ("not inventoried this pass")
   rather than the cross that would publish a false negative.

Assembly defects fixed along the way: the assembler read every .json in the data
directory instead of only crosswalk files; it dropped each row's disposition and
rationale when building rows, leaving the disposition column empty; and a row-id
collision between the loop and subagent domains (both invented
background-job-registry for different rows) was a hard error, now qualified by
domain since it is a naming clash rather than a duplicate mechanism.

All section 8 thresholds pass, including the D3 additions.
