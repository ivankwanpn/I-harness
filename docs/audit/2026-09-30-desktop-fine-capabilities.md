# Desktop fine capability audit — 2026-09-30

## Scope and evidence

This audit inspects the working tree in `D:/frontend-test`, based on commit `03a88b0ffb022759dc2f0a1bc9b4c0ba757dafbb`. It records the producer, transport, actual human UI, persistence behavior, and remaining limits for each requested capability. It excludes the user's existing `packages/desktop/electron.vite.config.ts` change.

The requested workflow features are integrated through host, gateway, IPC and renderer. Final verification passed 3,792 tests (9 skipped, 70/70 projects), with typecheck, five E2E files and reachability passing. Actual packaged acceptance covered both configured DeepSeek protocols, selected CMD, Goal completion, team member/task production and restart recovery. See [completion acceptance](2026-09-30-desktop-workflow-completion-qa.md) for logs and boundaries.

Evidence terms:

- **Wired in source:** a producer and transport lead to a mounted renderer control/display. This is not a claim that a packaged Desktop was exercised.
- **Focused tests passed:** the named tests were run during this work, with their stated boundary. Mock bridge/component tests do not establish a real Electron or provider round trip.
- **Test coverage present:** the named repository tests describe the behavior; this audit did not rerun them.
- **Integration pending:** an implementation or test specification exists, but the complete host → IPC → renderer chain was not yet established in the inspected source.
- **Missing UI / engine limit:** an exact absent control or domain behavior. Such a limit is not automatically a new implementation requirement.

The common Desktop chain is [shared request types](../../packages/desktop/src/shared/bridge.ts) → [main IPC validation](../../packages/desktop/src/main/ipc.ts) → [workspace SDK runtime](../../packages/desktop/src/main/sdk-runtime.ts) → [gateway router and advertised capabilities](../../packages/desktop-gateway/src/router.ts) → [gateway host](../../packages/desktop-gateway/src/host.ts). Settings and work-pane surfaces are capability gated. Backend package presence alone does not make a human control available.

## Gaps requiring a decision versus explicitly deferred work

### Completed integration and remaining optional controls

1. Workflow and Agent Shell host → IPC → UI integration is complete and covered by the final gate and actual packaged acceptance.
2. Streamed reasoning and reviewer context reuse were exercised on both configured DeepSeek protocols. One main turn produced 1 progress/1 canonical reasoning record; the Responses turn produced 10 progress/2 canonical reasoning records. Transient progress was absent from the saved log.
3. If the requested human capability includes editing Todo, add a real mutation contract and editor. Existing Todo status/count/paging are complete read-only displays.
4. If the requested input behavior includes enqueueing multiple prompts from the same window while its first is running or steering the next step, add explicit behavior and regressions. The current queue display/cancel chain alone does not supply it.

Items 3–4 are **missing controls**, not authorization to invent them during a read-only audit. They should be included in the parent task only when they match the user's requested behavior.

### Explicitly deferred / intentional limits

- Historical built-in child shell allowlist compatibility migration is excluded for the user's current testing dialogues. Preserve this limitation in feature notes; do not add migration work solely to support old test sessions.
- Reminders intentionally run at the next Agent step. An idle-session wake worker is a separate capability; no idle wake was requested or verified by this audit.
- Desktop autonomous Goal continuation is implemented without a fixed round allowance. The domain's optional round-usage field remains unpopulated; the UI does not invent a counter or budget.
- Unsent image drafts, live PTYs/process handles, in-flight prompts, pending interaction promises and isolated reviewer warm context do not become restart-surviving workers merely because session logs or inspection records persist.
- Review remains inspection plus explicit snapshot-based rewind. No full source editor, Git staging/commit UI, permanent chat delete, exact-hit history jump, or human prefix-approval manager was found; these are separate optional product capabilities.
