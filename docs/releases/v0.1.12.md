# I-harness v0.1.12

本版整合外部審計修正，並加入事件驅動的工具等待、引導期間的背景延續，以及子代理面板即時更新。Windows x64。

## 等待中也能引導主代理

- 在支援的工具等候期間送出「引導」，主代理可以先讀取新提示，原工作保留同一個工作／任務／cell ID 繼續執行；不會為了恢復而重跑原工作。
- 支援直接 `wait_agent`、`get_task_output(wait:true)`、各類 `job_output(wait:true)`、前景子代理的結果等候、`workflow_run(wait:true)`，以及前景 bash／pwsh／Agent Shell。
- Shell 交回既有程序的背景工作 ID，沿用原本的程序生命週期與沙箱限制。停止、關閉與清理仍由原來的工作擁有者處理。
- `code_exec`／`code_wait` 可以先交回同一個 cell ID；cell 內部的 `await` 繼續等真正的工具結果。主代理結束目前回合後，仍可在後續回合讀取尚在執行的原 cell。
- Job、Task 與子代理狀態改變會直接通知等待者，取代相關的 10／20 毫秒重複檢查。逾時與引導有不同的回傳標記，不把仍在執行的工作說成已完成。

這是有明確工作擁有者與可續讀 ID 的等待機制；不是任意第三方工具的通用中斷或重播。已開始的其他直接工具，以及必要的輸出保存，仍可能影響下一個模型步驟的時機。

## 子代理狀態與歷史推送

- 即使主代理沒有新訊息，子代理的狀態與已產生的工具／對話記錄也會通知面板刷新。
- 經過既有會話可見性及父子關係檢查後，讀取實際執行中的子代理歷史，無需等整個子代理回合結束才看到已產生的記錄。
- 新增、恢復、替換與關閉子代理都有對應的監聽生命週期；同一父會話的密集變更會合併通知，閒置時不增加輪詢。
- 本次提供狀態與持久化事件內容的即時更新，不宣稱逐字串流所有子代理文字。

「通知等待者」與「啟動閒置主代理的新回合」是兩層行為。背景子代理保留既有的持久化完成通知與父會話喚醒；一般背景 Shell／Workflow 完成後會更新可觀察的狀態，但不會自行建立新的模型回合。前景子代理因引導交回 ID 後，仍沿用工具結果交付方式，後續可用原 task ID 讀取。

## 外部審計修正

- 補上 `model/retry` 的持久化事件註冊，避免含重試記錄的會話、子代理或歷史在重新載入時被拒絕。
- 問題卡片有建議選項時仍可自行輸入；「保留問題，稍後回答」保留卡片並解除代理等待。延後回答不會被當成使用者選了某個答案，儲存失敗也不會丟失原來的等待者。
- 設定熱更新接上檔案事件監看；明確指定的設定檔不會被預設忽略規則漏掉，監看恢復後會核對停機期間的變更，短命令也能正常退出。
- 已完成子代理保留當時的模型記錄，名稱重用時按實際子會話辨識；缺少資料時明確顯示未記錄。
- Hook 核准綁定實際執行的命令；Git Bash 測試按實際受支援的 shim 辨識條件執行；ZIP 建置失敗會正確報錯。

IH 仍是混合式系統：上述等待與子代理更新改用事件，排程、部分設定同步、其他介面查詢、倒數與重試期限仍各自保留適合的定時機制。
