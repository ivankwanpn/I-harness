# I-harness v0.1.13-rc2（測試建置）

這是 `experiment/audit-fixes-v0.1.13` 分支的**未簽署、未合併**測試建置（Windows x64），用來實際安裝與驗證新的會話儲存後端（Session Commit Log，SCL）。

## 這個 rc 有什麼

### Session Commit Log（SCL）

- 新的 append-only 會話儲存：`<sessionDir>/<id>/session.v15.jsonl`，單一 commit 是持久點，sha256 `prev` 鏈；
- 已驗證：turn、fork（含 **nested selected fork**）、rewind（多種模式）、archive／delete／restore／batch、專案綁定／移動、compaction、todo、schedule、surface、標題／管理、search／lineage／subtree、context picker、CLI、重啟耐久、selected-results 繼承（含 read-through）；
- legacy 會話可讀，第一次寫入時才建立 v15 generation，legacy 位元組不改寫。

### 如何啟用（四選一，優先序由高到低）

1. host 選項（內嵌程式）；
2. CLI：`i-harness run|sdk|acp|sessions ... --session-store commit-log`；
3. settings 文件：`{ "sessionStore": "commit-log" }`（路徑預設 `%USERPROFILE%\.i-harness\settings.json`，或 `IH_CONFIG_DIR` 指定）；
4. 環境變數：`IH_SESSION_STORE=commit-log`。

沒有指定時仍是 legacy JSONL（預設後端未切換）。

### 如何確認目前用哪個

- 桌面：**設定 → 工具與環境診斷 → 工作階段儲存**，顯示 `Commit log` 或 `JSONL`；
- CLI：`i-harness sessions list --session-dir <dir> --json`。

## 測試時請留意

- **切回 legacy 時，commit log 寫的會話不會出現在列表**（legacy 只掃 `<id>.jsonl`）。資料仍在磁碟，把 store 切回 commit log 就會再看到；這是目前刻意的非對稱，不是資料遺失。
- 切到 commit log 後，既有 legacy 會話仍會列出並可讀，第一次寫入時遷移。
- 目前沒有 legacy 的 held-observation lineage／revocation 見證；來源被刪除時，inherited page 讀取不可用。
- 這是**未簽署**測試建置，Windows 可能顯示 SmartScreen 警告。
- 建置不含真實模型憑證；模型服務仍由你的設定提供。

## 回報問題

請附上：版本（`0.1.13-rc2`）、使用的 store（診斷頁或 `IH_SESSION_STORE`）、操作步驟、相關 session id，以及 `%APPDATA%\I-harness\logs`（或你設定的日誌位置）的錯誤片段。
