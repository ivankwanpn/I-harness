# I-harness Desktop 0.1.7

This local build adds dynamic plugin resources to the composer slash menu and
replaces its inline list with a grouped, searchable overlay.

- Type `/` to discover built-in operations, effective commands and skills.
  Enabled installed plugin resources appear automatically in the current
  workspace. The picker refreshes while open; disabling or uninstalling a plugin
  removes its items, and enabling or reinstalling it restores the items without
  a restart or a new conversation. Installation retains the existing explicit
  enable step and hook content-grant controls.
- Search names, descriptions or plugin IDs. Each row shows its resource kind,
  description and origin. Command argument hints remain available. Search runs
  before the bounded result limit; the menu asks for a narrower query when more
  results are available.
- Selecting a skill inserts `$skill-name ` into the draft; selecting a command
  inserts `/command-name `. Built-in workflow actions retain their existing
  behavior. Selection keeps editor focus and never sends a prompt automatically.
- The overlay stays above the input when space permits and keeps its own scroll
  area. Arrow keys, Home/End, Enter/Tab and Escape support keyboard use. Current
  selection survives a live catalogue update by identity. Hidden composers close
  the overlay, and unavailable registries clear stale plugin suggestions.

The suggestion API uses the same effective resource catalogue as the Resources
page and the existing `RuntimeInputs`. Workspace/plugin/global precedence,
disabled resources and source diagnostics are preserved. Only suggestion
metadata crosses this API; source bodies and authoring paths are excluded.
The legacy commands API, plugin input formats and hook authorization retain
their existing contracts. The reference comparison is recorded in
[`SLASH_SOURCES.md`](../../packages/desktop/src/renderer/session/SLASH_SOURCES.md).

The composer update stays on version 0.1.7. A single theme-aware input card joins
the project band, growing text area and responsive toolbar. Clicking the text
area retains the same surface without an added focus rectangle or native resize
handle. Text grows to a viewport-aware limit, then scrolls internally; deleting
text shrinks it again. Native drafts, attachments, IME input and send/stop/queue
actions retain their existing behavior.

The context capacity button shows an icon-only circular gauge of estimated usage.
Hovering opens details without taking editor focus; leaving the trigger and
details closes them after a short crossing delay. Clicking or keyboard activation
still opens the details with focus, and Escape closes them. The usage percentage
is kept in accessible text, the tooltip and details. Readings refresh at durable conversation boundaries
and model/operation changes, with burst coalescing and bounded background reads.
Unknown or failed readings retain unavailable accessibility/details; actual zero
and tiny positive usage remain distinguishable in the reading. The existing
token totals, role breakdown, estimate disclaimer and retry stay in the popup.
