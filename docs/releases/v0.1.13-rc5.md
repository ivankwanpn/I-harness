# I-harness v0.1.13-rc5（測試建置）

這是 `experiment/audit-fixes-v0.1.13` 分支的未簽署、未合併測試建置（Windows x64）。相對 rc4 的差異是**修復 legacy store 的 fork 無法續傳**。

## rc5 修正

rc4（預設 legacy JSONL store）從 UI fork 出來的會話可以建立、seed 也含來源歷史，但送任何 prompt 都會失敗：

```
RpcError: Original execution attachment requires its original entry construction
```

原因是 v1 fork 的 bootstrap 已經建立 child 的 managed document，而 legacy coordinator 在 entry 已有 document 時拒絕 attach execution（SCL 的 execution 生命週期不同，因此 SCL fork 正常）。

rc5 在 fork ready target 被觀察後**釋放 child 的 bootstrap document**（僅非 SCL store），第一次 prompt 即可 attach execution。

驗證：`host-legacy-fork-continue` 綠（fork → prompt → rewind）；實機 rc4＋修正後 fork 一個 1 回合會話並立即送 prompt，回覆 `ok`。

已知獨立缺口：legacy store 刪除 forked child 仍會回 `Original session parent unavailable`。

## 其他內容（與 rc4 相同）

- 首個 prompt 不被誤 reload 中斷；
- 首次 write 直接成功（instruction preflight 不再誤報 unseen-rules）；
- SCL 與 store 選擇、legacy/commit-log 可見性、artifacts 清理等；
- 未簽署；Windows 可能顯示 SmartScreen 警告；**不合併**。
