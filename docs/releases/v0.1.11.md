# I-harness v0.1.11

本版改善模型長時間等待、主代理執行狀態收尾、Codex 訂閱請求連續性與子代理角色選擇。Windows x64。

## 等待與執行狀態

- 主代理會在回合、停止 hooks、記錄寫入及後續工作完成後，通知介面真正的執行狀態。子代理回覆結束不再被當成主代理已完成；排隊工作也會保留正確狀態。
- 模型連線與串流進度有獨立等待上限，預設各 **300 秒**。可在 **設定 → 一般** 修改；0 關閉該上限，其他值為 30–3600 秒。儲存後從下一次模型請求生效。
- 文字、推理內容與工具參數進度會重設進度期限；單純心跳不會。長時間沒有進度會顯示獨立等待提示，停止按鍵仍可取消。
- 等待逾時使用現有自動重試次數；預設最多五次。OpenAI 模型滿載仍至少等待十秒。已知驗證、額度或無效請求錯誤，即使回應內容卡住，也不會誤判成可重試逾時。
- 診斷 Log 記錄有限的連線、安靜等待及結束資訊；不記錄每個文字片段或原始提示詞。

## 請求連續性與角色選擇

- 官方 Codex 訂閱連線補上會話、執行緒與單回合路由狀態。狀態依帳戶、子代理及回合隔離，不持久化。API key 的公共或自訂 Responses 連線保留原有行為；其他協議不會收到私有 Codex 標頭。
- Todo 內容未改變時，不再只因內部修訂次數增加而改動模型前綴；實際待辦修改、清空與恢復仍正常生效。
- `spawn_agent` 向模型提供可用角色及用途，提示依工作明確選擇角色；Code Mode 也能取得角色資訊。既有省略角色的呼叫仍使用 `general`。此改動不強制平均分配角色，也不變更使用者設定的模型。
- 此次調查沒有證實快取 Token 計算錯誤，亦沒有把歷史子代理用量改記到其他模型。快取改動驗證的是請求連續性與協議隔離，實際命中率仍須在使用中觀察。
