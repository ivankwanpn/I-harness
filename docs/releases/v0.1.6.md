## Plugin formats and lifecycle

IH retains the four marketplace entry forms and the six object source
discriminators plus string shorthands. Skills, Commands, MCP, Agents and hooks
feed the existing `RuntimeInputs`; supported hook documents normalize to
`HookHandlerSpec`. See [the compatibility matrix](../PLUGIN-COMPATIBILITY.md)
for the complete input and execution boundaries.

Nine matching synchronous Claude command hook events use the shared IH
authorization and agent lifecycle. Stop/SubagentStop feedback can continue the
existing model loop, with its normal budgets and cancellation. Hook processes
receive an owned, bounded temporary transcript projection; native history is
preserved. Actual child lineage and completed tool output survive the relevant
stop and cancellation paths.

Representative official Hookify and Ralph Loop scripts run unchanged in
isolated tests, together with explanatory-output-style and feature-dev role
fixtures. Python, native Bash, jq or Perl remain prerequisites when a plugin
needs them. Unsupported handler forms, async behavior and input/permission/
output mutations receive explicit diagnostics. This is documented coverage of
the supported contracts and representative plugins, not a claim that every
marketplace plugin has been executed.

## Windows PTY

For admitted installed x86-64 MSYS executables, a native MSYS PTY carries input
as raw bytes and keeps the controlling terminal, foreground signals, window
size and owned process tree. The audited Git Bash launcher is resolved before
the immutable execution snapshot, preserving its verified arguments and
environment behavior. The selected runtime, executable and configuration are
pinned before commit. The paired adapter, helper, protocol, source identity and
license/source notices must all pass the packaging gate.

The installed MSYS runtime DLL and build SDK are not distributed with the app.
Unknown/custom launchers retain their original execution path. The audited
launcher normalization explicitly rejects unsupported control switches and
ambiguous ANSI conversion instead of guessing. The admitted DLL import path
must be ASCII and shorter than 260 bytes. Restricted PSEC PTY remains
unsupported and fails before workload launch; the repair does not change a
requested sandbox mode. Native execution assurance remains experimental and
its qualification record is limited to the observed Windows host.

No live or paid model inference is used by these repair checks. Existing image
validation, sampled video frames and separately configured audio analysis
remain as documented in [0.1.5](v0.1.5.md).

## Verification

The final `pnpm verify:all` returned exit zero with 78/78 projects reporting,
6,012 passing tests, 21 existing environment/layout skips and zero failures.
Typecheck, five e2e files with 12 tests, and reachability all passed. Independent
native controls passed 16/16 on the frozen helper. Actual Windows qualification
records 39 passed, zero failed and four known PSEC unsupported cases.

The actual packaged executable passes the original Git/bin Bash call through
eight mixed resizes, correct dimensions, Unicode and owned resource cleanup,
together with image decoding/refusal and timed video frames/decoded PCM. Audio
is validated through a synthetic local callback; live provider analysis is not
claimed by that check. Native helper, adapter, protocol, qualification and
license/source notices all retain their checked identities.

The local Windows installer and portable ZIP are in
`packages/desktop/release-0-1-6-env-repairs`. The installer contains 8,406 payload
files; every portable ZIP file matches that tested payload byte for byte.
`validation.json` records their exact digests and scoped verification results.
This build has not been published as a GitHub release.
