# I-harness v0.1.9

本版接續 **v0.1.8**，修正工具呼叫串流解析，以及子代理重試後的錯誤顯示。Windows x64。

## 修正

- **Responses／Codex 訂閱**：使用工具參數完成事件內的完整 `arguments`，避免只解析尚未完整的累積片段。相容未提供完整欄位的端點；完整參數無效時仍會拒絕執行，不使用舊片段猜測內容。
- **Chat Completions／OpenAI 相容協議**：保留已完成呼叫的參數暫存，避免後續空白或空字串片段產生假的第二個呼叫或解析錯誤；同一個呼叫只會送出一次，完整資料仍會驗證。
- **子代理重試狀態**：新一輪開始時清除上一輪錯誤。重試成功後，列表與詳情不再從舊的任務紀錄補回過期紅字；本輪真正的失敗仍然顯示。

這些修正不限定於 gpt-6.1-sol。各協議使用獨立的參數解析器，共用事件與執行層；本次也檢查 Anthropic、Gemini、Bedrock 及共同 LLM 層的既有測試，沒有確認相同的兩項解析缺陷。

## 驗證範圍

Responses、Chat Completions、Anthropic、Gemini、Bedrock、LLM seam、core-agent、subagent 與 desktop-gateway 使用本機模擬資料驗證；另執行 Desktop 子代理介面測試、型別檢查與正式建置。發行 manifest 記錄最終結果及打包核對。

上述九個套件共 **1,192 項測試通過**；Desktop 子代理介面另有 **13 項通過**。這是本輪針對協議與子代理的驗證範圍，不沿用前一版的 Desktop 全套測試數字。

原始使用者會話未保留失敗時的原始串流參數，因此不能將每一次歷史錯誤都歸因於本次修正的解析缺口。真正無效的參數仍會回報錯誤。驗證沒有使用真實模型請求或修改使用者的會話資料。

**English:** v0.1.9 fixes final tool argument handling for Responses and Codex subscriptions, trailing argument deltas in Chat Completions, and stale subagent errors after successful retries. Invalid final arguments remain rejected. The other supported protocol adapters and shared execution layer were checked with local fixtures; this release does not claim a live-model reproduction of every historical failure.
