# I-harness Desktop 0.1.5

- Home and project navigation now use the same project-grouped conversation list.
- Stop remains available during an active conversation even when a follow-up draft or an in-flight submission occupies Send. Returning to a running session restores its running state.
- Archive accepts settled reusable child agents and waits for a live rewind finalizer. Actual pending work and unresolved recovery recordings remain protected, with readable explanations.
- Malformed images are rejected before tool output is saved. Invalid images already in history become explicit unavailable-image placeholders in outgoing model requests; original history is preserved.
- `read_video` reads sampled visual frames and analyzes speech and other sounds. Native file attachment supports MP4/M4V/MOV/WebM references, including external files.

## Video setup and coverage

In Settings → Models and providers, choose an OpenAI-compatible provider and set **Video audio model** to a model supporting Chat audio input. This is a separate selection from the main reasoning model. Audio is sent to the selected provider only when the tool reads it. Enable image input on the main model to see extracted frames.

The shared reader accepts up to 256 MiB per file, reads 30 seconds and six frames by default, and permits up to 60 seconds and eight frames per call. Longer videos can be read in successive intervals with `startSeconds`. Frames are sparse samples and timestamps are approximate. Audio analysis reports speech and other sounds; an absent track and failed/unconfigured analysis are distinct states. Incomplete audio analysis returns a partial result.

Attachments retain the original local path rather than copying video bytes. Keep the original file available until reading is complete. No live provider inference was used for automated verification.
