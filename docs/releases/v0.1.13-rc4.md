# I-harness v0.1.13-rc4（測試建置）

這是 `experiment/audit-fixes-v0.1.13` 分支的未簽署、未合併測試建置（Windows x64）。相對 rc3 的差異是**修復新 session 第一次 write 失敗**。

## rc4 修正

rc3 在新 session 第一次寫入新檔案時，instruction preflight 會以 `INSTRUCTIONS_REPLAN_REQUIRED / unseen-rules` 拒絕（`not-dispatched`）；模型要花幾步找規則檔再重試。真正被 mask 的例外是 `Target instruction evidence not issued`：admission snapshot 尚未涵蓋這個新 target。

rc4：preflight 在 `prepare(targets)` 後比較規則文字與 sources：

- 若沒有新規則（target 只新增 absent candidates），以最新 snapshot 發 proof，**第一次寫入直接成功**；
- 若規則真的變更（例如 turn 期間出現了 `AGENTS.md`），仍回 `unseen-rules` 讓模型重新規劃。

驗證：instructions 141/141；`host-write-first` 兩個案例（首次寫入成功、規則中途出現仍拒絕）；實機 rc3＋修正後新 session 寫入 `notes/first.md` 直接成功、無失敗卡。

## 其他內容（與 rc3 相同）

- 0.1.13-rc3 的首個 prompt 修復（transient read retry，不再誤 reload 中斷 turn）；
- SCL 與 store 選擇、legacy/commit-log 可見性、artifacts 清理等；
- 未簽署；Windows 可能顯示 SmartScreen 警告；**不合併**。
