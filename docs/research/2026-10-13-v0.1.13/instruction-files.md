## Finding

**I-harness already supports AGENTS.md and CLAUDE.md.** v0.1.13 should harden and expose that implementation, not introduce a second loader. The main gaps are scope boundaries, accurate read limits/cache behavior, explicit provenance and replacement/removal semantics, and child/compaction lifecycle correctness. Fully implementing Claude Code memory, rule imports, managed policy, or a general instruction framework is not required to support these two filenames.

`packages/instructions` is the current owner; assembly mounts it into `packages/runtime-context`. The original roadmap explicitly describes that arrangement (`docs/roadmap/2026-08-31-roadmap-A-core.md:44-50`).

### Lifecycle facts and static defects

1. **Cache does not avoid rereads.** `src/index.ts:28` calls the full reader before any stat check. Worse, editing an older file with the same length and keeping its mtime below another file's maximum leaves `(maxMtime,totalSize)` unchanged. The old cached contents are returned. Two size changes that cancel also evade the aggregate signature. A per-file mtime/size vector fixes those collisions; adding ctime/inode and revalidating before/after read strengthens it. Same metadata restoration remains a documented limitation of any metadata-only cache; content hashing on every read is an alternative, not a free cache.

2. **The nominal byte cap is inaccurate and does not bound I/O.** CJK/emoji can substantially exceed 24,000 UTF-8 bytes; cutting UTF-16 may split a surrogate pair. A large global/root file can consume the entire aggregate before the closest rules. `maxBytes=0` currently produces a truncation marker for nonempty input rather than disabling loading. Negative/NaN limits are unvalidated.

3. **Snapshots accumulate without a replacement statement.** `runtime-context/src/index.ts:49-59` dedupes only identical current text. Changed content is appended, while earlier snapshots remain normal model messages (`core-session/src/index.ts:689-714`). Only an entirely empty context produces `RUNTIME_CONTEXT_CLEARED` (`runtime-context:6`, `:48`). Removing instructions while skills remain produces a new skills-only snapshot without explicitly retracting the earlier instructions. This is an important contract for the runtime-event owner.

4. **Raw-log dedupe can lose effective instructions after compaction/reset/rewind.** Retained state scans the last raw plugin message (`runtime-context:27-34`) and is then an in-memory string (`:49`). Compaction can shadow ordinary user messages (`compaction/src/region.ts:127-159`), while derivation drops shadowed or rewound events (`core-session:631-645`, `:694`). An unchanged loader result will not be re-appended merely because its prior snapshot is no longer visible. This follows directly from source; it was not experimentally reproduced in this research. The existing `packages/compaction/test/instructions.test.ts` concerns caller-supplied summarizer instructions, not AGENTS.md preservation.

5. **Child instructions are not independently mounted.** `spawnChild` mounts a child scope and defaults `forkTurns` to `none` (`subagent/src/child.ts:288-296`); its agent uses the role prompt plus selected inherited system context (`:449-476`). Assembly's `inheritedSystemContext` includes project/hook/WSL/recovery only (`assembly:1143-1148`), not the instruction snapshot. `fork_turns=all` may include prior runtime snapshots; `none` does not, and a finite tail can omit the sole unchanged snapshot. Resumed child construction similarly uses its role prompt and inherited system context (`subagent/src/tools.ts:683`, `:740-760`).

6. **Child pre-step events can update the parent log.** Core-plugin emits up the scope chain (`core-plugin/src/index.ts:274-293`), and the parent's installed pre-step closure calls `service.render()` against the captured parent session without checking the payload session (`runtime-context:73-75`). Thus child steps can refresh parent runtime state but do not thereby furnish the child with its own instructions. This is a session-ownership defect, not a need to copy the parent's entire context.

7. **Instruction discovery is not a read sandbox.** Current filesystem sandbox policy explicitly leaves reads unrestricted (`sandbox-policy/src/paths.ts:27-31`). Loading an instruction is a separate promotion of file text into model guidance. Bounds/trust must be defined explicitly rather than claimed as already enforced by write approval. Current loader has lexical string dedupe only; symlink/junction aliases can duplicate or redirect sources outside an intended future boundary.

8. **Ambient home leakage affects tests and isolated profiles.** Low-level discovery tests mostly use the real home; the synthetic-home case only covers `~/CLAUDE.md` (`instructions.test.ts:32-41`). One test comments that ambient ancestors may exist but later asserts the complete content list equals just two fixture files (`:21-27`). Assembly cannot inject a fixture home. `IH_CONFIG_DIR` isolation elsewhere does not isolate instructions today.

## Recommended minimal v0.1.13 contract (proposal, not current behavior)

1. **Keep one resolver and the existing filename rule.** Preserve `AGENTS.md > CLAUDE.md` per directory and broad-to-narrow ordering; disclose when CLAUDE is shadowed. Both are plain instruction text. Do not parse execution commands from either file. Clarify that user requests and actual tool/approval policy continue to govern; file text cannot grant tool permission.

2. **Make scope explicit.** The host supplies immutable session CWD and explicit project-root boundaries. Bootstrap only loads the applicable root-to-CWD chain, not every descendant or every unrelated project folder. For an unbound CLI folder, use nearest `.git` root when present, otherwise CWD. If the selected root is narrower than a Git repository, the host-selected boundary wins. A Git worktree `.git` file counts as a marker. No traversal above that boundary. Shell CWD changes do not silently change session scope. Files from other declared project roots need their own labeled target scope.

3. **Do not silently add foreign globals.** A native global file can be `join(resolveHarnessHome(), "AGENTS.md")`, but changing existing `~/AGENTS.md`/`~/.claude/*` behavior is a migration decision. Recommended migration: resolve host-supplied explicit global source paths; preserve legacy globals for existing configurations through a documented compatibility option, and make the default/source list visible. Isolated profiles/tests must be able to supply an empty global list. Do not start reading `.codex`, `.claude/rules`, or `CLAUDE.local.md` just because the filenames are now documented.

4. **Fix the existing 24,000 limit rather than arbitrarily changing it to 32 KiB.** Define it as total rendered UTF-8 bytes, including headers and truncation diagnostics, with a separate bounded per-file read. Read in precedence order, show each selected/omitted/truncated source, and warn if local rules are excluded by earlier content. The policy may later reserve a budget for local rules, but silently dropping early global rules or reordering documents to fit changes semantics. Zero means disabled and performs no content reads. Reject or normalize invalid limits at the host boundary.

5. **Use one coherent structured snapshot.** Return source paths, scope directory/root, candidate kind, content hash, loaded byte count, state (`loaded`, `truncated`, `shadowed`, `unreadable`, `outside-scope`), and aggregate fingerprint. Render only from that same snapshot. The Desktop status and actual model input must not independently rediscover files and disagree. Do not include full file text in routine telemetry or status messages.

6. **Fix the cache with bounded work.** Discover candidates and stat identities before reading; cache per canonical source identity and per-file metadata, not maximum/sum. Detect additions/deletions and winner changes on each request boundary; invalidate on root/global-policy changes. Do not need an OS watcher for this release. Bound counts/depth/read bytes. Distinguish confirmed deletion from read failure. Prefer an explicit warning and retaining a known-good value for a transient error only while the source is still allowed; revocation/outside-scope/disabled must remove it immediately.

7. **Make symlink/trust behavior a documented instruction-source policy.** Use normalized absolute paths and segment-aware containment; check real target containment before auto-promoting instructions. Allow in-bound symlink/junction targets and dedupe aliases; skip auto-load outside the explicitly allowed project/global roots with a diagnostic. Keep lexical display/scope separate from canonical file identity. A host-wide “untrusted project” feature is not prerequisite scope: the loader can accept an explicit `enabled`/source allowlist supplied by the host without inventing a second approval UI. If a real project-trust state is later available, it must invalidate the instruction source immediately.

8. **Per-session delivery, including fresh/resumed children.** Each model session gets a fresh applicable snapshot independently of forked history. Share immutable file-read cache if useful, but do not share a mutable rendered/retained pointer or active nested-target set. Parent listeners must reject child payloads. Child scope defaults to its actual bound workspace/project roots; inherited history is contextual evidence, not authority for another project's rules. No recursive delegation behavior needs to change.

9. **Runtime-event work owns lifecycle.** Reassert the effective current instructions after compaction/reset/rewind; obsolete snapshots cannot remain operative, and removal of just the instructions section must explicitly retract it even while skills remain. Persist enough typed state to restore this correctly. Coordinate with the runtime-event redesign rather than adding instruction-specific scans across the event log in multiple packages.

10. **Include bounded per-target nested support in v0.1.13.** Bootstrap handles the root-to-CWD chain; lazy target resolution handles actual file-tool paths and explicit model lookups. Newly discovered instructions must reach a new model request before a mutation proceeds. Reading rules and then executing an already-generated write is not sufficient. See the concrete strategy below. Arbitrary shell source is not parsed to claim complete touched-path coverage.

### Required nested per-target strategy

The parent has confirmed nested per-target support belongs in v0.1.13 and that defective interfaces may be restructured. The following is the recommended design boundary, replacing a bootstrap-only release.

**One typed instruction service per session, shared immutable file cache only.** The session service owns the base chain, an ordered map of activated target scopes, the effective snapshot, and the instruction epoch actually shown at each model request. Every rendered file states its directory scope; loading `packages/a/AGENTS.md` must not turn it into a rule for sibling `packages/b`. Active scope state can include both with explicit labels. Child instances have independent scope maps and model-observed epochs, including when they inherit history.

**A bounded walk, not recursive discovery.** For a target file, normalize its absolute lexical path using the owning file tool's resolver; choose its containing authorized project root; walk only root through `dirname(target)` inclusive. Select AGENTS over CLAUDE independently at each level, dedupe shared ancestors with the base chain, and resolve canonical identities/containment before loading. For a not-yet-created target, resolve the deepest existing ancestor and retain the lexical missing suffix; never broaden the allowed root. Proposed work bounds are 32 distinct target paths per call/batch, 64 ancestor directories per target, 128 selected source files per effective snapshot, and the existing 24,000 rendered UTF-8-byte content budget. Exceeding the work bound returns an explicit narrower-scope request; it is not a successful partial scan. A mutation cannot proceed while applicable local instructions are omitted/truncated; report the source and ask the model/user to reduce the scope or edit the rules. Reads can still return data with a precise truncation diagnostic. The exact constants are proposed and should be pinned by tests/config, not hidden magic numbers.

**Targets are tool-owned metadata.** Add a small optional `Tool.instructionTargets(args)` contract returning normalized `{path, access: "read" | "write" | "command-cwd"}` descriptors. Native FS tools derive paths with their existing `resolvePath`; apply_patch parses once and supplies every affected hunk path before applying any hunk (`packages/fs/src/patch.ts:15`, `:35`, `:176`). Do not maintain a second switch on raw tool names in assembly. `read`/`list_dir` expose appropriate target directories; search tools may expose their search root but are not a promise to discover all nested instruction files in every match. Foreign/MCP tools do not automatically gain this descriptor or authority.

**The knowledge boundary is the model request.** Have core-agent stamp a host-owned `instructionEpoch`/request-context token on `ToolExec`, tied to the actual snapshot included in that model request. Model JSON cannot assert it has seen current rules. For every side-effecting native file call, compare the effective instructions for its declared targets to that token before dispatch. If new or changed applicable rules are found, admit the updated typed context and return a new *recoverable context-change/replan disposition* with no mutation. On the next model request the updated snapshot is visible; a newly generated tool call can then proceed. The disposition is not a policy approval denial and should not trigger approval UI or fail the whole conversation. Revalidate content/authority immediately before actual launch to close the normal prepare/dispatch gap; document that user-space filesystem TOCTOU is not kernel isolation.

**Preflight the whole direct tool batch.** `core-agent/src/execute-tool-calls.ts` needs a preparation pass over declared targets before any native mutation in that model batch dispatches. If one target needs new instructions, defer that batch's writes and emit clearly marked not-executed results, leaving no partially applied patch or sibling write. Reads may complete if the scheduler contract allows that safely, but do not let a read completing inside the same model-generated batch mark the model as having observed its new rule text. Never automatically retry the exact prepared mutation with a new epoch.

**Code Mode must hand control back to the model.** `code-mode/src/broker.ts:44-45` currently marks nearly every prepare failure fatal, and policy refusal is cell-terminal (`src/catalog.ts:24`, `src/register.ts:12`). Add a distinct context-replan signal through broker/runtime/register. On first new/changed scope for a mutation, stop the owning cell, cancel/drain its queued tool calls, preserve and report already-completed outputs, and return an explicit `context_changed` result to the outer model loop together with the new session context. JavaScript `try/catch` must not clear this barrier: `await tools.read(...)` or `instructions_get(...)` followed by `tools.write(...)` in the same cell does not give the model a chance to interpret new natural-language rules. Previously completed writes in a long cell cannot be rolled back; report them honestly. New independent cells only pass once a subsequent model request carries the current epoch. Children and mixed/direct mode use the same service and attribution.

**Shell's honest contract is CWD plus explicit targets.** Known shell `cwd` gets its chain loaded before dispatch. Provide a small read-only `instructions_get({paths})` tool for a model planning mutations through arbitrary shell commands or foreign tools; it resolves the same per-target service and admits those scopes, then requires a fresh model request before dependent mutation. Do not parse PowerShell/Bash source, recursively scan every directory, or claim hidden filesystem accesses are covered. The prompt must require explicit lookup of applicable target rules before shell work outside the currently described scope. If stronger coverage is later required, require declared target paths from those tools or build a separate execution policy; do not advertise it now.

**What the model receives.** The context block names each source and its `appliesTo` directory, lists narrower-scope precedence, and states that sibling scope rules apply only inside their directories. Replan tool results name the blocked operation/paths, say it did not run, and point to the newly admitted instruction context. Status metadata lists omitted/truncated/unreadable files. Changes/deletions/revoked roots produce the runtime owner's normal replacement/removal events. UI and model read the same snapshot; no reread in the renderer.

### Deliberately excluded unless the product decision explicitly adds them

- `@path` imports, recursive imports, globs, remote URLs, YAML `paths` frontmatter, `.claude/rules`, managed/org rules, auto memory, `CLAUDE.local.md`, `/memory` authoring, and automatic foreign-home migration.
- `AGENTS.override.md` is easy filename compatibility but still a behavior change. If selected, use `AGENTS.override.md > AGENTS.md > CLAUDE.md` per directory and document that it overrides only its directory candidate. Do not call it a whole-tree override. Keep it separate from support for the requested two names.
- No new global model prompt middleware; no instruction loader in `core-agent`; no provider-specific AGENTS implementation; no duplicated Desktop loader; no parsing arbitrary shell source to infer touched paths.

```ts
  root: string
  globals: readonly string[] // host-resolved, deterministic ordered allowlist
  enabled: boolean
}
interface InstructionSnapshot {
  fingerprint: string
  text: string
  sources: readonly InstructionSourceStatus[]
  bytes: number
}
interface InstructionSource {
  read(scope: InstructionScope): InstructionSnapshot
  // Required target lookup; no recursive tree walk.
  readForTarget(scope: InstructionScope, targetPath: string): InstructionSnapshot
}
```

`InstructionSourceStatus` should encode display/canonical path, owning scope, selected candidate and shadowed candidates, status, bytes/hash, and a bounded diagnostic. It should not include file text by default. Keep `createInstructionsSection` as a thin compatibility adapter around the source's `text` while the runtime owner migrates delivery. A filesystem adapter may be package-internal for deterministic unit tests; do not grow a public generic virtual filesystem without a real host need.
