## Existing push paths and missing coverage

### Workflow/background jobs and execution tree

`renderer/session/use-workflow.ts:50-64` is already event-invalidated. It listens to `desktop/workflow/changed`, `session/status`, and goal/plan/job/tool/team session events, then uses `createRefreshScheduler`. Host owns `notifyWorkflow` (`host.ts:178`), approval callback (`:305`), goal running transitions (`:369-371`), and workflow mutations (`workflow.ts:170`). Do not report this as another renderer polling loop.

The remaining event-coverage obligation is producer changes that are not durable session events: task registration/removal, background output availability, terminal lifecycle, cancellation authority and native cleanup status. `AgentProcessesPane` currently covers these by repeated reads. A job completion notification must not be delayed until the next model tool/result or human read. Reuse existing task/job observers where available; add collection observations only at their owning services. `ExecService.subscribeJob` is per known ID and currently supplies no initial snapshot; it does not by itself discover newly created jobs. `service.ts:421-455` is the registration/final-state notification boundary to extend, and streaming output needs its own notification coverage audit rather than assuming the existing subscriber fires for every chunk.

Subagent panes already use push: `desktop-gateway/src/session-subagents.ts:70-90` attaches `assembly.onSubagentsChanged`, coalesces for 50 ms, and emits scoped changed events. `renderer/session/SubagentPane.tsx:123` subscribes to bridge notifications. Keep this model; extend the unified revision contract without replacing its authority checks or child visibility rules. Execution tree is not a request to build another registry of agents.

### Tools/settings UI

There is no literal `ToolsSettings.tsx`; relevant surfaces are MCP, plugins/resources, Code Mode, agents/subagents and Code Context. MCP settings (`renderer/settings/McpSettings.tsx:21-35`) and Agent settings (`AgentSettings.tsx:41-56`) load on scope/mount/actions, not intervals; they can remain stale when another process changes settings. `CodeModeSettings.tsx:8` uses the shared helper with polling disabled. They need invalidation coverage even though deleting timers does not affect them.

MCP supervisor has producer callback `onStatus` (`mcp-client/src/supervisor.ts:43,154`) and catalogue rebuild behavior; session assembly handles live MCP tool-list changes (`session-executor/src/assembly.ts:1158-1167`). Route owned MCP status/catalogue changes into a settings/tools surface revision. Do not query all MCP servers periodically to discover a change they already report. For foreign servers that do not emit their optional list-change notification, retain explicit refresh/reconnect as the honest fallback. Changes must not replace unsaved settings drafts: update saved/effective baseline and show conflict/reload state while preserving draft ownership (`SettingsPane.tsx:92-97` intentionally retains forms).

### Git and files

No periodic state-query timers were found in review/files source. `ProjectGitPane.tsx:155-161` reads on mount/scope and navigation-changed, then explicit mutation/readback; `:163-173` reads actual Git changes. `ProjectFilesPane.tsx:48-61` loads roots on scope/membership/manual refresh; `:37-46` deliberately performs fresh explicit file opens and guards draft identity. `editor-drafts.ts:47` is an in-memory draft-store subscription, not an OS filesystem watcher.

To make these surfaces responsive to external edits, add a workspace change owner, shared with Code Context, rather than declaring current absence of timers sufficient. Watch admitted worktree roots for edits/add/remove/rename and explicitly watch Git metadata that matters (`HEAD`, index, refs, packed-refs, config and the resolved common Git directory). `.git` may be a file pointing outside the worktree and worktrees share metadata; the watcher must derive actual Git paths using existing trusted repo resolution, not concatenate `.git`. `fs-watch` default ignores `.git` (`fs-watch/src/index.ts:42`), so a generic workspace watch alone does not cover branch/index changes.

Send small invalidation information scoped to project/workspace/root/revision; recompute status/diff using existing bounded reads only while the relevant pane is visible or on next activation. Dirty editor buffers retain their text, base revision and conflict indicator after external changes; never overwrite them with incoming snapshots. External watcher events are hints, not authority to read outside current roots; existing native project membership, handle validation and save revisions remain required at every read/write action. Shared roots must not leak names or content to another workspace/session.

### CLI, SDK and transport

No direct interval/sleep/recursive-timeout loop was found in tracked `apps/cli/src`. CLI input and termination use readline/process signals (`apps/cli/src/index.ts:866-889`, `run.ts:474-475`). This does not prove transitive dependencies have no timers.

SDK already supports `onNotification` (`sdk/src/client.ts:184-188`), and server subscribes to session events (`sdk/src/server.ts:272-279`). Its timers are request deadlines (`client.ts:169`) and a 2 s shutdown grace (`:369`), not state polls. Existing protocol explicitly says notifications are append-onward and never replayed (`sdk/src/protocol.ts:46-49`). New surface subscriptions therefore need explicit snapshot/recovery semantics; do not silently assign replay guarantees to existing session/event.

Gateway capability augmentation is in `desktop-gateway/src/router.ts:34-76`. Desktop main filters notification methods (`desktop/src/main/sdk-runtime.ts:167-177`), and bridge union is in `desktop/src/shared/bridge.ts:152-159`; all three need additive changes for new notifications. Main invalidates runtime generations and emits disconnected at `sdk-runtime.ts:189-199`. Ensure subscriptions from a dead gateway epoch cannot refresh a new runtime, and do not make every stray notification auto-relaunch an offline gateway.

## Concrete small contracts/modules to plan

These are proposed paths, not existing implementations. The user's authorization includes restructuring existing IH modules when necessary for correct event ownership. Prefer a producer-owned revisioned snapshot/watch contract over attaching global callbacks to legacy reads. Reuse current projection logic, authority owners and notification transport where sound; avoid a new global store of copied domain state. The lightweight gateway hub below forwards owner revisions and composes views; it must not invent authoritative domain state or replace native permission checks.

1. **`packages/desktop-gateway/src/surface-events.ts`**: small revision/invalidation hub owned by one gateway lifetime. `SurfaceKey = {domain, sessionId?, resourceId?}`; `Cursor = {epoch, revision}`; `subscribe(key, listener) -> unsubscribe`; `invalidate(key, reason)`. Producers call only after committed/observable state changes. Listener failure cannot fail a producer. Coalesce invalidations per key without retaining unbounded output payloads. Gateway derives workspace identity; renderer cannot inject another owner. Session resource revision must include live ownership changes as well as persisted events.
2. **`packages/desktop-gateway/src/surface-subscriptions.ts`**: additive RPC request methods, e.g. `desktop/surface/subscribe {subscriptionId, key, after?}`, `desktop/surface/unsubscribe`, and `desktop/surface/changed {subscriptionId, epoch, revision, reason}`. Negotiate capability such as `desktop-surface-events: ["1"]`; older backend uses initial/manual refresh or an explicitly classified compatibility policy, never a hidden new timer. Prefer subscription acknowledgement with revisioned snapshot or subscribe-before-snapshot plus buffered invalidations. Initial subscribe must resolve unknown/archived/revoked scopes with terminal unavailable state.
3. **`packages/desktop/src/renderer/session/use-surface-subscription.ts`**: shared scoped read/invalidation controller replacing polling part of `execution-surface.ts`. Keep its generation and mutation-ticket protections, add genuine single-flight for reads, `dirtyWhileReading`, visible/hidden state, disconnect handling, mutation readback, monotonic revision acceptance. `pending.current` currently guards actions, not normal overlapping reads (`execution-surface.ts:12-25`); do not preserve that accidental overlap. Bind subscription before snapshot; once a read settles, a higher pending revision triggers one follow-up. Returning visible performs one synchronization and resumes subscription without a permanent wake timer.
4. **`packages/desktop-gateway/src/settings-observer.ts`**: gateway lifetime uses existing `watchSettings` and direct committed-write signals to perform initial/dirty serialized sync. Hold on to pending dirty state across watcher errors/replacement. Dispose observation before owner shutdown; await in-flight leased sync. Apply safety policy before issuing revision describing the effective state. Settings background sync must not run optional costly environment probes; existing separation in `agent-settings.ts:24-27` is valuable.
5. **`packages/desktop-gateway/src/workspace-changes.ts`**: ref-counted watcher leases for explicitly admitted source roots and resolved Git paths. Contract `watch(scope) -> {snapshotRevision, changes: AsyncIterable<Invalidation>, close}` with add/change/unlink/reset/unavailable. Bound queued changed paths, collapse overflow to reset/full rescan, share one watcher per canonical authority/root, track source-set revision, drop old-root events after revocation. Extend `fs-watch` options only as necessary for explicit Git metadata/exclusion policy and watcher health. A reset triggers one reconciliation scan; it is not a standing scan interval.
6. **Terminal producer contract** in `terminal/src/service.ts`, optionally extracted to **`terminal/src/observation.ts`**: `observe(id, owner, afterCursor?) -> {snapshot, subscribe, dispose}` or subscribe-then-read equivalent. Changes distinguish output range, root exit, output drained, settlement, resize and removal. Gateway `terminal.ts` adds subscribe/unsubscribe and bounded cursor reads. Cursor includes service epoch/terminal instance identity plus offset; string ID `term-N` alone can repeat after restart. Preserve current UTF-16 cursor units unless introducing a versioned migration. Terminal ring overflow keeps `dropped` and earliest retained offset semantics. Root exit alone must not stop reading before the final output drain (`TerminalRecord.outputDone` at `:86,92,130` is a separate signal).
7. **Browser producer contract** in `desktop/src/main/browser-surface.ts`, optionally **`browser-state-events.ts`**: `subscribe(workspaceId, listener)` and revisioned tab snapshots; register one set of WebContents event listeners per created tab, remove them on close/destroy. Native IPC event belongs to window + workspace epoch. Emit immediately on open/close and actual metadata transitions; coalesce duplicate navigation/loading events. Hidden browser view and suspended renderer subscription must not orphan the native views. Route only to their owning BrowserWindow.
8. **Retrieval status contract**: add `onStatusChanged(listener)` to `code-retrieval/src/types.ts` and implement at configure/start/progress/phase/cancel/commit/failure/clear/search-health boundaries in `service.ts`; similarly expose context-output status changes relevant to the combined surface. Avoid using durable index generation as sole UI revision: progress, failures and metrics can change without a committed generation. `context-runtime.ts` consumes workspace changes with `dirtyRevision`, remembers changes during active indexing, and rechecks enabled/authority before another run.
9. **Plugin/resource contracts**: replace managed `observe` implementation with native watch + committed registry observation in new **`plugin-registry/src/observation.ts`**; preserve registry locking/materialization ownership. **`desktop-gateway/src/resource-observer.ts`** converts effective local resource roots, imported registry updates and MCP catalogue changes into resource/settings domain revisions. Watch root creation/deletion/atomic replacement, including global and workspace layers with shadowing precedence. Do not turn each popup into its own recursive filesystem watcher.
10. **Coding Plans local state events** in account owner + gateway: subscribe to redacted account/login status/result changes; never send token/secret document contents. External credential file changes need narrowly scoped invalidation and a leased reread, not exposing secrets. Account generation must fence sign-out and stale sign-in/usage completion. No new external feature is required.

## Snapshot, missed updates, lifecycle and isolation invariants

- Every observable scope is identified by **connection/service epoch + authoritative scope identity + monotonic revision**. The revision is for the complete view, including ephemeral live authority; it is not necessarily session event seq or durable index generation.
- Register the producer subscription before capturing snapshot. Either provide an atomic snapshot-with-cursor at that boundary, or retain all newer invalidations while the snapshot is computed and re-read exactly once if dirty. Naive `read(); subscribe()` loses changes; naive `subscribe(); read()` still needs stale-read fencing.
- Notifications may coalesce; therefore they are invalidations, not promises of every intermediate state. For required ordered output, use sequence/offset and bounded replay. If delta replay has overflowed, return explicit reset/snapshot-required, never silently skip.
- Reconnect uses a new epoch and fresh snapshot/resubscription. No assumption that existing SDK session events replay. Unsubscribe on scope switch/unmount, ref-count shared producers, fence late replies, and unsubscribe before owner disposal. Destroyed sessions/resources get terminal unavailable/reset events.
- Visibility pauses expensive snapshot/output drains, not domain execution. Track dirty cursor; on visibility/focus activation resubscribe/snapshot once. Browser/terminal ownership remains alive where current product behavior retains it. UI timer inactivity cannot cancel legitimate jobs.
- Pending mutations keep controls locked until confirmed result/current readback. Invalidations while mutating set dirty, then drain once. A stale snapshot cannot re-enable cancellation, erase a draft or restore a revoked root. Events never authorize operations; existing execution ownership and native filesystem checks remain authoritative.
- Keep transport queues bounded. Large output stays in existing ring/spill/history reads with provenance; event payloads carry small identifiers/revisions. Terminal writes await frontend acknowledgement/backpressure. A slow or disconnected renderer must not block process settlement or grow unbounded queues.

## Meaningful acceptance tests to put in the implementation plan

1. **Idle query silence**: fake clock + counted requests/filesystem scans; mount each S1-S7 visible pane with snapshot settled, advance several old poll periods with no producer changes; assert zero extra state reads. For S8-S10 count leased settings reads, index starts and registry stat/reload calls, not merely absence of `setInterval`. Allow only documented display/deadline/protocol timers.
2. **Handoff race**: change producer before snapshot, during awaited read, immediately after subscribe acknowledgement and while mutation lock held; eventually exactly the newest revision wins. Burst invalidations cause at most one in-flight read plus one dirty follow-up; delayed old result never restores stale controls.
3. **Scope/restart**: switch workspace/session/page while read is held; retire old gateway epoch and replay its queued event/reply; assert no old content, ownership or mutation action leaks. Unknown/archived/revoked scope emits unavailable. Listener counts return to baseline after StrictMode mount/unmount and repeated pane toggles.
4. **Execution/process graph**: create cell, nested dispatch/output/result/close; create background shell/workflow/retrieval/subagent job, emit partial output, cancel, finish and lose live assembly. UI updates from producers without a model tool/result or a 1.5 s read. Historical records stay visible but cold history never gains live controls.
5. **Terminal**: output just before/during subscribe, multiple >32 KiB chunks, multibyte UTF-8 split across native chunks, ring overflow, slow xterm writer, hidden/resumed pane, root exit before last output/drain, settlement failure, close while read in flight, service restart with reused numeric terminal ID. Assert monotonic cursor, bounded queue, explicit dropped/reset and final tail output exactly once. Owner mismatch must reject subscribe as it rejects read.
6. **Browser**: main-side navigation, same-document navigation, redirect, title/loading changes, back/forward, blocked navigation, failure, renderer death, tab close and window destruction update their own workspace without list polling. Hidden tab does not generate renderer reads; reactivation has current metadata; URL field focused by user is not overwritten.
7. **Workspace/Git**: atomic rename-save, delete/recreate, new nested directory, ignore-file change, Git checkout/index stage/unstage, linked worktree `.git` indirection/common refs, source-root revocation mid-event and watch overflow. Confirm visible status/file tree catches up, inactive view refreshes once on activation, unsaved draft survives, and no excluded/cross-scope content leaks.
8. **Settings/plugin/resource**: another IH process performs leased atomic write; malformed temporary file, missing file first creation, watcher error/reopen, equal mtime/size different contents, update during materialization, write while apply in flight, shutdown with pending lease. New saved/effective policy and catalogue appears once; runtime policy stays constrained on invalid input; draft conflict state preserved.
9. **Code Context**: enabled initial index, burst edits, changes during active index, cancelled/failed progress, config/source set changes, disable/revoke while busy, steady unchanged workspace. At most one active index and one needed follow-up; no 30 s scans; final outcome always arrives even if progress coalesces; source-health validation stays authoritative.
10. **Coding Plans/foreign protocol exception**: local login pending/completed/cancelled/failure transitions push immediately, stale network completion after sign-out cannot restore account, redacted event schema contains no credentials. Device-token requests remain bounded by protocol interval/expiry and cancellation. Local UI does not query state every 1.5 s. Quota freshness clearly matches selected explicit/external-refresh policy.
11. **Compatibility/backpressure**: old backend lacking new capability still supports snapshot/manual refresh with clear availability; new notification whitelist/protocol additions are covered; saturate notification consumer and prove bounded invalidation memory/reset recovery and unaffected producer settlement.

Suggested implementation order for parent integration: establish additive scoped cursor contract and reusable renderer controller; wire existing session/resource producers; add terminal/browser observations; add settings/plugin/resource observation; add workspace/Git/retrieval invalidation; then cover static settings panes and exception/deadline behavior. Do not claim completion from deleting timer syntax alone; acceptance requires timely producer-driven updates, idle silence, recovery and unchanged authority boundaries.
