## Actual implementation

The existing prepared request now carries a small immutable `textOutput` observation. Actual adapters produce it from the lowered final body; selected output-cap derivatives recompute their own value and wrappers preserve it. Five adapter packages cover six distinct route kinds, including public Responses and Codex subscription after their different lowering rules. It is separate from final protocol validity, capacity, native authenticity and execution authority.

The real summary preparation consumer requires known text eligibility on the selected final candidate before attempt charging, flushing or transport. Known JSON/schema/enum/forced-tool modes block a text checkpoint; unknown/custom capability remains explicit. Ordinary main requests retain their format behavior. No raw options are stripped and no alternate model is silently selected; only the pre-existing explicitly configured summary client is used.

Prompt, checkpoint parsing and bounded stream collection are separate cohesive leaves. Accepted checkpoints require the exact framing, seven ordered nonempty sections, valid completion and retained size bounds. Tool output, refusal, truncation, incomplete/corrupt completion and malformed structure cannot become an accepted summary. Retained text allocation is bounded while actual trimmed JavaScript code-unit length is counted separately. Long surrounding whitespace remains compatible. Observed usage is finalized once even for rejected/error/cancelled attempts; a callback failure cannot silently accept text or hide an existing stream failure.

The authorless keyword prefill is removed: imperative words in replay text do not establish human provenance. Replay text remains intact and manual refinements cannot override the checkpoint/tool restrictions. This is not a claim that syntactically complete summaries are factually perfect or that every main-request authority representation is already integrated.
