## Frozen behavior to preserve

- One winner per directory: AGENTS first; only absence permits CLAUDE fallback. Empty AGENTS wins. Directory/unreadable/invalid AGENTS is diagnosed and does not quietly activate CLAUDE. Sources render broad to narrow with lexical scope labels; deeper rules never become sibling/global authority.
- Host roots are explicit. Select the narrowest authorized root containing cwd/target, intersect with confirmed Git boundary (including .git worktree file); otherwise selected workspace is the boundary. Other allowed roots activate on actual target use. Root/member revision belongs to the host. Canonical paths deduplicate aliases and reject junction/symlink escape; retain lexical paths for scope.
- Globals are ordered host/user configuration. New default is resolveHarnessHome()/AGENTS.md with same-directory CLAUDE fallback. Existing legacy profile migration records effective old home/.claude selections once as explicit globalSources, preserving actual old ordering/deduplication, and lets the user disable them. Never infer “legacy profile” from mere absence of the new key in a new isolated profile; migration must use persisted existing-profile evidence. IH_CONFIG_DIR profiles/tests do not inspect ambient home. No ~/.codex discovery.
- Explicit global entries are exact configured paths; default native pair retains winner semantics. No imports, .claude/rules, CLAUDE.local.md, managed policy, auto memory or AGENTS.override expansion. Import-looking text can yield a bounded unsupported diagnostic.
- Total rendered UTF-8 budget defaults to 24,000 bytes, including headers, separators, scope labels and truncation marker. Bound file reads after opening/checking regular file; never first read huge content then slice. Zero/disabled reads no content and clears effective instructions. At most 256 candidate/source slots across global/ancestor/active targets and depth 128; report bounded incomplete/error status, never complete authority after overflow. Candidate absence and shadowed priority slots are dependencies too.
- Transient unavailable sources may retain explicitly flagged last-known-good display; mutation needs reliable current applicable dependencies. Revocation/outside-scope/disable remove text immediately. No model call is required for discovery, refresh, diagnostics or invalidation.
- Watch events dirty only dependent source sets. Rebuild on initial/dirty/new target/explicit refresh/recovery; snapshot() is memory-only. Dirty during rebuild causes another bounded reconciliation, never lost invalidation. No every-step full stat and no periodic file polling fallback. Same source owner handles native candidate pending tokens before I/O and settle/invalidate/release on success, failure or partial effect.

## Shared contract root must freeze before integration writers

The names below are proposed additions, not claims about current exports. Keep existing InstructionScope/Snapshot/Service meanings; add dependency and reliability evidence needed by the already approved mutation gates.

1. **Source owner:** immutable InstructionSnapshot { revision, fingerprint, text, bytes, sources, reliability, dependencies }; dependency identity includes canonical candidate slot, lexical applicable scope, existence/winner/content revision, membership/global-policy revision, pending/unavailable state. `prepare(paths)`, `snapshot()`, `invalidate(paths)`, `subscribe(listener)`, `close()`; narrow `beginCandidateWrite(capturedOperation, targets)` returns an exact-once settled lease. Source owner owns neither producer cancellation nor Session acknowledgment.
2. **Session owner:** createSessionContext({ session, factSource, scope, sourceOwner, policy }) produces prepareTargets, reconcileBeforeCapture, captureInstructionEvidence, acknowledgeIssuedRequest, close. It owns activated targets and request acknowledgments separately per Session, even with shared physical reads/watches. Acknowledgment is bound to that Session + exact request/candidate + originating accepted exchange/call, never “latest text seen by any session.”
3. **Durable/current projection:** one typed `runtime/context` v1 complete section snapshot, published through existing owned fact/receipt/coordinator and registered in current closed event validation/persistence. Empty sections clears all; absent instructions clears just that section while skills remain. Latest valid current snapshot is a dedicated current-context component, not a human input attached to a tool exchange step interval. Old events remain audit data. Legacy runtime-context plugin messages remain readable; first typed snapshot suppresses their active rule authority.
4. **Request admission:** reconcile before each candidate capture/rebuild; synchronously capture section identity with ContextSnapshot. Existing capture/prepare/assess/checkpoint/final transport gate must account for instruction semantic identity and observed pending/revocation. Do not mutate the request after assessment. If observed state changes before first transport, rebuild through the existing bounded stale-input path; do not rerun pre-step hooks or input claims. Once a physical request is issued, its retry uses the same captured bytes; newly observed instructions take effect at the next logical safe boundary and fence affected mutation from stale output.
5. **Acknowledgment:** “rendered/persisted” is not “sent to model.” Bind issued evidence from the existing `prepared.stream` transport-issue/confirmation path to the exact prepared identity. Failed/incomplete model output grants no tool execution acknowledgment. Final accepted exchange/call carries access to the originating issued dependency evidence. For no-transport custom model test paths, use a controlled explicit equivalent contract, never falsely claim a physical send.
6. **Native target plan:** trusted registered tool captures one normalized plan from the same frozen args and binding used for execution. Entire known mutation batch resolves/prepares all applicable targets before any mutation body. Tool metadata is not model JSON authority. Exact request/dependency evidence travels privately via PreparedCall/ToolExec (or capability bound to them).
7. **Replan disposition:** typed INSTRUCTIONS_REPLAN_REQUIRED { currentFingerprint, boundedReason, splitRequired?, applied?, notApplied? }, separate from policyRefusal and cancellation. Initial refusal starts zero mutation bodies. Late invalidation stops not-yet-entered affected write boundaries, preserves real earlier effects and drains accepted independent work.

The root should freeze these as one compact contract before downstream edits. If typed events require a Session format increment beyond current11, the core/persistence writer owns that single decision and migration alongside R4B/R4C; do not independently allocate versions or copy old event append registries.

The actual-host report at `.superpowers/sdd/2026-10-23-context-transfer-host/long-growth-diagnosis-report.md` proves: runtime-context’s synthetic user/message becomes input in the same step source interval as a completed24-tool exchange; active-turn input protection then protects that whole exchange. After the turn, mandatory latest-exchange retention still blocks reducing it. The60-read repeated-growth path succeeded; the24-call path did not. This is evidence from the reported host tree, not a test run by this planning lane.

I3 and this repair MUST share one writer/contract for `core-session/src/conversation/{state,unit-state,sources}.ts`, `conversation/history/{group,sources}.ts`, current projection, `context-engine/src/snapshot/{build,protected,revision}.ts`, and `reduction/selection.ts`. Typed current rules stay protected/present independently; actual human task and unresolved effects stay protected; unrelated completed tool history must not acquire indefinite protection merely from a current-context update in its step. Do not solve this by dropping instructions, altering their authority into an untrusted summary, or weakening call/result grouping. Capacity escape from latest complete exchange and possible bounded summary source remain the existing R3/compaction owner’s repair, not a second instruction reducer.
