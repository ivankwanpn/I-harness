## 3. Shared R4C/E contract freeze (root decision before D work)

These are **proposed deltas**, not existing APIs. Freeze once with R4B's current Session11/format boundary; individual workers must not bump formats independently.

```ts
interface DeliveryKey {
  parentSessionId: string
  sourceNamespace: string // actual registry/delegation or owned source incarnation
  sourceId: string
  resultRevision: string // original retained terminal attempt, not rerender/wake ID
  deliveryKind: 'subagent' | 'team' | 'exec' | 'workflow' | 'code-cell'
}
type DeliveryDisposition = 'promote' | 'defer' | 'already-claimed' | 'incompatible' | 'suppressed'
interface DeliveryAdmissionReceipt {
  inputId: string
  disposition: DeliveryDisposition
  durability: 'durable' | 'nondurable'
}
```

- Replace text-only ParentInputAdmission with proposed `admitDelivery(source: TrustedDeliverySource, presentation: DeliveryPresentation): Promise<DeliveryAdmissionReceipt>` and `requestDeliveryWake(inputId:string):void`. Presentation retains existing text/description/display. TrustedDeliverySource is a capability minted by the actual source adapter after qualified original settlement; its immutable key/branch/delegation/generation descriptor travels outside model/tool/RPC input. Do not expose a generic mint function. Source/receiver commit-unknown remains existing typed recovery failure, not success.
- Keep original R4C tuple semantics: key independent of text, target epoch, transport and wake count. Old `completion:<new work UUID>:<new attempt UUID>` must not mint another identity for already-owned task/native results. Legacy task/message/call evidence is adopted conservatively; missing epoch/claim certificates means explicit defer/reconcile, never invented authority or text-hash identity.
- Store receiver target branch/epoch and disposition. Both idle lane selection and active step claim use the same committed eligibility/precondition. Summary may preserve/reassess a stable pending suffix; consumed delivery never becomes new because text is hidden.
- Recommend explicit durable **delivery generation under the existing recipient writer**, distinct semantically from finite model context/action invocation. Ordinary turns/steer retain legitimate background generation; Stop fences immediately, commits its closure, and old results remain suppressed through new human turn/restart. Do not create an independent completion-generation store. Original issued settlements may finish without authorizing transport/wake.
- Source drain and receiver scheduling drain have different responsibilities; only one of each per source/recipient. Add exact assembly/lane post-publication reconcile for both ordinary children and team. Remove old/new concurrent drain paths on migration.
- Deferred adoption must have an actual explicit recovery/manage caller naming the **same key** and audited current authorization. Generic human input cannot revive suppressed results. Root must choose that existing command or add the smallest real management action; an unused resolve API is not a deliverable.
- Trusted observation source yields `user-steer | background-event | undefined` from real eligible committed same-session input, and never claims it. Nested resultConsumer=code sees no host wake. Match exec promotionReason/workflow-subagent yield_reason/outer Code Mode union; no provider abort/replay.
- Policy reconciliation: explicitly background/handoff child followup attempts notify once per real result revision; quiet team and foreground followups stay quiet absent explicit parent delivery. This satisfies E3 without expanding the older R4C policy into notification for every followup.
