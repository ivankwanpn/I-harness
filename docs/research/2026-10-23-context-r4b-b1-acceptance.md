- Semantic inheritance is a dedicated selected-content representation. None performs no source payload work; current effective history, complete source intervals, turn domains, nested origin/omission relationships, typed media/results and exact dependency observations are retained without cloning consumed archive bodies or manufacturing local execution facts.
- Shared history remains the structural owner; seed records use local group/item/call/result/media addresses. Whole-group replacement is supported; inherited v1 callId pruning and false reduction progress are excluded. Inherited data creates no local pending-input/effect authority.
- Session11 records and reservation scalars are validated through ordinary public readers and same-owner private bootstrap staging. Existing format10 sessions can actually cross the writable barrier, preserve their prior body/metadata/observations, admit normal new facts and reopen; no ready certificate is fabricated on upgrade.
- Selected text and prepared-input equality/provenance use one descriptor-aware owned reader. Metadata-only source selection defers text equality in the EXISTING preparation owner; the same checks run on the selected complete component before formatting/provenance/rendering. Unselected prepared text stays unread, public/full validation remains strict, and actual observation property order is preserved.
- Public append/replacement refuse invalid seed/readiness candidates before publication. Public metadata updates preserve fixed reservation/birth fields, ordinary title/archive/model/workspace edits and body/torn-tail bytes. The final serialized header is compared against pre-evaluation protected expectations and those exact bytes are written, with detached return data.
- Memory bootstrap checks target installation slots, existing binding and current state before any mutation and again after the current guard. Observers see the complete installed state. One immutable catalog reference cannot carry contradictory catalog counts.
- Genuine old-reader qualification is reproducible from committed, hash-checked fixture bytes and supported Node/tsx. It requires no historical workstation folder, Bun, runtime Git history or network download. Original license files are retained; missing/corrupt/out-of-scope fixture data fails explicitly.
