## Conclusion

IH does not upload its whole JSONL disk transcript or blindly serialize every continuation backup. It uploads the current active projection, plus current system/tools, and adapter-eligible native reasoning. Repeating that active prefix in a stateless HTTP request is normal. The proved avoidable growth is repeated full child reports, retained large tool results, and accumulated changed runtime snapshots; the proved protection defect is measuring a smaller surface than the one serialized, particularly replayed thinking. Other agents can keep one visible session alive by keeping a bounded active window and replacing older content with summaries/pruned results. A huge visible session is not evidence of an equally huge model input.

Some Codex requests additionally use conditional WebSocket deltas, reducing repeated transmission. This changes wire bytes, not the amount of existing context the server processes. It is a transport optimization, not necessary to repair IH's overflow recovery.

## Four quantities that cannot be substituted

* **Disk transcript:** events, headers, metadata, original results and backups. Audit persistence can grow indefinitely while active input remains bounded.
* **Serialized request:** protocol body after projection, grouping, replay checks, images, options/cache filtering. JSON signatures/base64 and schema framing cost bytes; provider tokens are a different measure. Bedrock SDK command JSON is not exact serialized AWS HTTP size.
* **Provider input tokens:** provider accounting, including cached input according to the protocol's includes/excludes-cache semantics. A cached prefix remains context even if billed cheaply. A response-ID continuation can reference context absent from current request bytes.
* **Context state:** active input estimate/measurement, window, output reserve/cap, revisions and uncertainty. IH's current UI percentage is a neutral-history heuristic rather than a measurement of complete current provider input.
