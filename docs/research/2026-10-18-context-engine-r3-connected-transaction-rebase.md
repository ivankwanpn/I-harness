## Publication rebase findings

`ManagedAction.capture*` retains one lowered optional capture with admit/reconcile/observe. It intentionally exposes no retryAbsent privilege. `managed-document.ts` stores private Authorization and calls assertAuthorized while draining the queue and again inside issuingFactOwner.beforeIssue. JSONL fact-journal performs no await between that final callback and first write. This is the correct extension point for source/protection/binding comparison, not a new mutex or post-flush check.

The new context-specific capture must attach a synchronous trusted precondition to the same optional action. Its draft is a closed context-reduction group (only intended rewrite records, including replacement), not arbitrary SessionEvent[]. The callback carries no persisted credential/body/Session ownership and is never exposed to plugins. The regular fact validator still validates exact prefix coverage before staging.

Current pre-issue exception mapping loses unfamiliar errors: managed-document falls back to FACT_INVALID_GROUP, while JSONL maps unfamiliar pre-issue errors to absent. Therefore a typed `FACT_PRECONDITION_STALE` (or a single equivalently closed name frozen in the executable plan) must travel through every relevant mapper. A stale source is not a storage failure, unknown issuance or permission to retry arbitrary bytes. Check all in-memory/durable outcome readers before changing the union; keep arbitrary thrown errors closed and untrusted.

The same capture's committed disposition remains observable after Stop; source invalidation after issuance cannot revoke its known receipt. Unknown/recovery-required retains the actual capture handle for reconciliation and fences dependent work. Backend-proven absence after Stop cannot reissue. No required-settlement retry privilege is granted to an optional reduction. An in-memory standalone path may return only explicit nondurable disposition and must share atomic structural validation; it cannot manufacture FactReceipt.

The final check must include the complete request view that was last assessed, not merely selected source. If an accepted retained suffix arrived during a backend await, a previously ready target may be stale even though summary source remains valid. Refuse before issuance, reuse the completed summary only after bounded remeasurement, and issue a new capture only for that revalidated transaction. If only diagnostic/usage metadata appended and semantic/protection/binding facts stay identical, do not invalidate useful work because eventCount changed.

## Finite logical-step handoff

The existing `turn.ts` creates candidateState once after hooks/claims and reuses it across failed physical responses. Put the local summary-invocation tracker and reduction reuse state there; manual compact gets one explicit action-local state. Both auto and confirmed recovery consume that same state for a logical step. Do not allocate eight new local calls on each stale retry, span, piece or recovery attempt. F4 still owns physical reservations and cannot be claimed complete by this tracker.

Ruling: retain at most three genuine stale rebuilds/reassessments across the logical step, including suffix/binding/assessment changes. A successful committed rewrite is known progress, not evidence of unstable input, so do not charge it as a stale race. Further reduction passes must remove a finite selected eligible unit set and strictly reduce the measured failing input dimension; all generated summaries share the same at-most-eight local stream invocations. Prune-only proposals consider all eligible relevant records once, with no no-op republishing. This avoids both hidden reset of allowances and the old compacted boolean's premature failure after one useful but insufficient reduction.

Selected content/coverage/unit membership, branch/rewrite or applicable protection change invalidates the summary. Compatible retained suffix only requires full final-request remeasurement. Budget/usage/diagnostic appends alone do not consume stale allowance. Applicable calibration/recovery change requires assessment freshness but cannot become a reason to resummarize an unchanged source. The final executable plan must bind this to an actual read-only assessment revision/token or repeated pure calculation; it cannot use an arbitrary global settings counter.

The pre-E target remains `capacityFit && I+R+H < thresholdRatio*W`, separately from real recovery authorization. A receipt may yield reduced-over-target; it is not permission to send. The ordinary main path must then prepare/assess its actual current request and obtain any single changed-input recovery authorization through the existing recovery owner. Pending or exhausted authorization cannot be invented by a hypothetical probe.

## Guarded-publication coalescing boundary

The actual managed-document pump coalesces adjacent entries when action, source identity and required disposition match. A new optional reduction capture that keeps source undefined could share a frame with earlier same-action feedback/input facts. The history stage would see that prefix, but a final guard reading only live state.view would not see the uninstalled prefix inside its own batch. Thus a last-assessed full-request check could miss a semantic/protection change even though it runs at beforeIssue.

Ruling for the connected producer: give each guarded reduction capture a private unique optional coalescing-source identity through the existing Authorization.source field. It is a batching boundary, not a registered required-settlement authority. Keep its intended prune/replacement records inside one closed group, but never coalesce it with ordinary metadata/feedback or another reduction capture. Prior queued work must finish/install first, so the normal final live-view guard includes it; later queued work remains a subsequent suffix. This avoids a fake staged Session/second request renderer inside the writer and uses the existing writer lane.

Mandatory controls: held queue plus same-action plugin feedback before reduction makes the later full-view proof stale before any R write; irrelevant metadata before it remains semantically compatible; two guarded captures cannot share a frame; ordinary existing coalescing remains unchanged. A pure source-valid check alone is insufficient because a retained suffix can change final capacity. Cost is a separate physical journal frame for a reduction, preserving ordinary coalescing elsewhere.
