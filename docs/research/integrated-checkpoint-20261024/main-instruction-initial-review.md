### Important (Should Fix)

**[I1] Newly owned standalone saved-policy environment can escape construction-failure cleanup.**

- **Location:** `packages/session-executor/src/assembly.ts:1056` (new resource acquisition), with the unguarded callback at `assembly.ts:1178`–1179 and the disposal guard beginning only at `assembly.ts:1195`.
- **Trigger and result:** A supported direct caller can invoke `createSessionAssembly({ instructionSettingsPath: ownedPath, codeMode: () => { throw fault }, ... })`. Line1056 creates an owned saved-profile environment. Its `policy.ts:73`–85 starts the asynchronous strict-read/watch initialization immediately. Before entering the try block, line1179 calls the supplied Code Mode getter. If it throws, assembly construction rejects without entering the catch/dispose at lines1747–1749. The saved policy's initial job can subsequently acquire its watch lease, but no assembly is returned and the caller never receives the internally created environment handle. The owned policy/watch consequently has no reachable cleanup owner; repeated failed mounts accumulate these resources.
- **Scope:** This is the direct standalone `instructionSettingsPath` branch. Headless keeps an outer `ownedInstructions` handle, and SessionService keeps its `defaultInstructions` handle, so their outer cleanup can recover the corresponding environment. Those outer owners do not cover direct standalone construction.
- **Why it blocks:** The plan explicitly requires standalone default/environment ownership and joined cleanup on failed construction. Introducing an internally owned async watcher before a potentially throwing public callback, outside the only disposal guard, breaks that lifecycle guarantee even though the successful entry gates pass.
- **Correction:** Move environment/manager acquisition inside a construction cleanup guard that includes the initial Code Mode getter, or guard that intervening construction section and join the same original environment on failure. Preserve the original construction error and aggregate an actual cleanup failure; do not create a replacement environment or close a supplied borrowed environment.
- **Focused regression needed:** One direct standalone construction using a temporary selected profile and a deliberately throwing Code Mode getter, instrumenting the actual newly owned watcher/environment to prove no lease survives (or initialization is fenced before acquisition). Exercise one same-owner close failure/retry only if the correction exposes that path. No full suite rerun is required to establish this defect. This finding is established by source control flow; no new probe was run.
