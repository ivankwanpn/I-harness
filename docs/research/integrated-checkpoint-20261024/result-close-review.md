## Actionable finding

### [P1] Preserve the shared instruction environment while an original assembly remains held

Location: `C:/Users/inkik/.codex/worktrees/context-current/I-harness-main/packages/session-executor/src/service.ts:1037-1039`.

The new unconditional `defaultInstructions.close()` runs even when an assembly's `dispose()` just rejected and its original handle remains in `assemblies`/`mountingAssemblies`. This environment is dependent on that assembly's original instruction publications; it is not independent cleanup in this state.

Concrete case: use the normal service-owned instruction environment, prepare a main instruction view, and make the actual managed runtime/context append report `unknown` while reconciliation remains `unknown`. Global close reaches `assembly.dispose()`. At `assembly.ts:1804-1806`, `runtimeContext.close()` cannot settle the original publication, and the explicit `runtimeClosed` gate prevents `instructionManager.close()` from closing its pinned original view. The assembly and result-store registration are retained for the same-owner retry. The changed global close then reaches `defaultInstructions.close()` anyway. `context/instructions/host.ts:18-23,26-31` directly closes every underlying `InstructionService`, bypassing `instructionView`'s references/pin gate in `views.ts:21-24`, and closes observation and the owned watch. `packages/instructions/src/service.ts:215` makes that source snapshot unavailable and clears its cache/listeners synchronously. Thus the still-unresolved original publication loses the observed instruction source that assembly disposal deliberately preserved, before its real disposition is known.

This is introduced by moving environment cleanup ahead of the accumulated-failure throw. BASE kept this dependent environment alive when assembly disposal failed. RC-03 allows continuing independent cleanup after reader failure; it does not authorize bypassing an unresolved producer's original view ownership. No instruction-owner refactor is needed to correct this new ordering regression.

Keep attempting reader cleanup, `beforeDispose`, independent assemblies/documents and other authorized independent cleanup. Close the owned default instruction environment only once no retained or mounting assembly handle remains. In particular, a reader-only cleanup failure must still permit closing an otherwise independent default environment. Preserve the original environment object for a later explicit close when an assembly remains held.

Required regression: exercise the actual default/service-owned environment, without supplying `instructionEnvironment`, through the unknown runtime publication case above. Assert that first close rejects, the original staged instruction view remains observed/ready and is not closed, the original assembly/result owner remains retained, no publication is replayed, and original reconciliation followed by explicit close settles it and closes the original view. Retain the reader-only independent-cleanup positive control. The existing `main-instruction-publication.test.ts` accurately checks the ownership rule (`closes === 0` while unknown), but supplies `instructionEnvironment: environment`; consequently `defaultInstructions` is absent and the 92-test green run cannot detect this regression.
