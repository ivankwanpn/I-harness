## Required next design boundaries

R4B remains one semantic export/import/target-bootstrap gate; R4C owns delivery keys and wake/claim transitions. B consumes R4A's final immutable artifact dependencies and pin/grant owner, not a new artifact store or task scheduler.

The source export is a pure derived snapshot operation: effective ordered conversation/checkpoints/typed tail, exact lineage/provenance and dependency descriptors. It does not copy consumed raw proof bodies, parent usage/calibration, action/attempt allowances or permission receipts. Native replay compatibility is checked against the actual target route/binding; matching model labels are insufficient. Pure inspection does not create provider/auth/model work. The actual child constructs its own first request including role/current host instructions, delegated task, schemas, media and raw options, then uses the already accepted shared admission owner.

The in-flight parent spawn exchange, including parallel siblings and effect-unknown units, remains observation-only and is excluded as a whole from child wire replay. B must exercise the actual managed and standalone spawn/all first request; it cannot wait for its own spawn result or synthesize a result. None removes inherited conversation, not required host instructions. An inseparable requested boundary needs an explicit refusal, not extra inherited turns hidden behind a successful N selection.

Bootstrap must be a capability of the existing coordinator/target document owner with a stable operation identity and exact seed/header digest. The executable plan must define new-target versus qualified existing-empty-target behavior, cached/open eligibility, complete declared prefix length, source/dependency freshness and original unknown reconciliation. Artifact grants/pins and seed/initial-input receipts precede any child model/tool execution. Cross-store grant and document writes are separate confirmed phases; do not describe them as a distributed atomic commit. Unknown creation/grant cannot be answered by repeated spawn or destructive cleanup.

The100MiB parent oracle concerns semantic export/child seed size and absence of extra full-log cloning. It does not claim R6's archive streaming/cold-memory gate: the current source may already be loaded in memory. Actual controls must independently compare parent effective content/dependencies to the child's first prepared request and inspect absence of inherited execution facts/anchors, not merely compare two outputs of the same compiler.

Before B dispatch, freeze the actual semantic DTO/target compilation/creation unions, all real consumer and version fences, exact crash/Stop/cold oracles and old-path retirement against accepted R4A.
