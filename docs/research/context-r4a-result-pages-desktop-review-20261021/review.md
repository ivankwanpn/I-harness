## Actionable product finding

**F1 — [P2] Reject payloads whose byte coverage disagrees with the returned continuation.**

Location: `packages/desktop/src/renderer/session/result-page-view.ts:25` (ordinary pages), with the same missing relationship at `packages/desktop/src/renderer/session/result-page-view.ts:31` (same-record exec continuation).

The ordinary-page check only rejects payloads that *exceed* the declared span. A response matching the full immutable ref can therefore return `offset:0`, `nextOffset:50`, `eof:false`, `data:{kind:"text",text:"abc"}` for a 100-byte artifact and be accepted. Clicking Next then requests byte50 and silently skips 47 bytes. A response with the same three payload bytes and `nextOffset:null,eof:true` is also accepted; `RecordedResultPage.tsx:50` displays `0 → 100 / 100 bytes`, and `RecordedResultPage.tsx:56` announces the end of saved content despite 97 unaccounted bytes. Even an empty nonfinal text payload with an advancing offset passes. Existing fake page fixtures frequently use unrelated payload lengths and declared positions, so current UI tests do not detect the missing invariant.

For exec, a first response with `cursor:{recordOffset:9,sliceOffset:0}`, one `YWJj` (three-byte) frame slice and `nextCursor:{recordOffset:9,sliceOffset:100}` passes. The component forwards that exact cursor on Next, skipping 97 bytes within the same saved record. The current test requires a cursor to advance lexicographically but does not relate that advancement to the raw bytes returned.

The original ordinary owner (`packages/context-output/src/artifact/reader.ts:44`) derives nextOffset/EOF from the actual consumed encoded-byte length, and the original exec owner (`packages/context-output/src/artifact/exec-reader.ts:33`) derives same-record slice advancement from actual consumed raw bytes. The presentation boundary needs the corresponding checkable invariants. Preserve the original UTF-8 decoding behavior: `TextDecoder` can consume a leading three-byte BOM without including it in returned text, so a blanket re-encoded-text equality test would reject valid original pages. Require exact coverage for base64 byte data, explicitly account for the original decoder's bounded BOM omission for text, and constrain same-record exec continuation to the decoded bytes actually returned. Add meaningful malformed-response controls together with genuine owner/BOM and existing header/slice-continuation controls.
