# ContextEngine R4A — retained results and bounded model projection

2026-10-16. Future decisions based on pinned product `292362992f304e6bf7811f22df29608999c59539`; no implementation/test claim. Detailed API/limit/ingress evidence is `.tmp/context-redesign-20261015/r4-result-retention-preflight.md`. The approved [redesign](../superpowers/specs/2026-10-15-context-engine-redesign.md) and [framework](../superpowers/specs/2026-10-15-context-engine-framework.md) remain normative. Reviewed F1/F2/F3 contracts must be rebased before executable R4 dispatch; the current F1 writer receives no additional scope from this document.

## Concrete losses that the new owner must precede

The ordinary spill guard replaces tool output before its archive event and can return the original on a no-fit path. Exec's default per-channel64MiB spill cap can delete the full file and retain only a tail. Optional Context Output captures an8MiB prefix by default and has unsynced authoritative files, TTL/GC without active-reference pins and full-blob read/hash per page. Code Mode may drop output in the worker before the host receives it; its outer shipping spill wrapper can also change the structured object delivered to guest code. MCP's client preserves content/isError/structuredContent, but its bridge drops structuredContent and throws stringified error content. Child/job/outbox stores repeat full bodies despite bounded reports.

Ruling: deliver **R4A envelope + durable artifact + real ingress/read integration** as one reviewable gate; semantic seed export and child epoch/delivery qualification follow separately. Capturing a preview or adding a late file reference cannot repair source bytes already discarded. Existing incomplete/history data stays explicitly incomplete; migration never invents bytes, ACLs, integrity or durable receipts.

## One result, distinct execution and retention facts

The existing trusted tool/child/job producer owns execution outcome. The common versioned result envelope binds that outcome and call/source identity to a bounded model preview, ordered typed media and a retention disposition. Retention distinguishes complete, incomplete, unavailable and unknown; byte counts/digest/codec/revision are present only when established. A retention failure cannot turn a completed tool into a fabricated execution failure, and a shortened error message cannot turn an error/unknown effect into success. Unknown effects remain nonreplayable.

Separate a program's result value from its model projection. Code Mode guest transfer receives the same once-lowered structured value within its existing transfer policy, not a preview envelope. Above the guest limit, preserve the full host result artifact when admitted and keep the existing explicit transfer failure. Do not raise guest memory/CPU/transfer limits as a shortcut. Tool body, finalize, post-tool hooks and legacy getters/toJSON must not run again because storage failed or a page was requested. Rebase F1's once-only capture/settlement contract rather than create a competing serializer.

MCP normalization occurs while the complete McpCallResult still exists, before success/error branching drops fields. Retain content plus structuredContent and isError once; normalize recognized media/resource positions in order. A remote resource URI is retained as the returned reference, not a promise that its remote bytes were fetched. Arbitrary structured keys named image/images/audio remain in the complete payload. Only actually supported model media become typed input parts; unsupported audio/resource forms remain honest descriptors/references, never huge base64 text or invented protocol support.

## Full storage is separate from preview/index capture

Ruling: retain the existing workspace Context Output store responsibility and its configurable **512MiB default total disk quota**. Do not invent a second result store or silently increase quota. Full managed result admission is independent of optional Context Mode enablement and its8MiB bounded text/index capture. Search/index remains optional/rebuildable and can be partial. A complete100MiB result is admissible when real available quota covers its exact bytes, authoritative metadata and bounded staging/index overhead. It is not limited to the old8MiB prefix; it is also not promised when quota is insufficient.

Keep initial model/report policies with exact units: ordinary serialized model text/envelope64,000 UTF-8 bytes, child preview2,048 UTF-8 bytes, aggregate report16,384 final JSON bytes. Media has separate typed bounds; those text caps cannot be presented as total image/audio payload limits. Charge escaping and metadata. A configured cap below the minimal truthful envelope is rejected explicitly, not solved by dropping outcome or returning full original text.

For exec stdout/stderr, tee exact framed bytes into the artifact owner before the old collector's64MiB discard. Preserve channel/order and execution settlement; do not join another100MiB string or read it back merely to compute a preview. For already-materialized normal/MCP values, stream-encode the owned normalized value with the reviewed stack-safe JSON semantics and source ordering, avoiding another full serialized string/Buffer. Codec/digest scope must distinguish original channel/text bytes from encoded structured-envelope bytes.

Code Mode's existing guest emission limits remain. If a worker drops bytes before host admission, report source-limited incompleteness; saving every admitted byte cannot be called a complete original. Full arbitrary guest-output streaming is a separate producer/transfer change and is not required merely to make R4A's normal/exec100MiB fixture pass. This exclusion must remain visible in the final delivery report.

Known quota/capture refusal may settle with a bounded truthful outcome and an explicit unavailable/incomplete retention disposition, after that fact is durably recorded. It never falls back to an unbounded prompt or silently claims the original is recoverable. Until the fact is committed, its source handle remains retained. Unknown artifact or fact publication instead retains the source/pending operation and reconciles the exact identity; it cannot be relabelled as known refusal to release data early. Capture/serialization exceptions must use this explicit failed-retention contract or remain recovery-required, never an empty successful `{}` or repeated effect.

## Durability, pins and quota ownership

The existing artifact owner gains a qualified cross-process ownership/commit boundary using existing locking primitives. Authoritative blob/manifest/owner metadata requires complete-write handling, sync and exact disposition; the rebuildable search index cannot be commit authority. The workspace owner is distinct from F1's session document writer, with narrow composition ports and no reverse imports or second session log. Do not hold a session allocation lane while streaming a large artifact.

Commit artifact bytes/integrity/ACL and a pending ownership pin first, then publish the result envelope through F1's actual receipt. Failure between stores leaves a pending/orphan artifact that may be reconciled; it is not a distributed atomic transaction or permission to delete possibly referenced data. Unknown publication protects the artifact. Recovery differentiates committed references from proven unreferenced abandoned writes without repeating finalize/capture/body execution.

Ruling: start with **conservative document-lifetime reference pins** for newly committed managed results and grants. This is a safe superset of active-snapshot/checkpoint dependencies and avoids evicting a result still reachable from cold history or a replacement's source evidence. Ordinary TTL/quota GC cannot delete these pinned artifacts. Unpinned optional captures retain existing configured expiry/eviction behavior. The cost is higher retained disk use; when the existing quota fills, new full retention reports unavailable instead of evicting pinned data or growing without limit.

Deleting a document releases only that document's ownership pin after its existing deletion disposition is confirmed; other grantees/pins remain. Archive is not deletion. Existing generic Context Output clear/cache cleanup must refuse pinned or publication-unknown objects and return a bounded explicit disposition; it cannot break committed references silently. This stage does not add an automatic destructive purge. Source visibility/ACL revocation may deny reads without authorizing GC while a required pin remains. Orphan cleanup requires affirmative evidence that no committed/pending publication refers to the object; uncertainty keeps it protected.

Full-result refs become the retained truth for new large child/job/outbox bodies, with bounded previews and revision metadata instead of repeated full strings. Their existing settlement/delivery owners remain. This change alone does not qualify wake scheduling, input claims, branch promotion or delivery exactly once; those are the later R4 delivery gate.

## Bounded authorized reads and integrity

Preserve current workspace/session/source-visibility checks and host-only grants; a path or model-supplied ref-shaped object grants nothing. Before body I/O, validate owner, current visibility and exact revision/range. Read pages must include envelope/escaping/metadata in their final serialized response budget, advance a byte cursor on UTF-8 boundaries and report stale/missing/incomplete state explicitly.

Ruling: new immutable artifacts need a bounded-range integrity scheme rooted in the committed ref/manifest, so a32KiB page does not read/hash100MiB anew. Use streamed whole-content digest during capture plus a bounded chunk index whose identity is committed with the ref. A page verifies the relevant chunks against that rooted index. Keep whole-content digest and encoded-byte length separately for cold/full integrity controls. Exact chunk/codec schema and index-overhead calculation are frozen in the executable plan, with independent tamper/range tests; an unrooted editable list of chunk hashes is not proof of the ref's content.

Legacy refs keep their old integrity/expiry claims; no fabricated chunk index. Their one-time verified import/reindex, if performed, must stream under the owner and produce an explicit new immutable revision before claiming bounded page qualification. Rebuildable search uses the existing bounded text/work budget, reports partial coverage and cannot fetch full artifacts or external resource URIs implicitly. Loss of the optional index cannot revoke committed content or expand read authority.

## Acceptance and compatibility requirements

New result semantics require a deliberate versioned data contract and incompatible-reader fence at the actual future session/artifact versions. Legacy tool/result records remain readable by the legacy projection branch; ignorable context/result-ref metadata cannot serve as the only binding for a new outcome/artifact envelope. Structural export/fork must preserve dependency/ACL distinctions without copying live receipt or parent authority.

The executable gate must include:

- Literal1,048,576/104,857,600-byte complete results under sufficient configured quota; independent original digest after cold reopen, bounded model/report JSON and no extra full-body serialization. A deliberately insufficient quota case produces a bounded unavailable disposition with truthful execution outcome.
- Actual exec frames before spill discard; normal/MCP once-lowered structured payloads; current shipping Code Mode mount order/program value; explicit guest-source truncation; synthetic failures and background/child outputs. Full incoming MCP fields survive error presentation and typed image order survives supported model projection.
- At least100 child/job results with1MiB bodies and independently named revisions, bounded fan-in/pages, no full-string copies in notification/model metadata. This is retention/report evidence only, not wake/claim evidence.
- Blob/metadata/pin/fact issuance/receipt/install crash cuts, same-identity reconciliation, concurrent owner/ACL/GC controls, pinned expired content, cross-owner/path-forged refusals, index loss and explicit clear refusal. No reference before artifact commitment or deletion of publication-unknown content.
- Exact final response budgets with quotes/emoji/NUL, stale refs, mid-UTF8 offsets, deep JSON, source getter/toJSON once, range integrity/tamper, bounded page read work and zero tool/finalize replay.

No result size, quota, cache default or delivery guarantee changes through this planning document. R4A, semantic seed, child delivery and R6 cold-history/memory qualification remain unfinished until their own implementation and fresh review.
