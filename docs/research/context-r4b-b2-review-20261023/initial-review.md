## Issues

### Critical (Must Fix)

### Important (Should Fix)

1. **Preserve qualified bootstrap frames across ordinary event replacement.** `packages/session-persistence-jsonl/src/index.ts:45–46,224–237`.

   The new `assertPublicBootstrap` requires two physical frame lines for a nonempty semantic seed: the seed frame and completion frame. `replaceEvents` still validates the supplied event history and then writes the entire archive as one frame with a random ID. On a genuine B2 target, a successful replacement of the *identical* events therefore makes the next normal read and title update throw `SESSION_BOOTSTRAP_INCOMPLETE`. It also loses the original deterministic frame keys required for qualified receipt adoption. This violates preserved ordinary canonical-rewrite behavior and R-B-24 historical-frame identity. Existing `semantic-publication.test.ts:31` covers a literal B1 fixture without a retained bootstrap stage, so it misses the new fence interaction.

   Root's scoped real-backend probe reproduced a successful two-deterministic-frame → one-random-frame rewrite, followed by failed normal read/title update and separately blocked qualified resume. Preserve the exact immutable bootstrap frames and rewrite only an allowed later suffix, or provide another contract-preserving implementation that cannot acknowledge a replacement and leave the target unreadable. Add a maintained genuine-B2 replacement regression, including cold receipt adoption. Evidence: `task-2-probes.md`.

2. **Repeat the current source/Stop fence before each short-write continuation.** `packages/session-persistence-jsonl/src/backend/bootstrap-header.ts:78–90`.

   `continueFile` calls `before()` once before its asynchronous write loop, then issues every remaining `h.write` after awaited short writes without another guard. Thus a source change or Stop during the first partial write still permits the rest of that stage/header to be persisted. A later guard prevents the next phase, but does not protect the issued file's continuation. R-B-21 explicitly requires current guarded continuation and a header latch that can check more than once across awaits.

   Four root-requested real-file probes confirmed this on the reviewed source: after the first 11 bytes caused either staleness or abort, the stage received another 168 writes/1839 bytes, reaching its full 1850 bytes; the target header received another 71 writes/780 bytes, reaching its full 791 bytes. Same-stale resume correctly performed zero writes and fresh recovery succeeded, which isolates the missing check to the in-flight loop. Move the repeated issuing guard to each write boundary, retaining the original operation/partial bytes when it fails. Extend the maintained short-write cases at `test/bootstrap-physical.test.ts:238` to flip currentness/Stop during a write, rather than testing those properties only separately. Evidence: `task-2-probes.md`.

3. **Treat a matching publication artifact as retained uncertainty, not absence.** `packages/session-persistence-jsonl/src/backend/bootstrap-header.ts:53–62,93–105`; orchestration consequence at `packages/session-persistence/src/coordinator/bootstrap.ts:103–123,196–200`.

   `readBootstrapState` discovers `.publish` siblings, but uses the exact invocation's publication filename only to exclude it from `foreign`. If that publication file exists without the target or stage, the `!prefix && !stageBytes && !foreign` branch reports `absent`. Preparation also ignores that same-name `.publish` on the new-target path. The existing bytes are never checked for a valid matching original operation; their filename silently becomes sufficient to proceed around them. This contradicts R-B-21's requirement that unknown retained bytes cannot mean absence and that a filename alone does not establish operation identity. It also gives inspection an incorrect no-confirmation answer for visible uncertainty.

   The root-requested probe created only a literal 19-byte partial publication artifact at the invocation-derived path. This is a constructed retained-artifact negative, not a claim that the normal write sequence naturally produces that cut. Inspection returned `absent` with `needsConfirmation:false`; supplying a new-target payload then returned `ready` while leaving the original publication bytes ignored. Detect and classify the exact publication artifact explicitly, preserve uncertainty/unknown-manifest identity when its binding cannot be reconstructed, and validate every retained original artifact before any continuation. Add publication-only inspection and same-operation/foreign-byte refusal controls. Evidence: `task-2-probes.md`.

### Minor (Nice to Have)

4. **Reject non-enumerable DTO fields instead of silently dropping them.** `packages/session-persistence/src/coordinator/bootstrap-header.ts:14–17`; `packages/session-persistence/src/semantic-seed.ts:11–13`.

   The new record/wrapper checks use `Object.keys`/`Object.values` after `isStrictFactData`. That shared predicate rejects accessors, symbols, proxies and cycles, but intentionally permits non-enumerable data properties. Consequently a hidden unknown data field is accepted and disappears during canonical capture; a non-enumerable optional metadata field can likewise be read during validation and then omitted. The specified creation codec requires own enumerable data with exact keys, and existing `seedFields`/`seedData` already show the stricter descriptor policy. Check all own descriptors and enumeration status at these new boundaries and add small descriptor controls. This is a strict-input contract gap; the reviewed capture path does not turn the dropped fields into new storage authority.

5. **Capture the expected cleanup diagnostic in the maintained test.** Existing `packages/session-persistence-jsonl/test/fact-batch-journal.test.ts:609`; observed `.tmp/r4b-b2-20261023/stable-jsonl-suite.log:12–16`.

Supply/assert a diagnostic reporter for that fault case so the expected error is checked and successful qualification output stays clean; preserve the current committed receipt/no-rollback assertions.
