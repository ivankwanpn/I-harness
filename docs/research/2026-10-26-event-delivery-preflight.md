## Concrete current defects and exact publication timing

1. `service.ts:307–351` computes `parent-notify-SHA256(input.text + input.description)`. Same key with changed presentation can become a new input; two genuinely distinct results with equal presentation can collapse. Input identity must be derived from a canonical typed tuple, not concatenated presentation.
2. `service.ts:291–305` keeps `cancelledParents` only in memory; line735 clears it for a non-system human submission. There is no durable binding between a pre-Stop child and its launch generation. A late result after new human input can therefore pass the current gate. Restore cannot reconstruct that live set.
3. `subagent/index.ts:restoreTasksAndSweep` first restores mirrors, then task document, qualifies original retained results, classifies old attempts, and calls `notifDrain.drain()`. `assembly.ts:1441` awaits `subagent.ready` before assembly returns. At that point service `parentNotifyFor.admit` demands `assemblies.get(id) === owner()`; the new assembly is not yet published. The error row remains retryable, but an ordinary child has no later equivalent of team drain.
4. Exact service publication is `service.ts:675–699`: `assemblies.set(sessionId,assembly)` → delete mounting map → register pre-step hook → `lanes.set(...createSessionExecutor(...))` → execution subscription → attach hooks → `await assembly.drainParentNotifications?.()` → return. This recovery hook is correctly after publication/lane installation, but `assembly.ts:1662` implements it only as `for (teamHandles) handle.drainLeadMessages?.()`.
5. Ordinary `registerSubagent` only exposes `ready`, `flushPersistence`, `dispose` and tasks/projectors; it has no post-publication drain handle. Its terminal callback can still run during construction. Add an explicit lifecycle handoff to this same existing drain: restoration/qualification can finish pre-publication, but delivery admission/wake waits for the exact published recipient and lane. On publication, drain ordinary+team through their existing owners; do not install another ordinary drain alongside the old terminal/restore path.
6. A receiver admission can survive while source ack or wake is lost. Current service scheduling sets are process-local and current source `woken` may suppress retries. After publication, reconcile committed receiver pending eligible deliveries independently of source woken hints, using one recipient scheduling drain. Install change subscription before initial reconciliation; use dirty/single-flight catch-up so a change during any await causes another pass.
7. CLI is a separate open gap: `apps/cli/src/run.ts:497–506` default `admit` invokes `lane.submit({tier:'inject',...})` without awaiting its returned `.admitted`; wake is a no-op. Its executor is created only at914–922, after assembly construction; there is no post-lane ordinary drain call. Do not count service qualification as CLI completion. The later CLI seam must preserve the same key/receipt and await actual admission; no parallel legacy/new path.
8. Gate delivery on the actual original committed end/source result and trigger the same source drain after that settlement. This is an observed source ordering, not a runtime-reproduced defect claim.

## D1a contract to freeze before dispatch

The following describes required semantics and proposed names, **not existing APIs**. Root should freeze exact DTO/event names and compatibility policy after B2 lands, rather than have implementation invent them independently.

**Stable key:** `{recipientSessionId,sourceNamespace,sourceId,resultRevision,deliveryKind:'subagent'}`. Namespace is the actual mounted durable registry/state identity, sourceId the original task identity, and revision the original retained terminal revision. Bind original launch/start proof and recipient branch/generation outside rendered content. Generation, presentation, transport, wake count and recipient incarnation are not additional key components that could remint a delivery.

**Recipient-owned facts:** one durable delivery generation open/close/fence and per-key disposition/admission under the existing managed journal writer. Keep source delegation's generation binding in an original committed launch record (or an explicitly versioned existing source document field if root chooses that location). Reuse `subagent/start`/`subagent/end` and original retained witness instead of copying result bytes. Do not assume a new field on these events is format-neutral. The receiver source/captured group must have the same original-observe/reconcile/retryAbsent discipline as ReceivedInputSource; do not expose generic fact append or a forgeable RPC/model capability.

**Generation rules:** first authorized real work opens/binds generation; ordinary completion, human send/followup and steering retain still-authorized background generation. Explicit user Stop synchronously fences admission/claim/scheduling, captures durable closure through its existing required writer, and reports/retains closure debt on failure. A later human turn opens a new generation; it cannot rebind older sources or clear the prior fence. Disposal revokes the exact live owner immediately and waits for owned drains; it must not silently be reclassified as a durable user Stop. Parent/session deletion, cancellation chain and scope retirement remain stronger. Uncertain closure blocks new work through the existing recovery barrier until original disposition reconciles.

The current public `SessionService.cancelRunning?(sessionId):{cancelled:boolean}` and its implementation are synchronous. `{cancelled:true}` can acknowledge a live stop request, not durable closure completion. Root must freeze how existing submit/close/recovery barriers await the original closure (and how errors are surfaced), or explicitly version an awaited Stop acknowledgment before claiming that stronger guarantee. Never silently advertise the existing return value as a persistence receipt. Controlled crash cuts must distinguish before closure issuance, issued-unknown and confirmed closure; no design can claim an unissued disk record survived a process cut.

**Eligibility is one fold/precondition:** source is qualified, target exact current recipient/branch, original generation open, not cancelled/suppressed/claimed, committed receiver admission, and current scope/lifetime. Use the same result for Inbox pending eligibility, idle scheduling, active step capture and later D4 observation. Recheck before commit after preparation awaits, not just when a service snapshot is read. Noneligible rows remain inspectable without becoming executable. A generic system input or copied inherited history cannot create eligibility. Preserve human and schedule behavior.

**Admission/claim:** proposed private `admitDelivery(trustedSource,presentation)` returns the original committed input id/disposition/durability only after actual receiver publication. Same key/rerender returns the original record without another admission or transformed payload. Same original uncertain capture retains its exact frozen DTO; changed presentation during uncertainty is not a second batch. A committed grouped promotion is consumption even if wake, model request, provider result or final save later fails. Never replay a consumed delivery to recover a failed model request.

**Wake:** repeatable scheduling hint derived from the committed eligible Inbox, not source ack or timeWoken. One recipient drain uses dirty/single-flight scheduling and the actual `submit(...,{admittedInputId})` lane. Both active-claimed-before-submit and duplicate hint races resolve as already consumed, without reporting a new product failure or sending another request. A persistent error leaves original pending/debt and may arm one bounded error-backoff retry; no healthy-success interval. Error retry cannot keep resending a failed/claimed input.

**Legacy/deferred disposition:** do not silently trust v1/v2 task rows or old admitted text as generation certificates. Root must choose one concrete compatibility path before dispatch. Recommended narrow choice: legacy unproved rows remain readable through real `get_task_output`/existing task result pages and cannot auto-wake; no deferred-adoption API is added in D1a. If root instead requires automatic legacy adoption, D1a must expand to a real explicit management/recovery entry naming the same key and current authorization, with cold controls. An exported unused resolve function does not meet that obligation. This packet does not claim full D2 legacy migration. Preserve all old results and mark unproved delivery honestly; never infer their suppression or consumed state from hidden text alone.
