## Artifact owner and confirmation policy

Use the proposed separate SeedDependencyTransferScope registered in the existing artifact owner, backed by its existing mutation chain/lease and private WeakMap. Data-only BootstrapDependencyRequest/Outcome remain the actual core contracts; context-output never imports persistence. Binding is exact operationId/manifestDigest/sourceSessionId/targetSessionId/targetDocumentId, with targetDocumentId equal to targetSessionId for this session bootstrap. Capture strict own data synchronously. This is a trusted host composition boundary, not a JavaScript sandbox or permission minted by parsed DTOs.

Distinguish source authorization for NEW publication from current target authority for PASSIVE original confirmation. confirm requires genuine source access to all root/member/catalog evidence, original transfer binding, caller current guard, and genuine current target project/source before every issued mutation and after waits. reconcile never grants/recreates pins and must not require a still-running original parent simply to confirm existing exact target publications. It verifies original immutable operation/catalog metadata, exact original transfer publications and genuine current target authority. Physical source-pin release and parent runtime closure are separate from policy; missing original artifact metadata or unavailable target authority still refuses. No copied header roots may substitute for broker authority.

The host capability therefore needs separately named source availability and target lifetime/current-scope access; a single ambiguous available() callback must not silently tie passive adoption to the parent's runtime. The implementation contract must freeze these function names and currentness capture after review of the completed host getter; no generic successful callback fixtures establish production authority.

## Existing immutable records and catalog closure

Keep the current pin/access/companion layout. Target pins keep the ORIGINAL artifact operationId/revision. Add a closed seedTransfer binding to new transfer pins, not a second ACL/index. A pre-existing target pin with another/missing transfer binding cannot be relabelled as this bootstrap receipt. New transferred companions are closed v2 with exact original catalogOwner/catalogOperationId/memberOperationId, target identity, sourceId/lowest ordinal, transfer operation/source session and manifest. Existing valid v1 readers remain compatible; transfer additionally checks actual catalog entries, since legacy witness shape alone does not prove ordinal/sourceId membership.

Reuse the accepted streaming catalog reader and no-clobber immutable metadata continuation/confirmation. Canonical-first witness is mandatory for repeated identical member refs: retain and fold every occurrence, publish one lowest-ordinal companion per existing singular key. Validate all aliases and original operations. Conflicting/noncanonical existing bytes are retained and refused. No arbitrary100-entry cap, whole-catalog materialization, member body reads, or new on-disk catalog index. Preserve explicitly bounded32768-byte pages/8192-byte entries and sourceId uniqueness bookkeeping that scales with count.

Nonempty closure uses the prior proposed start/root/entry/end canonical hash fold. Roots sort by canonicalJsonData(fullref), uses by canonicalJsonData(use); catalogs follow root order, entries follow actual ordinal including unavailable and duplicate-ref observations. Each root folds original owner; retained entries fold original member owner/operation; final counts distinguish roots/catalogs/all entries/retained occurrences. Binding includes workspace, operation, target document/session, source session and manifest. No policy result, physical pending filename, current host revision or completion record enters the digest. Empty closure remains the accepted literal and does not invoke the dependency port. Independent literal vectors must cover ordering, unavailable entries and repeated refs.

## Pre-ready host ordering — separate host phase needed

An artifact-only adapter cannot bind zero-artifact targets before READY. Do not fake an artifact, mutate assertCurrent, or invoke the dependency port for an empty set. A narrow optional host target-preparation port on BootstrapGuards is the preferred extension to the SAME coordinator bootstrap owner: once the original header is confirmed, and outside its session lane, confirm the actual host target association before dependencies/seed/completion; on adoption use passive reconciliation before READY. Generic storage users without project ownership can omit the port; actual Gateway callers must provide it. Outcomes are host phase confirmation/blocked facts, never a new bootstrap receipt or execution authority.

The host port captures the original logical operation's intended project before initial issuance. It proves target identity with actual coordinator.inspectBootstrap(full original invocation) plus manifest, uses the existing broker serial/document readback/management admission, and cannot call ordinary target profile while incomplete. It must not recapture a different current source project on retry. Caller-owned operation intent or already exact saved target binding must supply recoverable intent; absence means blocked/payload-required rather than guessing. Exact port names/outcomes, requestDigest binding to project intent and cold retry restoration still need freezing with Task4 actual caller ownership, before dispatching that implementation. No new persistent authority catalog or distributed CAS claim.

Next implementation can complete artifact transfer against genuine injected host access, while broker pre-ready phase is a separately owned dependent slice. Full Task3 acceptance requires the genuine host adapter and actual policy tests; artifact unit callbacks alone are not sufficient. The original fork RED stays open until Task4 cutover.
