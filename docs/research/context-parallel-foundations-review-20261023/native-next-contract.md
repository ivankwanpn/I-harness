## 2. One current completed-component owner

- `conversation/validation.ts::ConversationValidationIndex.history()` delegates to `history/index.ts` and `history/replacements.ts::projectHistory`. This is the owner of visibility, rewind, replacement and monotone source consumption.
- `conversation/seed-selection.ts::selectSeedHistory` currently constructs a semantic-source validation index itself, then uses `seedSourceIntervals` / `history/intervals.ts::closeSourceIntervals`, complete-unit predicates and the safe input partition. Factor that existing selection body to accept an already-owned index/history. Both normal semantic export and the live component resolver use that body. Do not copy its refs/closure algorithm into core-agent or a second native selector.
- `conversation/render-items.ts::renderConversationItems` consumes selected recipes without owning grouping. `seed-capture.ts::captureSeedSelection` and `payload.ts` own one-capture selected payload validation and call/result/media mapping. Reuse these within core-session; never cross-import private files from core-agent.

Proposed normal readonly cooperation entry in core-session (not an authority constructor):

```ts
readCurrentConversationComponent(view: SessionView, ref: ConversationItemRef):
  | {kind:'unavailable'}
  | {kind:'current'; component: CurrentConversationComponent};
interface CurrentConversationComponent {
  readonly representative: ConversationItemRef;
  readonly members: readonly ConversationItemRef[];
  readonly unitDigest: Digest;
  readonly contentDigest: Digest;
  readonly messages: readonly LLMMessage[];
  readonly accepted: readonly {
    acceptance: ExchangeAcceptedEvent;
    assistant: SessionEventView; // exact assistant/message object
    calls: readonly SessionEventView[]; // exact ordered tool/call objects
  }[];
  readonly inherited: readonly {group: object; items: readonly object[]}[];
  isCurrent(): boolean;
}
```

The implementation uses a private view-to-existing-index reader reference for managed views, populated by `managedSessionState`; this is an association to the existing owner, not another index or archive. It validates readiness and exact view/header/format/index installation. Standalone reads may use only the actual current `conversationIndexes` entry and its owner checks; no cache means unavailable, not a new index reconstructed for native authority. Ordinary seed export on arbitrary/cold views retains its existing observation-only path. The returned component is observation data; its shape never authenticates an assistant. Only the execution owner's private accepted-object maps can do that.

Exact component relation: run the shared selector at `selection:{kind:'all'}` against current effective history, before payload capture; find the sole selected complete interval containing an item whose `historyItemRef` equals the requested ref. Any member ref addresses the same interval and digest; representative is its first member. All members must be addressable. Partial interval, duplicate/ambiguous ref, failed/open/unresolved/legacy-fragment, unknown/missing result, incomplete media companion or omitted interval is unavailable. Use existing `physicalUnitState` / `exchangeCompletion`, including receivedResults; do not infer completeness from end, result existence, or tool success. A recorded error/not-dispatched result can close history when the shared owner says so; an unknown result cannot.

The root host's all/completed/N selection must be matched to these complete intervals through the same selector, retaining exact descriptor membership in memory before seed capture. A requested ref plus digest cannot authorize arbitrary seed JSON. `lookup(view,ref,digest)` means this exact current full component; it cannot mean an undocumented partial group or historical atSeq projection. A completed/N export is native-eligible only if its selected interval is also the same currently effective complete component. Historical-only content remains portable/unverified.

### Concrete digest preimages

Use existing `seedHash` semantics: SHA256 of UTF-8 `domain + '\0' + canonicalJsonData(preimage)`. Optional absent properties are omitted; present arrays preserve order; addresses are `{seq,part}`, never owner-string parsing. No functions, object IDs, undefined values, receipts, credentials or runtime tuples enter hashes. Factor helpers inside the existing seed capture/selection owner rather than reimplementing mappings downstream.

1. `assistantDigest = H('ih.native-source.assistant.v1', {version:1, assistant:{text, thinkingBlocks?, providerContinuation?}, calls:[{callId,name,args}, ...]})`. Values are exactly the installed assistant slots and accepted callSeqs order; include empty text, original native order/bytes and complete args. Never hash the whole step/event archive. The weak key and exact acceptance fields separately bind which event/attempt this digest describes.
2. `messageDigest = H('ih.native-source.message.v1', message)` over the exact pre-lowering LLMMessage, including role/content/toolCallId/isError/toolCalls/thinkingBlocks/providerContinuation and every image descriptor/base64. This will be the message digest consumed by NativeUnitPlan; adapter projectionDigest remains its distinct final-lowering report.
3. `contentDigest = H('ih.native-source.component-content.v1', {version:1, items:[{kind, messages:[messageDigest,...], calls?, results?, input?},...]})`. Calls are the shared capture owner's `{id,name,assistantMessage,call,result,outcome}` ordinal mappings. Results contain `{kind,message,media,isError?}` plus, for envelope results, exact `execution`, `sourceRetention` and `dependencies`; replace artifact table ordinals by their full seven-field ManagedArtifactRef and include catalog count/use kind. Input contains `media` and component-local raw/derived input relationships when present. Translate every cross-item/message relationship to component-local ordinals, not target seq/origin slots. This helper must consume the same captured selected SeedItem metadata produced by seed-capture; do not write another result-envelope projector. Source addresses, rebased turn extents, provenance-origin numbering and `sourceAcceptance` are deliberately excluded from contentDigest because they change on legitimate import. They are bound separately below. No artifact body/catalog enumeration or hidden output read is permitted.
4. `unitDigest = H('ih.native-source.current-component.v1', {version:1, contentDigest, members:[{ref,extent,unit?,sources,evidence,recipes,acceptances},...]})`. `unit` is `{source:{seq,part},state}` when present; sources/evidence use shared coverage order; recipes are `{kind,index?,item?,calls?}` translated from archive indexes to exact seq addresses. Acceptance entries are `{seq,version,exchangeId,actionId,attemptId,stepStartSeq,assistantSeq,callSeqs}` for every actual assistant recipe, not only `item.step.acceptance`. For seed recipes use `{groupSeq,itemOrdinal}` and exact installed group/item identity outside the preimage. Include selected input admission/media/prune-source coordinates and dependency metadata via the shared capture result. Member order is effective projection order. Extent is the unrebased source extent. No global event count, whole seed digest, whole projection digest or unrelated component enters unitDigest.

For every assistant recipe, map the assistant/call addresses through the shared history owner's acceptance metadata (available in history facts / legacy step acceptance), then return **original** events at those coordinates. An item may contain several assistant recipes; checking only its first physical step is insufficient. An unpaired/legacy assistant inside an otherwise complete component makes native proof unavailable, including assistants with no native block. Inputs and summaries remain observation bytes, never fabricated accepted assistants.

### Currentness and payload-read bound

A proof retains exact view, original accepted objects, component member addresses, unitDigest/contentDigest and selected result/media/seed-group object references. Its guard synchronously re-resolves through the same owner; checks original live scope and terminal evidence; verifies all current original references and digests; requires unchanged ordered membership, closure and data. Changed calls/results/media, replacement/summary/reset consumption, rewind exclusion, selected content change or different inherited group rejects. Unrelated appended work may leave an older component current if all these comparisons still match; changing only the global event count is not a semantic mismatch. Scope close is monotone and cannot recover through equal data.

For immutable managed events, caches may reuse selected payload hashes only while the same original objects and selected metadata remain current; structural owner resolution still runs. Mutable standalone objects require selected-slot recapture/digest checks and owner integrity checks; no blind revision cache. A conservative first tranche should return unverified for mutable/unattestable standalone sources, rather than freezing caller-owned events or trusting stale cached metadata. Root must explicitly choose this bounded limitation or fund standalone immutable fact publication in its existing owner before claiming all Task5 source controls complete.

No native lookup invokes `captureContextSnapshot`, `projectConversation` over all rendered history, whole-seed export for a single ref, JSONL serialization, or whole-history hashing. Descriptor/metadata traversal remains allowed. Render only the selected component after closure. `projectToolResult` already substitutes pruned content and retains media; hash the effective substitute/media, not the omitted output. Result digest changes after prune even with the same result object. The 100MiB consumed source oracle must instrument payload access, not just compare final request size.

The outgoing host captures shared selected components and original proofs before awaits. A nested lookup recomputes the target's complete selected component using shared history, requires its contentDigest and member/message/result/media correspondence equal the original captured group, then creates a private forwarding proof bound to **target** unitDigest whose guard delegates to unchanged original proof + originalUnitDigest and also checks current target scope/component. No new local accepted evidence is minted for `inherited-observation`. A further fork forwards this same origin chain; no reading origins JSON as authority and no unbounded global registry. Reject partial groups, missing mapping for any required assistant, reordered/mutated media/calls/results, closed intermediate or original scope.
