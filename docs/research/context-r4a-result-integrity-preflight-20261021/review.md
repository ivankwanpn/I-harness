## Actionable plan amendments

### 1. Tie the cold receipt to the operation observation that was checked

The draft correctly identifies unproved lookup confinement/ref-validation risk, but its static corruption matrix should explicitly cover the **two actual operation reads**. At inspection, `artifact/ownership.ts:182–186` reads operation.json, checks only that observation's owner.operationId, then calls `reconcileArtifact(target)`. `artifact/recovery.ts:32–39` independently reopens operation.json and chooses the disposition/ref from the second observation. The workspace fence serializes cooperating store methods; it does not make a fixture replacement between those native reads impossible.

Add one held native metadata-I/O control after a genuine original cold-lookup baseline: distinguish which operation observation the gate checks and which one supplies the receipt; replace only the disposable fixture record at the controlled seam. Check that the returned commitment cannot belong to another operation/ref/directory. Calibrate the observer on both metadata opens and retain the exact read/replacement sequence. This is an unexecuted source hypothesis, not evidence that the race succeeds.

The pre-repair report to root should name both the static and held-read outcomes and the minimal original-owner correction. Do not qualify a change that validates only the first record while the second remains an independent source of the receipt. A single validated original observation or validation of the actual returned observation may be sufficient; do not presume a new journal/schema/authority. Record the actual bounded metadata count rather than requiring one open of the current two-read implementation.

The cold oracle also needs a small explicit phase table before RED: authentic capturing may have no manifest/ref; authentic staged stays recovery-required; authentic refused can have no body/index/manifest after writer cleanup; authentic committed must describe its exact original immutable identity. Root should settle whether the cold committed contract requires the on-disk manifest, the embedded committed manifest, or both before asserting a new missing-manifest disposition. None of these storage dispositions establishes a current pin, read ACL, F1 publication, or execution success. The draft already preserves those authority boundaries; retain them in each assertion.

### 2. Make manifest/codec corruption oracles semantic and discriminating

Draft line54 says “field encoding” mutations must reject. Define those mutations concretely before implementing assertions. Current `manifest.ts:7–21` computes revision from its canonical serializer after bounded JSON parsing and checks decoded field order/values; it does not hash raw on-disk JSON bytes. Whitespace or an equivalent JSON string escape can change physical file bytes without changing canonical manifest identity. An extra/renamed key, wrong type/value/order, invalid JSON, truncation, or over-budget file is a different control. Do not turn equivalent JSON spelling into an assumed corruption RED or add a global byte-canonical JSON validator without an explicit contract decision from root. Exact writer-output bytes remain a valid independent positive vector.

Likewise, malformed **UTF-8** is a valid text/json decoder control, while syntactically invalid JSON encoded as valid UTF-8 is not automatically a result-page decoder failure: this reader pages the encoded JSON text and does not parse a complete JSON document per range. In the inspected code, fatal text TextDecoder errors map to the public bounded `unavailable` reason; exec record decode errors are wrapped as `corrupt` (`reader.ts`, `result-page.ts`, `exec-reader.ts`). Assert truthful refusal/no replacement text and the actual approved reason contract, rather than requiring identical reasons across these separate paths.

Keep the draft's authentic low-level sink approach: commit the malformed literal codec body so its actual body/index/manifest/ref agree, retire the writer, and prove the intended reader reached decode after valid rooted verification. Stale proof bytes only test integrity refusal. Header literal is exactly nine bytes, `IHEXEC01` followed by LF; avoid a fixture containing backslash+n. No repair, UTF-8 replacement, or encoder replay is allowed.

### 3. Specify deadlock-free held-read scheduling at the actual owner

Draft line58 permits held I/O plus a current-policy change but omits the scheduling restriction already stated in witness design line80. A store read holds `ownership.mutate`; another grant/release/deletion routed through the same store queue cannot complete while the read is held. Gateway `session-management-fence.ts:29–43` drains admitted readers before management runs. Awaiting a draining archive/delete/close/exclusive call before releasing the reader would test a fixture deadlock.

Write the schedule in the plan: start the read, await the calibrated native hold, initiate the real revocation/fence action, observe its actual admission/blocked state, release held I/O in a guaranteed finally path, then join both read and management. A direct policy owner that does not drain can settle before release; name that distinct seam. Use actual broker revocation or the actual Gateway fence when qualifying those paths. A raw coordinator metadata update is a separately labeled host-policy probe, not the complete Gateway management route. A companion/body replacement during the hold must be an explicitly accounted fixture filesystem mutation, not an awaited queued store method.

Require no returned page for a concrete change still in force. Do not demand zero touched bytes after I/O began or detection of an entire revoke-and-restore ABA interval. Reuse the active unit's accepted rewind/archive controls if they already discriminate this behavior.

### 4. Keep the transport oracle and accepted requirement IDs precise

The current model-tool adapter deliberately clamps integer maxBytes above32768 and maps native legacy offset to a typed cursor; the typed shared parser/SDK path rejects those invalid typed queries (`tools.ts:61–64`, `result-page.ts`). Existing `context-output/test/result-page.test.ts` asserts this distinction. For each malformed-input row, specify whether it targets that compatibility adapter, the typed parser/RPC, or the trusted service port. Do not demand the same rejection for a model-tool compatibility input and an invalid typed SDK query. Malformed viaCatalog semantics and a v1-only host should retain the accepted witness unit's distinct preflight boundary after rebase.

The draft calls this “approved R4A A5.” The original plan's acceptance matrix actually names A5 “durable pins” and A6 “bounded integrity” (lines351–352). Root can retain the current work-unit sequencing/name, but its handback should map bounded integrity clauses to that original requirement and explicitly leave the 100MiB/scale and packaged qualification open. This is an evidence-label correction, not a request to add A6 scale or broaden the unit.

## Confirmed sound portions of the draft

The independent hash construction matches the approved contract and current `artifact/index.ts`: domain00 + u64be ordinal + u64be actual length + bytes for real leaves, domain02 + u64be ordinal for padding, domain01 + ordered child digests for branches. Header is64bytes with reserved zeros at20–23 and56–63; one-based node1 begins at64. Empty/65536/65537/131073 byte bodies correctly produce n/p/node counts1/1/1,1/1/1,2/2/3,3/4/7 and index sizes96/96/160/288. No wrong header-size, domain, or index-length expectation was found.

The future fixture must choose and record its exact literal byte recipe, codec/completeness and constants before invoking the product writer. Distinguish all chunks and the one-byte tails. Independently compare full expected index/manifest bytes and body digest/root/index digest/revision; checking only the returned revision against another product helper is insufficient. The retained empty regression has pinned revision/index SHA constants, but it corrupts the index before its page read; add an actual successful cold empty-page read if the four-shape positive suite is meant to cover every shape. A zero-length body performs no body data read but still verifies its real empty leaf.

The raw I/O bound is correct when applied to the reader's **requested verification interval** `min(remaining,maxBytes+3)`, not merely the shorter text eventually returned after JSON-budget shrinking. At most two65536-byte chunks intersect that interval. For a nonempty body with k touched chunks and tree depth d, current proof data is64byte header +32byte root + k*(32byte leaf + d*32byte siblings); a final body chunk may be shorter. The empty-body special case reads header64 + root32 + empty-leaf32 bytes from its96byte index, including the repeated root/leaf node; count128 actual bytes rather than deduplicating offsets. Record every actual native read, including retries caused by short reads; distinguish requested lengths, successful bytes and offsets. Do not deduplicate repeated reads to make an exec page appear cheaper. Exec header, verified preceding LF, bounded45056-byte record windows and repeated rooted callbacks remain separately accounted costs. Positive calibration must observe actual FileHandle reads, not just the existing open-count spy.

Untouched body corruption need not fail an unrelated range. A required sibling corruption does affect that range's proof. Same-length chunk swaps need distinguishable original bytes, and a public forged ref rejected at operation identity does not reach the manifest/proof owner. These distinctions in the draft are correct.

The proposed witness scope matches the WIP design: one selected8192byte closed companion, exact member/catalog refs and real pins, no catalog body/index scan to infer membership, no missing-witness reconstruction, and pre/post current-policy checks. Member pin.operationId is the frame operation; companion.catalogOperationId is the catalog operation. Native registry sourceId/ordinal are host-published semantic metadata, not independently derivable from captured session/project source. Do not promise cold detection of shape-valid coherent rewrites of every trusted record. Rebase this mapping only after the active unit is accepted.
