## 5 · 殘餘（寫出來，不是藏起來）

1. **拒答沒有自己的通道**：`content_filter`（Responses）、`SAFETY`／`RECITATION`（gemini）、`stop_reason: "refusal"`（anthropic）今天仍是「200 空成功」——本階段只保證它們**不掉進 `truncated`**；給它們一個通道要動 seam 的詞彙（產品決定）。
2. **沒有 catalog 家族**：`anthropic`／`openai`／`openai-compatible` 三個 family 不存在 ⇒ 內建 anthropic profile 的預設模型（`claude-3-5-sonnet-latest`，真實上限 8,192）沒有卡片 ⇒ 拿 `ANTHROPIC_MAX_TOKENS_FALLBACK`(128,000) ⇒ **仍然 400**（與今天相同，但不是修好）。**R5 之後，使用者自寫的上限不再受此影響**。
3. **legacy thinking 的 `budget_tokens` 必須小於 `max_tokens`**：使用者把上限設得比 legacy budget 小 ⇒ 400（reasoning 是 Ⅲ 的地盤）。
4. **openai-compatible 的殘餘 flush 仍缺 `tool_calls` 片段累積**（pre-existing）：**只在無邊界末幀出現的工具呼叫 delta 會被丟掉**——與 R12 同一個「幀邊界決定行為」的類。
5. **子代理拿不到上限**：`packages/subagent/src/child.ts` 建自己的 agent deps 時不傳 cap（**窗口在那裡也缺** ⇒ 不是本階段造成的不對稱）。
6. **proof gaps（具名，未補）**：T5 有一條測試（無上限時 route 的 `generationConfig` 原樣通過）**沒有記錄過的殺手**，且「request 的 cap 勝過 route 的 `generationConfig.maxOutputTokens`」沒有斷言；T7 有五條斷言同理（殺手一行就能寫，但沒量）。
7. **`SSEParseError` 不帶 `cause`**、`HeadlessResult.truncated?: boolean` 比其他兩個表面寬（且 R14 後 repo 內無生產讀者，是主機介面）——階段 Ⅰ／Ⅱ 的既有註記。
8. **引用腐**：`packages/diagnostics/test/record.test.ts:58` 引用的是 `packages/llm-gemini/src/index.ts` 的一個行號（洩漏訊息的來源行），該行號已漂移（本階段前就 stale，之後差更多）。**未修**（不在任何任務的可寫範圍內）。
