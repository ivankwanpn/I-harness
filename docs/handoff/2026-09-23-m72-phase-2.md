## 5 · 殘餘（寫出來，不是藏起來）

1. **拒答沒有自己的通道**：`content_filter`（Responses）、`SAFETY`／`RECITATION`（gemini）、`stop_reason: "refusal"`（anthropic）今天仍是「200 空成功」——本階段只保證它們**不掉進 `truncated`**；給它們一個通道要動 seam 的詞彙（產品決定）。
2. **anthropic 的 fallback 從不經過夾取**（終審 I1 改寫了這條的**成因**）：`ANTHROPIC_MAX_TOKENS_FALLBACK` 是在**轉接器裡**選的（那裡沒有窗口），而夾取只夾**鏈上解析出來的值** ⇒ 那個 128,000 **永遠沒被夾過**。可達的兩條路：(a) 沒有卡片、也沒有使用者上限的 anthropic route（內建 profile 的預設模型正是此例，真實上限 8,192）；(b) **本階段之前沒被任何人提到的一條**——**compaction summarizer 自己組請求**（`compaction/src/summarizer.ts:181-184`，不經 core-agent），而它**正因為上下文快滿才發出**，此刻 `input + 128000 > window` 最容易 400。**不是退化**（此前 anthropic 根本沒有 `max_tokens`，這些請求本來就是 400）⇒ 本階段**不改碼**；修法屬於「把常數移進鏈裡、讓它被同一條夾取處理」的層，與 reasoning 同一位擁有者（Ⅲ）。**這條的規則比「沒有卡片才會這樣」更寬，讀的時候不要被舊措辭誤導。**
3. **legacy thinking 的 `budget_tokens` 必須小於 `max_tokens`**：使用者把上限設得比 legacy budget 小 ⇒ 400（reasoning 是 Ⅲ 的地盤）。
4. **openai-compatible 的殘餘 flush 仍缺 `tool_calls` 片段累積**（pre-existing）：**只在無邊界末幀出現的工具呼叫 delta 會被丟掉**——與 R12 同一個「幀邊界決定行為」的類。
5. **子代理拿不到上限——有兩個站點**（終審 I2 補上第二個）：`packages/subagent/src/child.ts:270-317` **與** `packages/subagent/src/tools.ts:657-666`（後者是 **resume／rebuild 路徑** ⇒ 長壽命子代理每次重建都會再丟一次）。兩者都只留 `state.binding.client`（＋effort）去建自己的 agent deps——**窗口在那裡也缺** ⇒ 不是本階段造成的不對稱，且 cap 沒有窗口會毀掉夾取，所以本階段**不改碼**。⇒ **值鏈的完整性只對主要 session 成立**；下一階段若動這兩個檔，應把 `binding.contextWindow` 與 `binding.maxOutputTokens` **一起**往後傳。
6. **`maxTokensField` 只能改 settings.json**（終審 M8）：`provider set` 沒有這個開關（與 M61 的 `inputModalities` 同形狀 ⇒ 先例，不是退化），但這個開關的動機（新 OpenAI 模型拒絕 `max_tokens`）因此不易被發現——PR 要明說。
7. **兩件終審判為 latent 的事**：只有 `maxOutputTokens` 的卡片會被顯示成 `"no card"`（`models.ts`／`provider.ts` 以 `contextWindow` 為前提；四個出貨家族都同時有兩個欄位 ⇒ 今天無感）；openai-compatible 的兩個 frame 解析點仍未統一（R12 補了第二份而不是合併 ⇒ 建議下次動它時抽 `handleFrame`）。
6. **proof gaps（具名，未補）**：T5 有一條測試（無上限時 route 的 `generationConfig` 原樣通過）**沒有記錄過的殺手**，且「request 的 cap 勝過 route 的 `generationConfig.maxOutputTokens`」沒有斷言；T7 有五條斷言同理（殺手一行就能寫，但沒量）。
7. **`SSEParseError` 不帶 `cause`**、`HeadlessResult.truncated?: boolean` 比其他兩個表面寬（且 R14 後 repo 內無生產讀者，是主機介面）——階段 Ⅰ／Ⅱ 的既有註記。
