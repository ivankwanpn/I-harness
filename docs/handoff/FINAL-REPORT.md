## 1. What was asked

Implement the design **in the order it specifies**, with five steps: (1) per-call policy resolution with the event-scan cost **measured** and a cache decision that handles invalidation rather than assuming it; (2) one denial shape across shell and fs **plus** declaring the `sandbox_permissions`/`justification` schema arguments the marker text advertised but no schema declared; (3) terminal and fs-search; (4) complete the escalation ladder against a real approval service; (5) read isolation **last**, and only after answering what IH would actually hide.

Binding constraints: no production change without a test that failed first **and** a mutation proof; all §8 audit thresholds keep passing; push to `origin/m62` only; **record honestly anything the design does not answer**; and spec §5 is binding — no permission rule engine, no governance layer, no second LLM danger classifier.

## 3. The three deviations from the goal text, each with its reason

1. **Terminal: refuse per call, not "refuse to mount".** A mount-time rule cannot see a mid-session mode change — which is the hole the whole goal exists to close — and `opts.sandbox === undefined` means "the host requested no sandbox", so unmounting would silently strip the terminal from hosts that never asked for sandboxing.
2. **fs-search: no change, and the premise corrected too.** ripgrep has no file-writing flag, verified **behaviourally on the binary `fs-search` actually resolves** (`@vscode/ripgrep@1.18.0` → 15.0.0): `--replace` rewrites stdout while the file stays byte-identical, `--output` is unrecognised, and of 145 flags only `--files-without-match` matches `write|output|out`. The spec's premise ("`fs-search` must be routed onto the shell's exec path") was **already true** — both get the same `exec/service` instance — and the review corrected the spec's claim that it had been refuted: what was at stake was only the request's `sandbox` field, and confinement buys nothing there because `rg` cannot write. Spec §3.4 now states the mechanism.
3. **Read isolation: answered, not deferred.** IH has no input naming paths; a default list would be a guess at someone else's threat model shipped as a security claim.

## 6. Where the goal's constraints "keep all §8 thresholds passing" and "measure it" stand

Measured at the final commit `3e0e2536`, on a **clean tree** (the discipline the ledger earned the hard way — the checker reads the working tree, so a mid-edit run looks authoritative and is not): `pnpm -r typecheck` **exit 0, every package**; `check-thresholds.mjs` → **ALL THRESHOLDS PASS**; `verify-citations.mjs --all-problems` → **8678 resolved, 0 missing files, 51 problems**, of which exactly **3 are `BLANK_LINE`** (`compaction/src/config.ts:99`, `settings/src/index.ts:1269`, `settings/src/index.ts:918`) — **all three pre-existing, none this goal's debt**. The residual `BLANK_LINE` set is **three, not five or seven**: earlier counts of it were taken through the checker's `first 30` window, and one citation that used to be flagged (`fs/src/error.ts:35`) **stopped being blank** because this range moved content onto it.

**The full suite at `3e0e2536`: every package green except `session-executor`, whose only two failures are the known-red WSL-`bash` pair** (87 passed / 2 failed of 89). The four scope counts this range's tasks were reviewed against — sandbox 39, sandbox-policy 17, fs 73, shell 49 — all pass, and the two new/edited assembly suites (`sandbox-escalation` 5/5, `sandbox-terminal-refusal` 4/4) pass. **The `apps/cli` M12 pair, inherited as "known-red", passed on this run** — reported because it is newer information than the claim it replaces, and because "known-red" should shrink when it can, not persist by repetition.

**What that proves is narrower than it sounds:** every citation names an existing file at a line that is neither blank nor a pure comment — it does **not** mean each citation points at the right code, and **a shift onto a different non-blank line is invisible to the tool** (the ledger records a case: `fs/src/error.ts:35` went from blank to holding unrelated content while the checker stayed happy).

**The performance claim is withdrawn, and the withdrawal is the honest form of the answer.** Spec §7 originally published **0.056–0.125 ms** per resolve. Scope C could not reproduce it with anything in the repo: the repo's own MEASURE test printed **0.244 / 0.274 / 0.235 / 0.106 / 0.099 ms/call** across five clean runs (sometimes inside the range, sometimes above), while its own quiet harness gave 0.0245–0.0257 ms. So the published number was **one uncontrolled observation quoted to 0.001 ms**, and §7 now says so. **The decision survives**: the worst observation, 0.275 ms, is **0.55×** the 0.5 ms budget, so "no cache" is not falsified — only the attestation was. I also corrected my own mechanism claim: the cost is the **scan**, not the `slice` (measured at ~0.0013 ms).

**And the test that guards that claim is a ceiling, not a detector — measured, not assumed.** The bound was `perCall < 5` (10× the budget); the fix round tightened it to **2 ms** and then measured what the tightening buys: the case prints **0.087 ms/call** on a quiet run, and a **semantically identical 10×-scan mutation printed 1.002 ms/call** — so **a 10× regression passes both bounds**. 2 ms fires at roughly 20× quiet / 7× loaded. That is recorded in spec §7 and in the test's own comment, because a threshold test's detection power is itself a claim that must be measured.

**The "only known-red failures" claim is verified at the cause, not inherited.** The four red tests (`workspace-cwd` ×2, the `apps/cli` M12 pair) all shell out to `bash`, and on this host `bash` resolves to `C:\WINDOWS\system32\bash.exe` — WSL's bash — where `bash -c "node --version"` returns `node: command not found`, exit **127**, while the Windows `node --version` returns `v24.15.0`. The failures are a property of the WSL environment's PATH, reproducible in one command, and **not** a regression from any change in this range.

## 8. Process observations — the part worth carrying forward

The defects in this goal were overwhelmingly **not** in the code. They were in the *text about* the code, and in the instruments used to check it.

1. **A comment asserting a CURRENT fact about a component another task will change is a promise nothing checks.** **Nine** instances (the ledger said seven; two more were found later). The productive form of the rule: **the task that changes a component owns its comments** — and in every case the catch came from a later reader, never from the author of the change.
2. **Corrections edit the steps and leave the boilerplate.** Fourteen defects in this plan's task text had that shape: the Files list, the test sketch and the commit line still described the pre-correction task. Three separate corrections to one paragraph of the ladder plan were needed, and the third survivor was found by an implementer reading the plan against the redesign that contradicted it.
3. **A rule that cannot be EXPRESSED gets worked around, not obeyed.** `denialFor` could only change *which* mode a hint named, never suppress it — so the shell hand-built a denial literal to achieve "no guidance". Hence `escalationTarget: SandboxMode | null`, and hence the enforced check that a target must be strictly wider than the mode in force.
4. **A rule that is only exemplified fails on the next example.** `WIDER_MODES[mode][0]` was right for both surfaces that existed when it was written and wrong for the third: the terminal, which refuses in *every* confined mode. The fix was not a better default but a stated rule — "the narrowest mode in which THIS operation is permitted".
5. **"The type says so" is not evidence at a tool boundary.** `Tool<Args,Output>` erases `Output` at the registry: removing a field from a tool's output type leaves `tsc` exit 0 **and every test green**, verified twice.
6. **A test that covers a path is not a test that fails when the path breaks.** Two specimens, both found by the final review and both fixed: a test whose spy recorded a field's *value* (so it passed identically whether the key was omitted or passed as `undefined`) while its comment claimed that distinction was the contract; and a test that asserted an *advice string* instead of **performing the advised retry** — which is precisely how the fs surface shipped the terminal's "retry that cannot work" bug.
7. **When two measurements disagree, suspect the instrument first** — and note that the wrong number is always the one you were about to report. Seven instances in this session, all mine: a checker that skipped source-less nodes; a printer's 30-item cap that hid findings twice; a counter that returned 0 while work was intact; a two-package grep quoted repo-wide; a `-First 12` window treated as the end of the data; a case-insensitive matcher assumed case-sensitive; and a working-tree read while an agent was mid-edit. **Twice the fix was already written down and not made mechanical** — which is why the fixes now live in the tools (`--all-problems`, and a dirty-tree guard that refuses to look authoritative).
8. **A reviewer's finding is a claim like any other, and specificity is not evidence of verification.** One confident, specific, *false* reviewer finding was propagated into a brief and a live dispatch before I checked it; had the implementer obeyed, a ruled change would have shipped green and unpinned. Two of the final review's findings were false in the same way (`terminal/src/tool.ts:47` and "nine tools"), and both were caught by checking rather than by trusting.
9. **Unrun is unproven, and "only one test reddened" is weaker than "only one could".** A reviewer's vacuity check named a mutation nobody had run; running it reddened six tests. And when a mutation reddens exactly one test, the interesting question is whether the others *could* have.
10. **A red-first test can fail for the wrong reason and look like success.** Fix P1's first red run failed because an unrelated guard-approval prompt threw — the file's own header had warned about exactly that. The test was only valid after `approveAll: true`; **"it went red" is not evidence until you have read why**.
11. **A test's own bound is a claim about detection, and it can be measured.** The timing guard's tightening was itself verified by mutation — and the measurement showed a 10× regression still passes, which no amount of reasoning about the number would have told me.
12. **One model route means the final review cannot buy a stronger model.** The deployment exposes exactly one, so quality was substituted with **structure**: four disjoint scopes in fresh contexts, each required to re-derive claims from code. That substitution should be reported as structure, not as extra rigour.
