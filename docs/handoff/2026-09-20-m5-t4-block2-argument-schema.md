## 3. 這一塊的**負載軸承**：兩層的分工

| | 對未知關鍵字 | 對誰 |
|---|---|---|
| **值那一層** | **忽略** | **每一個工具，含 MCP** |
| **斷言那一層** | **拒絕** | **只有 IH 自己寫的** |

**⇒ 只移植值那一層，未知關鍵字會被**靜默忽略**。** 這是整個設計的單點。而它與 dsh 的關係是**兩個方向都不一樣**：

| | dsh 有、IH 沒有 | IH 有、dsh 沒有 |
|---|---|---|
| | `oneOf`、`const` | `minimum`、`maximum`、`maxItems`、**型別陣列** |

**⇒ 「照 dsh 抄」兩個方向都會錯。** 而**原樣移植 dsh 的斷言層會拒絕 IH 自己的兩個工具**（`subagent/src/tools.ts:77` 的型別陣列、`plan-mode/src/index.ts:25` 的 `properties: undefined`）。

**⇒ 而這一塊**沒有任何既有宣告需要遷移** —— 三個看起來要改的，兩個由子集涵蓋、第三個（`workflow/src/tool.ts:73` 的字串映射）由 **§3.6.1** 涵蓋。**

## 4. 這一塊**找到**的東西 —— 而它們都不是設計階段想到的

### 4.1 三個測試**一直在用畸形的參數**驅動 `write`

```
packages/session-executor/test/assembly.test.ts:793,986
apps/cli/test/guardian.test.ts:28
      ↓ 用 args: { path, content } 驅動真的 write 工具
packages/fs/src/index.ts:250   required: ["path","text"]   ← 它宣告的是 text
```

**⇒ 那些呼叫**一直都是畸形的**，而它們通過**只因為沒有任何東西在檢查**。而它們**到達了那個查詢 reviewer 的審批縫** ⇒ **那幾條測試一直在用一個畸形的呼叫測 guardian。**

**⇒ 而抓到它的是**把檢查接上去**這件事本身。** 而複審用突變量掉了「它們的主題還在不在」：**舊 fixture ＋ 現在的強制 ⇒ 紅；舊 fixture ＋ 關掉驗證 ⇒ 綠**（**「以前通過只因為沒人檢查」是量出來的**），而 `no-guardian` 突變**仍然讓它們紅** ⇒ **縫還在、它們仍然依賴那條縫。**

### 4.2 兩處**我寫的 rationale 事實上是錯的**

| 我寫的 | 量到的 |
|---|---|
| §3.3：**`-0` 不是 JSON 數字** | **`JSON.parse('{"n":-0}')` 產得出 `-0`。** 拒絕它是對的，**而理由錯了 —— 真正的理由是無損性：`JSON.stringify(-0)` 是 `"0"`** |
| §2.4：畸形呼叫的觀察者**「改用 `tools/pre-execute` 或 telemetry」** | 那條路上 **`pre-execute` 0 次、`post-execute` 0、`post-tool` 0、guards 0、telemetry 0 個事件** —— **唯一的人工痕跡是 session log 裡那筆合成 `tool/result`** |

**⇒ 兩處都更正了（引舊文再更正）。** 而它們的形狀是同一個：**一句我寫下的、聽起來對的解釋，而沒有人量過它。**

### 4.3 而 `e2e/` 不在 `pnpm -r --no-bail test` 裡

**⇒ 而 block ① 的爆炸半徑普查為什麼漏掉它**：**`e2e/` 不在那個指令裡。** 所以那個「9 條改寫、5 個套件」是一個**工作區套件**的數字，不是全 repo 的。

**⇒ 而處置不是「記下來」—— 是**讓它不可忘記**（§2 的那個指令）。** 因為**這一條分支在同一個形狀上中了兩次**：

| # | 裁定 | 代價若錯 |

## 7. 這一塊**沒有**做的

- **block ③（界）** —— 下一塊。**而它的第一件事已經被指名了**（見下面那一格）。
- **`outputSchema` 的強制** —— **零主體**（全樹含測試只有 1 處）。
- **接縫的錯誤旗標**（`is_error`）—— 五個適配器 × 五種協議，是另一個單元。
- **把 `e2e/` 變成不可能忘記** —— 這一塊加了一個指令（`pnpm verify:all`），**而它**不是一個 hook**。** 要它成為強制的是 **CI 或 git hook 的決定，在這一塊之上**。

### 🔴 而 block ③ **必須先處理的一件事**（終審的建議，一字不改地記在這裡）

> **If block ③ keys on `code === TOOL_FAILED` it silently bounds abort fills; if it keys on "an object with an `error` string" it bounds real tool outputs shaped like that.**
>
> **My recommendation: before block ③, add the one missing bit of the vocabulary the block already established — make both fills carry their code** … and have the spill predicate read the code, not the shape.

**⇒ 那兩個填補住在 `execute-tool-calls.ts` 的三處**（`:197` 軟、`:458` 本體失敗帶 `code`；**`:381` abort 不帶**）。**⇒ 在 block ③ 之前讓它們一致，否則那個界會用一個**猜**去決定什麼是合成失敗。**
