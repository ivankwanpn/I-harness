# I-harness — 接管指南（**而它為什麼不是 `CLAUDE.md`**）

> ## ⚠ 這份檔案**本來叫 `CLAUDE.md`、放在 repo 根目錄，而那會弄壞兩條測試 —— 這是量到的事實，不是顧慮
>
> **`packages/instructions/src/files.ts:7` 是生產程式碼**，它會**從工作區目錄載入 `AGENTS.md`／`CLAUDE.md` 並注入 session 的 instructions**（同一個目錄裡 `AGENTS.md` 優先）。
>
> **⇒ 在 repo 根目錄放一個 `CLAUDE.md`**不是寫文件** —— 它改變**每一個** session 的 system prompt。** 量到的後果：`packages/session-executor/test/service.test.ts` 的兩條 `createSessionService — real session queue projection (Task 11)` 當場紅（`expected [ Array(1) ] to deeply equal [ 'first' ]`，而實際收到的是**這份檔案的全文**）。**把檔案移出根目錄 ⇒ 那兩條立刻恢復（31/31）。**
>
> **⇒ 所以它留在這裡，而「要不要真的在根目錄放一份 `CLAUDE.md`」是一個**未決的產品決定**：**
> - **要**：新的 session **自動**讀得到下面這些約束。代價是**每一個 session 都多背這些 token**，而**那兩條測試要改成不依賴「prompt 只有我們送的東西」**（它們現在用 `seen` 當「什麼被執行了」的代理，而 `seen` 收到的是整個 prompt）。
> - **不要**：樹維持全綠，而新 session **要靠人告訴它讀哪裡**（那就讀 `docs/handoff/2026-09-20-queued-work.md` §0）。
>
> **而這一格本身就是這個 repo 的品質訊號的示範**：作者（我）假設了一個文件檔是惰性的，**而下游的量測（`pnpm verify:all`）當場證否。**

## 2. 三條不可協商

**① 引用會腐 —— 引用前先量。**
```bash
grep -n "<你引用的符號>" <檔案>
```
行號是**基準，不是事實**。**同一批改動裡既要引用、又要改被引用的檔案時：先寫符號，行號只在最後一次編輯之後量。**

**而計數一樣會腐。** 任何 `grep | wc -l` 的結果都要**連同範圍一起寫下來**，並在排工作前重量。（實例：一個「79 站點」被追出來是量於 `ede0850`，**而寫下它的下一筆提交就已經是 80**，此後長到 110。）

**② 不要 amend 任何已回報的提交。** 修錯**往前修**（新提交），並在提交訊息裡說明。

**③ 提交訊息不加任何 attribution trailer** —— 沒有 `Co-Authored-By`、沒有 generated-by、沒有任何「co-worker」。

## 3. 閘門只有一個

```bash
pnpm verify:all
```

它**先數母體再跑** —— 母體的定義是「**持有 `package.json` 且帶 `test` script 的 workspace 目錄**」（工作區是 `packages/*` ＋ `apps/*`；**2026-09-21 的讀數是 66 of 66** —— 而 `packages/` 底下有 **66 個目錄**，所以**這兩個 66 不是同一件事**，引用時說清楚你在數哪一個）。

**⚠ `pnpm -r --no-bail test` 單獨跑不是閘門** —— 它**在有紅的時候只跑一個前綴**（量到：66 個專案裡只回報 58，8 個從沒開始），所以單獨跑出來的「全綠」可能是假的。

## 4. 這個 repo 的品質訊號

**不是「文件一開始就對」，是「錯了會被下游量測抓到」。**

- **紅先測試 ＋ 變異證明**，不得動生產程式碼（roadmap §1.7）。
- **推送只到里程碑分支**；`main` 的合併時機由人決定。
- **沙箱設計 §5 的三條排除是約束，不是選單。**
- 這一整條分支上，**作者被下游量測更正過三十次以上** —— 每一次都是同一個缺陷：**一句陳述比 artifact 多宣稱**。**⇒ 寫下任何主張之前，先問「我量了嗎」。**
