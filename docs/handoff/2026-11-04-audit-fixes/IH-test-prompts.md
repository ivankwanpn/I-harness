# I-harness 全功能測試提示詞包

> 用法：在一個**全新空白資料夾**建立專案，按下面順序逐條貼上提示詞。
> 每一條都寫了「預期」與「通過標準」；建議邊測邊在最後的記錄表打勾。
> 提示詞以「意圖」描述，不依賴特定工具名稱——時間軸上顯示的工具名可能與文件不同，這是正常的。

---

## 0. 前置設定（只做一次）

1. 开一個空資料夾，例如 `D:\ih-test`（以下稱「測試專案」）。
2. IH →「專案 → 新增專案」→ 名稱 `IH Test`、資料夾指向它 → 儲存。
3. 「設定 → 模型與提供商」：確認至少一個可用的提供商與模型，並在會話輸入框上方選好模型。
4. 「設定 → 執行與權限」先設為：**工作區寫入** + **危險操作詢問**（後面 B4 會逐一改）。
5. 建議先開一個新會話，命名 `00-smoke`。

> 測試期間若出現審批提示，請按測試目的選擇允許／拒絕；每次選擇都記錄下來。

## A. 冒煙測試（先跑這 10 條，約 30 分鐘）

### A1 基本建立與讀回
```
列出目前資料夾的所有檔案（含隱藏檔），確認它是空的。然後建立 notes/hello.txt，內容是兩行：
hello IH
second line
建立後用工具讀回來，把實際內容貼給我。
```
**預期**：先 list（空）、再 write、再 read；內容與要求完全一致。
**通過**：檔案存在、內容逐字相同、助手有貼出讀回結果。

### A2 精準編輯
```
把 notes/hello.txt 的第二行改成 second line edited，其他內容不要動。改完顯示 diff 或前後內容。
```
**預期**：只改第二行；顯示變更。
**通過**：第一行未變、第二行正確、沒有多餘空白或換行變化。

### A3 執行命令
```
用 PowerShell 執行：Get-Location; $PSVersionTable.PSVersion.ToString(); 然後回報工作目錄與版本。
```
**預期**：命令在測試專案路徑執行，回傳版本。
**通過**：路徑正確、有 exit code 0、輸出可讀。

### A4 背景工作
```
在背景啟動一個 25 秒的命令：Start-Sleep -Seconds 25; Write-Output "background-done"。
先告訴我 job id，不要等它結束；然後用 job 輸出工具查一次狀態，等它完成後再查一次最終輸出。
```
**預期**：立即回傳 job id、狀態 running；完成後輸出 `background-done`。
**通過**：沒有阻塞 25 秒、最終輸出正確。

### A5 子代理
```
開一個子代理，讓它在 tests/ 下建立 a.txt、b.txt、c.txt 三個檔案（各一行），完成後回報每個檔案的路徑與內容。主代理不要自己寫檔。
```
**預期**：出現子代理活動、三個檔案由子代理建立、最終彙總。
**通過**：檔案存在、時間軸可看到子代理的工具呼叫。

### A6 審批（負面）
把權限改成 **唯讀**，然後：
```
在 workspace-write-only.txt 寫入 "should not exist"。
```
**預期**：被拒絕，檔案不存在。
**通過**：助手說明被權限阻擋、沒有建立檔案；切回工作區寫入後檔案仍不存在。

### A7 Context Mode（大輸出）
先在「設定 → 上下文與檢索」開啟 **Context Mode**，然後：
```
執行一個會產生約 200KB 文字的 PowerShell 命令（例如 1..20000 | % { "line $_" }），
不要直接把全部內容貼出來；告訴我輸出被保留到哪裡、預覽是什麼、以及如何用引用取得第 15000 行附近。
```
**預期**：工具輸出被保留為引用（reference），只顯示有界預覽；能依引用分段讀取。
**通過**：時間軸出現保留／引用；助手能取回指定區段且內容正確。

### A8 Rewind
```
在 rewind.txt 寫入 "version 1"。然後再改成 "version 2"。最後用 rewind 還原到「寫入 version 1 之後」的那個點，還原後讀出檔案內容。
```
**預期**：rewind 面板可選該回合；還原後內容為 `version 1`。
**通過**：檔案內容正確、面板顯示還原結果。

### A9 會話分叉
```
把目前會話分叉（fork）成一個新會話，在新會話裡問：這個會話的第一個使用者訊息是什麼？
```
**預期**：新會話保留分叉點以前的歷史；回答正確。
**通過**：分叉成功、歷史一致、原會話不受影響。

### A10 用量統計
```
（切到「設定 → 用量統計」）告訴我剛才這些回合總共用了多少 token、哪些模型、快取命中率是多少。
```
**預期**：頁面有紀錄；助手能讀到或引導你查看。
**通過**：數據非空、與剛才的操作大致相符。

## B. 完整測試

### B1 檔案與編輯

**B1-1 大量檔案建立**
```
在 fixtures/ 下建立 30 個 .txt，檔名 file-01.txt 到 file-30.txt，每個內容是 "id=<編號>\nkeyword=<A 或 B>\n"，編號 1..30，偶數用 A、奇數用 B。建立後列出檔案數量與前三個檔名。
```
**通過**：30 個檔案、內容規則正確、回報數量 30。

**B1-2 patch 編輯**
```
用 apply_patch 一次修改三個檔案：file-01.txt 的 id 改成 101、file-02.txt 的 keyword 改成 C、file-03.txt 末尾追加一行 note=patched。完成後逐一讀回。
```
**通過**：三個檔案各自正確、其他檔案未動。

**B1-3 大檔讀取（分頁）**
```
建立 big.txt，內容是 1..5000 行，每行 "row-<n>"。用分頁方式只讀第 4000 到 4020 行，不要一次讀完整檔。
```
**通過**：只取回指定區段、助手說明分頁方式、沒有整檔倒出。

**B1-4 二進位安全**
```
建立 blob.bin：前 16 bytes 是 0x00..0x0F，然後重複 0xFF 共 1024 bytes。用讀取工具確認它不會被當成文字解析而亂碼；回報檔案大小。
```
**通過**：大小 1040 bytes、助手不強行解碼或明確說明二進位處理方式。

**B1-5 路徑邊界（負面）**
```
嘗試把內容寫到 ../outside.txt 與 C:\Windows\Temp\ih-escape.txt，兩個都試，然後告訴我結果。
```
**通過**：兩者都被拒絕（工作區邊界），檔案不存在。

**B1-6 符號連結（進階）**
```
如果可行，建立一個指向 fixtures 的 junction/symlink，然後嘗試透過它寫入；如果被拒絕，說明原因。
```
**通過**：拒絕或明確的安全處理，不會無聲跟隨連結逃逸。

### B2 搜尋與檢索

**B2-1 檔名搜尋**
```
在目前專案搜尋所有檔名含 "file-1" 的檔案，列出結果。
```
**通過**：至少 file-10..file-19，且不含 file-2x。

**B2-2 內容搜尋**
```
搜尋內容含 "keyword=C" 的檔案，列出檔名與行號。
```
**通過**：命中 B1-2 改過的檔案，行號正確。

**B2-3 Code Context（需先在設定開啟並建索引）**
```
開啟 Code Context 並為本專案建立索引，完成後用混合／詞彙搜尋找出 "patched" 出現在哪些檔案。
```
**通過**：索引進度可見、搜尋結果正確；關閉索引後搜尋行为符合設定。

**B2-4 大型樹搜尋（可選）**
```
在 node_modules 不存在的空專案中，建立 200 個子目錄各放一個檔，然後搜尋其中一個唯一字串，回報耗時感受與是否被截斷。
```
**通過**：能完成、結果正確、有截斷提示（若有）。

### B3 Shell、終端、工作管理

**B3-1 退出碼**
```
執行 pwsh -NoProfile -Command "exit 7"，回報工具看到的 exit code 與 stderr。
```
**通過**：exit code 7、沒有被誤判為成功。

**B3-2 逾時**
```
執行 Start-Sleep -Seconds 999，但把工具逾時設短（若介面可設）或直接執行並在 30 秒後按停止，回報結果與是否留下殘留程序。
```
**通過**：停止後回合結束、沒有殘留 sleep 程序。

**B3-3 互動終端（PTY）**
```
開一個互動終端，執行 node -e "console.log('pty-ok')"（或 PowerShell 等價），把輸出貼回來；然後關閉終端。
```
**通過**：PTY 可互動、輸出正確、關閉後無殘留。

**B3-4 輸出截斷**
```
產生 5MB 的輸出的命令，確認工具回報截斷／保留位置，而不是把 5MB 全部塞進對話。
```
**通過**：有截斷標記或引用、對話沒有爆量。

**B3-5 編碼**
```
用 PowerShell 輸出中文與 emoji：Write-Output "測試 😀 完成"，確認工具顯示正確、不亂碼。
```
**通過**：中文與 emoji 正確。

### B4 權限與審批（逐一切換設定）

> 每小題都先改設定，再貼提示詞。

**B4-1 唯讀：允許讀、拒絕寫**
設定：唯讀 + 危險操作詢問
```
讀 notes/hello.txt，然後嘗試改它。
```
**通過**：讀成功、寫被拒。

**B4-2 工作區寫入：區內可寫、區外拒絕**
```
在區內建立 inside.txt，然後嘗試寫 ../outside2.txt。
```
**通過**：inside 成功、outside 被拒。

**B4-3 完整存取：可寫區外**
```
在系統 temp 目錄建立 ih-full-access.txt，寫入一行，然後刪除它。
```
**通過**：成功（這是預期行為，測完記得切回工作區寫入）。

**B4-4 審批模式：逐項詢問**
設定：工作區寫入 + 逐項詢問
```
建立 approval-ask.txt。
```
**通過**：出現審批提示；允許後才建立。

**B4-5 審批模式：危險操作**
```
連續執行三個命令：echo hi、Get-ChildItem、Remove-Item -Recurse -Force fixtures。
```
**預期**：前兩個不問、第三個詢問（危險）。
**通過**：只有破壞性命令跳審批；拒絕後 fixtures 仍在。

**B4-6 審批規則記住**
```
在上述審批中選「記住／always allow」，再執行一次同樣的危險命令，確認不再詢問（或依 UI 行為說明）。
```
**通過**：規則生效；可在設定中撤銷。

**B4-7 模型代審（delegate，若有）**
```
用 delegate 模式執行一個中等風險命令，觀察是否有代審紀錄與最終決定。
```
**通過**：有代審活動、決定可追溯。

執行產生 300KB 輸出的命令，然後用引用工具分別取前 100 行、後 100 行、以及包含 "ERROR" 的行（自行製造一行 ERROR）。

**B6-2 手動壓縮**

**B6-3 自動壓縮（長會話）**

**B6-4 超限保護**

若可設定，把 context window 調得很小，送一個超長輸入，確認有清楚的超限訊息而非靜默截斷。

**通過**：明確錯誤、可恢復。

**B8-4 週期提醒**

## E. 已知限制（不是 bug，別誤判）

- **排程最短 300 秒**；非 managed 會話可能只在下一次互動時觸發提醒。
- **Rewind 對衝突檔案仍會覆寫**（UI 會先警告），且不備份被覆寫的內容。
- **Hook 在 session sandbox 之外執行**；plugin 的 MCP server 隨 plugin 啟用而啟動，沒有額外的逐次審批。
- **Windows 版未簽章**，SmartScreen 會警告。
- **全域搜尋／索引**首次建立需要時間；大專案請耐心等索引完成。
- 某些工具（LSP、WSL、MCP、Skills、Hooks）需要外部安裝或設定，未設定時應顯示不可用而非崩潰。
