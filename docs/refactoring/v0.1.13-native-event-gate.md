## E8採用的接線方向

Windows Job completion messages只能作額外提示。真正的root handle退出後，查`JobObjectBasicProcessIdList`，對每個確實仍屬ownedJob的process取得`SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION` handle，經`IsProcessInJob`核對後等待其退出。退出事件再reconcilejobmembership，涵蓋後生descendant與PIDreuse界線。保持root／tree／I/O／release四個完成條件分離。

Linux使用專用supervisor/subreaper，使reaping不是IH所有其他process的全域副作用。SIGCHLDwakeupfd喚醒無timeoutselector，waitpid的WNOHANG只是排空已可回收狀態，不是計時循環。產品版仍需一般化descendantidentity與namespace／confinement，不可把fixture已知PID當完整實作。

成功idle不查狀態；一次性安全期限只適用取消／釋放／無法取得可靠觀察的失敗處理，不能給正常長時間retained工作強加fixture的整體10秒上限。

## 必須保留的產品整合 gate

- Windows robustmemberfallback和取消的組合尚未執行：取消早於rootexit、所有Jobmessages遺失下取消、outputoverflow/backpressure都要實測。
- failedcleanup必須持有未完成read的OVERLAPPED與handle直到ack；prototype的失敗退出路徑不代表這個產品保證已完成。
- PIDlist要能grow，不受fixture63個member限制；處理truncation、exitedbeforepin、PIDreuse、DACL/access、持续churn、nestedjobs與breakaway政策。
- restrictedtoken、私有pipe安全描述、inheritedhandle白名單、suspendedlaunch/jobassignment、PSEC／ConPTY／MSYSrelay不能繞過。
- Linux一般子孫探索、動態descendant、failurekill/reap、launchadmissionsealed、ownrelease都要補；WSL實際worker、bubblewrap、seccomp、namespaceteardown及transportclose另跑。
- macOS/Darwin沒有本次實機證據；不能把Linuxsubreaper套為POSIX通用結論。發布前對平台支援／nativepoll的說明必須逐項如實。
