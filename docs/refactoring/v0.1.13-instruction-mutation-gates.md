## A. Mixed instruction and code mutations

Ruling: reject an entire known batch/call before any mutation body if it changes a potentially applicable instruction candidate and mutates another overlapping target; also reject candidate mutations that can alter the rules governing another candidate mutation in the same operation. Return typed INSTRUCTIONS_REPLAN_REQUIRED with current fingerprint and a bounded split-required reason. Do not fabricate the not-yet-written snapshot, split/reorder work automatically, or replay original arguments. A standalone candidate change executes once under currently delivered rules; its real success is preserved, and the next provider request reads the resulting disk snapshot before fresh code mutation.

Overlap follows the HOST resolver's applicable source policy: selected narrower root/Git boundary, explicit globals, lexical scope and canonical aliases. It is not bare path ancestry. Globals affect only consumers of that global policy; unrelated roots and sources must not become instruction authority. Treat even currently shadowed candidates conservatively for mixed-operation rejection. Unknown overlap fails closed for mutation planning. A proven independent scope can retain its accepted work.

Why: current rolling prepare/dispatch and sequential patch hunks can write earlier targets before later source discovery. A model-authored rule file is not evidence that the request carried the post-write effective rule. Cost if wrong: conservative shadowed edits may be rejected, and recovery from one mixed batch costs two additional provider boundaries; proactive splitting costs one. Test both hunk orders, separate calls, same-path/ancestor candidate interactions, narrow/multiple roots and explicit globals before shipping.

## B. Precise race guarantee

Ruling: initial preflight rejection means zero mutation bodies for that batch. Once a relevant source invalidation/unavailability/revocation is observed, no further not-yet-entered affected native mutation boundary may proceed under the stale evidence. Lawfully completed earlier effects and accepted independent producers are retained and drained. This is not rollback, all-time zero historical effects, atomic filesystem consistency against unobserved external writers, or proof of model obedience.

Why: a source can change after earlier work or after a write/rename syscall has started; watchers and source epochs cannot retroactively prevent that I/O. Cost if wrong: users could misinterpret partial late replan as all-or-nothing editing. Mitigate with explicit applied/not-applied results, typed disposition preserved through patch catches, held-gate request/effect tests, and clear documented limits. No generic filesystem lock or polling fallback is authorized by this clarification.

## C. Pending native candidate writes

Ruling: add a narrow pending-write token/lease to the SAME I2/E7 source observation owner for known native instruction-candidate mutation. Announce pending/dirty before mutation I/O; settle and invalidate before exposing its result, including failed or partially effective writes. Other participating consumers cannot treat affected snapshots as reliable during that interval. Producer execution/cancellation authority stays with the native tool/cell owner; the source token is observation/reliability state, not a new execution registry.

A writer's self-write allowance is bounded to its own captured authorized operation; it must not waive sandbox checks, close/root revoke or independently observed source changes. Always release pending evidence through owned settlement/cleanup; retirement cannot silently strand it or falsely claim reliable state. Dirty or unavailable source handling may keep flagged last-known-good text, but relevant mutations require reliable evidence or explicit replan. A failed invalidation publication preserves the real filesystem result and makes the source unavailable/replan, never false success with clean stale authority. No second loader/cache/acknowledgment owner.

Relevant dependency evidence includes candidate absence/priority slots, applicable ancestors/globals and membership revisions, not only currently loaded file hashes. Each accepted call retains its applicable dependency view and originating request acknowledgment; a different Session/request seeing new text cannot acknowledge an old cell. A full snapshot changing in an unrelated proven-independent scope alone must not abort that accepted producer.

Why: success-only invalidation proves freshness after settlement but leaves a window where another Session can prepare from a known in-flight native write. Cost if wrong: extra source state can deadlock a writer against its own prepare or leak a pending lease. Gate with self-write allowance, overlapping two-consumer held writes, partial failure, close/revoke and exact release-once tests; return explicit unreliable/replan instead of inventing a complete snapshot or blocking unrelated scopes.

## Required implementation placement

- Capture frozen arguments/binding/schema/native normalized target plan once; metadata uses the registered tool receiver, actual body consumes the same plan. No arbitrary model JSON authority. Preserve existing ordered policy/guard/approval and body sandbox ladder.
- Whole-batch target preparation precedes mutation; dispatch and native write/rename/unlink boundaries recheck relevant evidence after awaits. Final synchronous check stays OUTSIDE validatePrepared's policyRefusal wrapper and adds no await between final authority validation and execute.
- Replan is a separate scheduler disposition: stop new admission, retain ordered results, drain accepted work, no shared abort signal solely for replan. Patch keeps its real applied paths and explicit replan rather than flattening it into ordinary filesystem failure.
- Code Mode latches host replan before any catchable result/success continuation, blocks queued/new calls and guest store completion, stops guest execution, retains outputs and joins accepted producers without invoking their cancellation path solely for replan. Existing policy/Stop/revoke/dispose cancellation remains stronger and separate. Closed-event/broker retirement/source completion adapters carry the disposition without claiming continuation can resume or replay.
- Read-only results remain inspectable. Shell coverage stays host-known cwd/explicit instructions_get; no static parser promise for arbitrary shell internals.

Future RED/GREEN matrix in investigation report is required input to I5: actual assembled registry/native filesystem/Code Mode and controlled provider request assertions, no fake RED from merely absent registration. I2/E7 must supply pending reliability and invalidation contract before consumers claim it. I3/I4 supply exact Session/request acknowledgment and owner cleanup. This is a dependency gate, not permission to implement feature semantics in S17 structural work.
