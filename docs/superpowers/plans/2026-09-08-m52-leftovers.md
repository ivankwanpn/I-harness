## L1：minimal `retain()` 與未提交行

- 現況：`packages/tui/src/minimal/commit.ts` 的 cursor 是「已提交的引擎行數」；`retain()`（loop 的 `maybeAutoRetain`，>2000 → 1500）從**前端**裁塊。
- 待判定場景：cursor > 新 total 時（提交落後量 > 被裁行數），re-anchor 會把**未提交的尾部行**一併視為已提交 → 那些行永不進 native scrollback。
- 要求：寫探針判定是否真能構造（cursor 落後且 retain 後 newTotal < cursor）；真則最小修（方向：讓引擎回報被裁行數，commit cursor 同步下移），假則 NOT-A-DEFECT。

## L2：B1 timeout 重武裝測試

- 現況：`packages/hooks/test/hooks.test.ts` 只斷言 attempts=2 與 pre/post 各 1；即使 retry 改成直呼 `tool.execute` 也會過。
- 要求：加一個**能區分**「retry 重新進入 cascade」與「直呼 tool body」的斷言（例如掛一個 spy cascade handler 計數，或讓工具記錄每次 attempt 的 `exec.abortSignal` 是新 controller）。不得改生產代碼。

## L3：repeat-guard reminder 的敘述順序

- 現況：`guard-repeat-tool` 在 `agent/post-tool` 追加 `user/message`（提醒），投影的 user/message 分支先 flush 工具塊 → 之後的 step 文字（assistant/message）落在提醒之後：`assistant("",toolCalls) → tool → user(reminder) → assistant(stepText)`。
- 期望（若可安全實現）：`assistant(stepText+toolCalls) → tool → user(reminder)`（文字屬於呼叫本身）。
- 要求：先判定最小改動是否安全（例如 mid-step 的 user/message 不立即 flush、或把提醒緩衝到 step 結束後發）；若需要改動投影的訊息緩衝語意（有 blast radius）→ **停下來報 BLOCKED** 並列選項，不要猜。
