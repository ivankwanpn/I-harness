# Desktop D2–D3 Implementation Plan（人機介入＋成果檢查前台）

**日期：**2026-09-26
**前置：**`docs/superpowers/plans/2026-09-25-desktop-d0-d1.md` 已完成（本地 commit `a62419e..86aec1e`）；後端宿主 `packages/desktop-gateway` 已實作、審查並以真工具執行驗證（`desktop-interaction`／`desktop-review`／`desktop-sandbox`）。本計畫只做 `packages/desktop` 的前端接線，不改 gateway、不改既有 SDK／CLI。
**Spec：**`docs/superpowers/specs/2026-09-25-desktop-workbench-design.md` §5.3（待人處理）、§8.1–8.2（後端契約）、§9 D2／D3 放行條件。

## 全局約束

- 只在 `D:\frontend-test`、分支 `codex/desktop-workbench` 工作；不推送、不開 PR、不動 `D:\I-harness-main`。
- 每個新能力都走既有 scoped IPC union；不加通用 passthrough，不讓 renderer 取得路徑以外的檔案系統能力。
- 能力不存在或請求失敗時一律顯示具體不可用原因，不造假成功、不樂觀標記已批准。

## Task D2：人機介入（審批／提問）

**Files：**`src/shared/bridge.ts`、`src/main/ipc.ts`、`src/main/sdk-runtime.ts`、`src/renderer/interaction/pending.ts`、`src/renderer/interaction/PendingPanel.tsx`、`src/renderer/shell/Workbench.tsx`、`src/renderer/app.tsx`、`test/interaction-runtime.test.ts`、`test/interaction-pending.test.ts`、`test/interaction-ui.test.tsx`。

**介面：**新增請求列 `desktop/interaction/pending`（`{workspaceId}` → `PendingInteraction[]`）與 `desktop/interaction/reply`（`{workspaceId, requestId, sessionId, decision}` → `{accepted:true}`）；`DesktopEvent` 的 method 增加 `desktop/interaction/request` 與 `desktop/interaction/closed`；純函式 `upsertPending` / `removePending` / `pendingForSession`。

1. 先寫紅燈測試：manager 轉發兩種 interaction notification；IPC 驗證 decision 形狀（缺 requestId／未知 kind → 拒絕）；列表 reducer 新增／移除／過濾；UI 顯示 reason、按「批准」帶 `approved:true`、提問送出答案、失敗保留項目並顯示錯誤。
2. 實作後跑 `pnpm --filter @i-harness/desktop test -- interaction`、`typecheck`、`build`。
3. Commit：`feat(desktop): surface approvals and questions`。

## Task D3：成果檢查（變更／diff／預覽）

**Files：**`src/shared/bridge.ts`、`src/main/ipc.ts`、`src/renderer/review/ReviewPane.tsx`、`src/renderer/shell/Workbench.tsx`、`src/renderer/app.tsx`、`test/review-runtime.test.ts`、`test/review-ui.test.tsx`。

**介面：**新增請求列 `desktop/review/changes`（`{workspaceId}`）、`desktop/review/diff`／`desktop/review/file`（`{workspaceId, path, maxBytes?}`）映射到 client 的 `desktop/review/*`；`ReviewPane` 只呈現宿主回報的狀態：`unavailable` 原因逐一分開（untracked／binary／deleted／no-diff／not-found／not-git-repo），`truncated` 必須明示。

1. 先寫紅燈測試：IPC 驗證（空 path、非正整數 maxBytes → 拒絕；合法 → 一次 client 呼叫）；UI（`listing unavailable` 顯示原因、binary／deleted 顯示不同訊息、文字 diff 渲染且截斷標記可見、點檔案觸發 diff 請求）。
2. 實作後跑 `pnpm --filter @i-harness/desktop test -- review`、`typecheck`、`build`。
3. Commit：`feat(desktop): add read-only result review`。

## 完成與放行

兩任務完成後：`pnpm --filter @i-harness/desktop test`、`typecheck`、`build` 全綠；跑一次 `pnpm verify:all`；真宿主 e2e 需證明審批回覆可讓被擋下的工具完成（沿用 gateway 的 fixture provider 手法）與 review 在真實 git 工作區回報變更。D4（打包、簽章、性能基線）本計畫不做。
