### BUG-2 [HIGH] Gemini 同名並行工具呼叫被折疊

- 位置：`packages/llm-gemini/src/index.ts:153-165`（`handleFunctionCall`）。
- 根因：`pendingCalls.find((c) => c.name === fc.name)` 按 name 去重；兩個同名不同 args 的 `functionCall` 併成一個，後者 args 覆蓋前者（`finalizeCalls` :175 的 `Object.assign({}, ...rawArgs)`）。
- 語意要求（依現行註釋 :135-140 的累積契約）：**帶 name 的 chunk 一律開新 pending call**（不再 find-by-name）；**只帶 args 的 chunk 續接最後一個 pending call**（既有行為保留）。單一呼叫的 name + 後續 args-only 分段累積語意不變。
- RED 測試（`packages/llm-gemini/test/gemini.test.ts`）：SSE 串流含 `parts=[{functionCall:{name:"get_weather",args:{city:"A"}}},{functionCall:{name:"get_weather",args:{city:"B"}}}]` → 必須 emit **兩個** `tool_call`，args 分別為 `{city:"A"}` / `{city:"B"}`（現行只 emit 一個 `{city:"B"}`）。再加一個 name + args-only 續接的測試，證明累積語意未被破壞。
- 不得改動其他 adapter 或 llm-seam。

### BUG-3 [HIGH] `removeProvider` 對 legacy-only provider 靜默 no-op

- 位置：`packages/provider-runtime/src/index.ts:171-182` × `packages/settings/src/index.ts`（legacy 讀投影 `normalizeLlmWithLegacy` :498 + `SettingsStore.legacyProviders` pin :663/:740/:789）。
- 根因：`removeProvider` 讀 `canonicalLlm(settings)`（**不含** legacy 投影），legacy-only 行 → `:174` 早 return；settings 讀端每次 reload 又把 legacy 行投影回來 → 永遠刪不掉。
- 修法（方向）：給 settings store 一個**窄的 legacy 行移除 API**（例如 `dropLegacyTuiProvider(id: string): Promise<void>`，實作 = 從 `legacyProviders` pin 中刪除該 id 並持久化；`legacyProviders` 全空時可清成 undefined），加入 `SettingsStoreSurface`；`provider-runtime.removeProvider` 在 canonical 行不存在時呼叫它（canonical 存在時照舊，並**同時**清 legacy 同名行，避免 reload 復活）。
- RED 測試：`packages/provider-runtime/test/runtime.test.ts` —— 用 raw settings.json 寫入 legacy-only `tui.providers.deepseek`（不寫 canonical）→ load → `removeProvider("deepseek")` → `directory()` 不再含 deepseek；**重載 settings 後仍不含**（這條是關鍵：證明不是靠記憶體投影）。另加 `packages/settings/test/*` 對新 API 的行為測試（移除存在/不存在 id、pin 空時清理、註釋保持寫入）。
- 不改 legacy 讀遷移語意（既有 migration 測試須保持綠）。

### BUG-5 [MED-HIGH] `windowedDiff` 純 append 產生幻影刪除（**範圍已修正**）

- 位置：`packages/text-diff/src/index.ts:87-136`（tail pair 等長 end-anchored 視窗）。
- **實測事實（controller 2026-09-08，m50 當前代碼）**：60000 行 + 10 行 append →
  `added: 10, deleted: 10, hunks: 2, truncated: true`。
  bug-hunt 報告寫的「~9990 刪 + ~9990 增」**不成立**；真實缺陷是**純 append 被記成 10 個幻影刪除**（before 尾窗起點 50000 vs after 尾窗起點 50010，等長視窗下前 10 行被判為刪除），亦即 M49 Task 9 已 ledger 的 deferred minor（有界於 Δ）。
- 語意要求：**純 append 不得產生 deletions；純截斷不得產生 additions**；尾窗內真實改動仍要正確回報；`truncated: true` 保持。
- 建議方向（實作者可擇優，但須在報告說明）：當兩側尾窗**絕對位置重疊**時，diff 交集區間 `[max(bStart,aStart), min(bEnd,aEnd))` 的**同絕對位置**內容，並把兩側各自的非交集餘量計為純刪/純增；行號沿用既有 offset 機制。
- RED 測試（`packages/text-diff/test/diff.test.ts`）：
  - 60000 + 10 append → `deleted: 0, added: 10`；
  - 60000 → 59990（純截斷）→ `added: 0, deleted: 10`；
  - 尾窗內真實改動（改 3 行）→ `added: 3, deleted: 3`；
  - 既有測試（含 `deleted ≤ 1000` 的界線測試）全部保持綠或**收緊**（收緊需說明）。
- 不改 `createTextDiff` 的公開形狀、不改 ≤2 MiB / ≤50k 行門檻、不換 diff 庫。
