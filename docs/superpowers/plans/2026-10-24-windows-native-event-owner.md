## Root rulings

- N2-01: implement the actual shipping native wrapper. The ACL runner's infinite kernel wait is already event based; rewriting that wait or its unused-in-IH direct pipe API is not a substitute for this task. Preserve ACL legacy's retainedTree:false and every existing capability refusal. N1 compatibility work stays separately visible, not silently counted complete.
- N2-02: retain current synchronous I/O and admit the specified bounded stop-only CancelSynchronousIo retries as cancellation handling within the existing absolute deadline. No retry timer exists for healthy readiness, root/tree status or thread completion. Preserve original explicit cancel/release retry behavior; do not restart work or silently extend normal job lifetime. An equivalent event/cancellation primitive must be proved before removing the race fallback. No ad-hoc CancelIoEx/OVERLAPPED/named-pipe migration.
- N2-03: actual callback/unregister, worker/thread exit, OS handle and buffer lifetime outrank reporting completion. Attempt independent cleanup while retaining dependent original resources after failure; do not free callback storage or turn deadline/incomplete into resourcesReleased. Use the existing lifecycle owner and finite same-owner retries, not a second executor/completion registry.
- N2-04: include the active MSYS bridge polling sites in this package scope. Direct pipe/ConPTY results and MSYS results are separate qualifications until both actually pass. No supported route or policy restriction may be removed to obtain a green result.
- N2-05: one writer owns native source, focused tests and generated assets/provenance. Freeze source and obtain an interim independent unsafe/lifetime review before full real qualification and asset acceptance. Correct findings with the same reviewer; final full-range review includes generated identity/qualification evidence. Do not ask the user for a redundant execution approval at these internal checkpoints.
- N2-06: use original build/qualification owners, fresh owned output paths, isolated configuration/workload fixtures and recorded process/resource cleanup. Never edit manifest/qualification hashes to bless stale binaries. Keep experimental/historical-one-host labels and expected unsupported cases honest. Source/body/raw evidence stays immutable between qualified runs.
- N2-07: no public process protocol/interface change, general decomposition, Session/product version change, provider requests, installed-user-profile changes, push/tag/release or non-Windows implementation. Shared consumers may receive focused tests, not concurrent product rewrites. A proven seam gap returns to root with its causal evidence.

## 3. Native wait and tree algorithm — normal and total advisory loss

1. Configure the original kill-on-close outer Job before launch. Optional Job IOCP association happens while Job is empty. IOCP thread blocks `GetQueuedCompletionStatus(INFINITE)`, coalesces a hint, and wakes Inbox; it never treats message PID/ACTIVE_PROCESS_ZERO as authoritative. Explicit `PostQueuedCompletionStatus` stop token ends and joins the IOCP thread before port/Job release.
2. After CreateProcessW succeeds, capture the **real root process handle** in `Running` and install a one-shot `RegisterWaitForSingleObject(INFINITE,WT_EXECUTEONLYONCE)` before ResumeThread. Registration failure keeps the original unresumed child owned and enters rollback, with TerminateProcess if Job assignment failed. Assignment still precedes user execution. An already signaled process invokes the same native completion path; no periodic zero-time wait.
3. Callback context is heap-stable and generation-bound. Callback only marks `signaled`; it cannot allocate unbounded messages, unwind across the extern-system boundary or wait for consumer capacity. Poison/failure is captured as a preallocated fatal slot and wakes the owner. Reactor reads GetExitCodeProcess once after signal (except MSYS public root, described below), records failure as unknown root when needed, and emits original root status exactly once. `started` ordering remains dispatch-owned: an immediate exit queued during resume is consumed after `started` is emitted, not from the callback.
4. On root exit, cancel/control, relevant Job hint, or a member exit, reconcile `JobObjectBasicProcessIdList` on the **exact owned Job**. Grow buffers for ERROR_MORE_DATA or assigned/listed mismatch using checked sizes up to the explicit memory bound; never accept partial population as emptiness. Nested Job membership is included. Seal helper launch/assignment admission using existing consumed-commit and ownership rules before considering zero final.
5. For every listed identity, open `SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION`, validate `IsProcessInJob(handle, exactJob)`, read creation time through GetProcessTimes, and retain the actual handle. Register its infinite one-shot exit wait. The handle and validated Job determine ownership; a PID, process group, advisory notification or fixture-known descendant never does. No unrelated handle is terminated.
6. Exit-before-open, departed/reused PID, a mismatched current process, or a signaled identity still lingering in a snapshot triggers bounded immediate catch-up, **32 rounds per causal reconciliation**, then explicit incomplete. Keep already pinned state and the failure cause. Never rearm an already observed identity as a new completion event merely to force another query. Access denied and unexpected API errors are explicit incomplete; existing independently pinned live member waits remain usable, and explicit release/cancel can retry.
7. With **every ordinary Job message dropped**, root wait starts reconciliation, then each pinned live member's exit is the guaranteed causal wake for the next complete snapshot. A live pinned member proves nonempty; descendants it creates are discovered when it exits. Children/grandchildren born after root exit therefore remain covered. If identities churn beyond the bounded reconciliation budget, no success is guessed and no healthy timer is installed.
8. Tree-empty is published once only after the required public root has been observed and a complete factual owned-Job snapshot is zero, with launch admission sealed. EOF does not authorize it. Final release joins observer registrations/threads; close of Job itself is not the tree ACK. Cancellation before root exit uses the same reliable root/member waits plus a factual immediate reconciliation; cancellation under total hint loss is a required test.
9. Native wait teardown occurs outside callbacks and locks: `UnregisterWaitEx(wait,INVALID_HANDLE_VALUE)` drains outstanding callbacks; only after it succeeds free callback context and close the waited handle. A once-only registration still needs this. Failed unregister/close retains the actual owner/token; stale slots cannot touch a new generation. An explicit cleanup retry operates on the same pending owner. Wait registration tokens are not CloseHandle handles.

API basis: infinite one-shot process/thread waits and mandatory unregister are supported by [Microsoft RegisterWaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-registerwaitforsingleobject); callback-drain ACK and the prohibition on self-blocking unregister are specified by [Microsoft UnregisterWaitEx](https://learn.microsoft.com/en-us/windows/win32/api/threadpoollegacyapiset/nf-threadpoollegacyapiset-unregisterwaitex). Ordinary Job notices are explicitly advisory and their PIDs need retained identity: [Job completion-port contract](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_associate_completion_port). Complete snapshot growth and child-Job inclusion follow [Job PID-list contract](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_process_id_list). Local pinned `windows-sys-0.61.2/src/Windows/Win32/System/{Threading,JobObjects,IO}/mod.rs` contains the referenced declarations; new callback behavior is still unexecuted.

For `complete-tree`, retain current root-bound termination at the root event. For `retain-tree`, natural root event never terminates descendants. Failed TerminateJobObject remains retryable independently of root observation, cancellation submission and already-sent ACK; preserve the existing native failure-injection control at `runner.rs:233–326`. Reattempt termination on explicit retry, causal membership/identity change, or classified stop-only failure backoff, never healthy samples.

## 4. Transport capacity, cancellation and final thread join

### Preserve existing synchronous I/O where it already supplies real completion

The actual transport currently uses anonymous/synchronous files, blocking Read/Write workers and **CancelSynchronousIo**, not overlapped reads. Blocking I/O on owned worker threads is already event waiting; replacing it with named pipes is not a prerequisite for zero healthy polling. Keep those endpoint/security/ConPTY constraints for the minimal N2 cut. Do not call CancelIoEx on the assumption that a current File owns an OVERLAPPED operation; there is none.

Replace `try_send+sleep` with a bounded frame queue guarded by one mutex plus `not_empty/not_full` conditions. Producer waits while full and not discard/closed; consumer pops under that mutex and notifies capacity; discard/close is set under the same mutex and notifies **all** blocked producers/consumer. Thus capacity becoming available or cancellation between predicate check and sleep cannot be lost. One native output reader per channel preserves byte order; no normal output is discarded.

Cancellation drains queued frames once under queue lock and accounts bytes once; a producer that still holds a not-enqueued frame counts it once when observing discard. Writer's in-progress frame counts conservatively on an interrupted/failed partial write, as current protocol permits. Preserve TS's separate local-discard accounting, native outputAbandoned flag, channels, output-end marker, and 1 MiB delivery queue. Do not double-count a frame across queue drain, producer and writer.

Replace input `recv_timeout` with blocking queue wait. `stop_input` closes public input admission under the same queue lock, drops/wakes the receiver and rejects pending request IDs exactly once. `EndInput` keeps existing ordering/idempotence; MSYS public success still waits its controller ACK. A private priority stop slot ensures `_owned-stop` is not retried by polling a full user input queue; control capacity changes wake the input worker directly. Preserve private-ID rejection and no unmatched public ACK for `_owned-stop`.

### Cancellation ACK and the synchronous I/O race

Each worker owns its synchronous file and active buffer for the entire native call. Track `{operation_sequence,stop_requested,in_call}` under a small operation gate. Once stopping, no new user operation can be admitted. Call CancelSynchronousIo on the **owned actual worker thread**, preserve native result, and await operation return/terminal worker slot plus actual thread exit. Cancellation success or ERROR_NOT_FOUND alone is never I/O settlement.

This distinction follows [Microsoft CancelSynchronousIo](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelsynchronousio): the call requests cancellation on a thread, does not await operation completion, and may lose a race to normal completion. An actual terminal result remains required.

There is a real check-to-call race: a worker can pass its stop gate but not yet enter WriteFile when cancellation finds no pending operation. Removing the old tick must not strand that write. This draft freezes a **stop-only retry/backoff**, not a healthy timer: retry targeted CancelSynchronousIo at 1, 2, 4, 8, 16, 32, 64, then 100 ms capped intervals only while that admitted operation lacks completion, bounded by the existing absolute 10 s cancellation deadline. Stop the backoff immediately on the native operation/thread completion event. Mark this separately in the timer census. It is never used to infer root/tree emptiness or read readiness. If implementation instead eliminates this race with a proven native primitive, review that equivalent before dropping this fallback.

If the writer elects to introduce overlapped I/O for eligible newly created endpoints, freeze it as a separate reviewed transport delta first: FILE_FLAG_OVERLAPPED at creation; stable pinned OVERLAPPED **and buffer** per operation; unique operation generation; immediate completion vs ERROR_IO_PENDING; actual result via event/IOCP; targeted CancelIoEx; normal completion, ERROR_OPERATION_ABORTED or other result ACK before reuse/free. ERROR_NOT_FOUND races are reconciled through the original operation. Keep endpoint ACL/peer/handle inheritance, ConPTY's required handle mode, existing private Node pipes and status framing intact. Merely changing a Rust type or calling CancelIoEx does not convert an inherited synchronous pipe. The minimal packet does not require this migration, and cannot claim a new CancelIoEx product pass.

See [Microsoft overlapped pipe I/O](https://learn.microsoft.com/en-us/windows/win32/ipc/synchronous-and-overlapped-input-and-output) for creation/operation requirements and [Microsoft CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex) for storage retention through completion. These API contracts support the ownership rule; E8a's pending-read ACK does not qualify current N2 synchronous transport or an unimplemented migration.

### Terminal worker slots and joins

Each started input/output/reader/console/control worker has a unique WorkerKey, retained JoinHandle and native thread-handle registration. Its epilogue stores final `Result`, retained files/handles and final accounting in its slot, then returns. An OS **thread-exit** wait wakes the reactor; a message sent just before return is not sufficient to join. Registration after thread start handles already-finished threads through the signaled native handle. No `JoinHandle::is_finished` remains in production settlement.

After actual exit, drain its final slot, retire its native wait, join that exact thread, and collect panic/close failures. Join all started workers even if one failed; never return at the first failed join. A thread that exits without a terminal slot is a failed worker, not an implicit success. Console close is one owned worker; ConPTY close may block while output drains, so it is started at factual tree completion and never blocks the reactor. IO settled requires every required worker's result/drain/actual-exit/join, all retained-handle transfers consumed, console closure and final output state; only then emit original `io-settled`.

Control reader is facade-owned, separately retired after final response/EOF; close its admission, wake blocked control-capacity waits, cancel its own pending synchronous read if necessary and join before helper normal return. Do not include open host control input in workload tree completion, and do not wait for host EOF before responding to an explicit release (TS ends stdin only after confirmed release). This prevents a release/EOF deadlock. The supported TS peer keeps status drained; broken status enters the same owned shutdown path.

## 5. MSYS relay cut — required for the existing MSYS route

Keep the original forkpty root, trusted relay vs nested workload Job, raw input bytes, ACK semantics, resize, exit-status decoding, installed-runtime identity binding and private output channel separation. Do not replace this route with ConPTY or advertise PSEC PTY.

Concrete bridge change:

1. Create parent-private MSYS wake pipe descriptors **after forkpty**, so the untrusted child never inherits them. Existing child still assigns itself to the exact inherited workload Job and closes private descriptors before exec (`bridge.c:141–153`). Add only the verified `pipe` ABI declaration to `api.h`; confirm against staged pinned SDK.
2. Start one blocking `waitpid(original_child,...,0)` reaper thread after fork. It owns that exact fork child, handles EINTR, decodes status once, writes the original `ROOT` line under status_lock and sets root-observed state, then writes a wake byte. No WNOHANG periodic call. Never reap other processes or signal a guessed group.
3. Output worker uses indefinite poll/read readiness for the single MSYS master; on terminal output it records ended then writes the parent wake descriptor. Main controller blocks on **control fd + internal wake fd** with `poll(...,-1)`, drains wake bytes, then evaluates cached root/output facts. No periodic sample of output.ended. Root may precede output EOF or vice versa without completion conflation.
4. Input worker keeps its current bounded eight-frame queue and capacity semantics. Waiting for an empty queue already uses a native event. For a pending master write, replace the 100 ms POLLOUT wait with indefinite poll on master writable **and an input-stop wake descriptor**; still write one byte after readiness to avoid the documented MSYS master-lock coupling (`bridge.c:101–115`). Stop/disconnect/root-terminal wakes this poll, prevents new delivery, and reports unresolved accepted input accurately. No ACK is sent for bytes merely queued.
5. All bridge state predicate/wake publication ordering must be locked/atomic: update state before writing wake; use parent-private nonblocking wake descriptors; coalesce wake bytes while a pending flag is set; main drains and clears/rechecks under the same lock to avoid a full wake pipe or lost transition. EAGAIN on a wake write preserves the pending predicate/readable wake; an actual closed/broken wake is a failed owner. No busy draining loop when the pipe is empty. Keep descriptors until every publishing worker has joined. Join reaper/output/input after their real terminal events; preserve the current deliberate TerminateProcess fallback when accepted input cannot be honestly joined/delivered after root/output completion (`:243–251`), with native outer ownership remaining authoritative.
6. Rust MSYS stop becomes transitions: submit private stop once (priority slot) -> await original ROOT -> terminate remaining nested workload Job for cancellation/complete-tree -> await outer relay/member exits. Retain the existing **absolute 2 s observer grace**; if no trustworthy ROOT/bridge completion, escalate to the outer Job once and report unknown root where appropriate. This is a requested-stop failure deadline, not a normal completion limit. Early cancel before READY/root assignment and all Job hints lost are required real cuts; outer Job membership/root wait remains the fallback authority.

Local SDK confirms pipe/waitpid/pthread_join declarations at `build/pty-msys-sdk/usr/include/sys/{unistd.h:180,wait.h:21}` and `pthread.h:180`; `sys/poll.h:33–43` provides poll ABI. The exact readiness/cancel behavior of indefinite MSYS master polling and wake coalescing is **not executed here**. If that controlled cut fails, MSYS zero-poll remains blocked; Rust-only successes may qualify their direct routes but not the full N2 claim. No silent supported-route removal.

## 6. Failure, retry and resource release ordering

Keep original `createExecutionLease` retry/historical-incomplete behavior (`packages/sandbox/src/execution-lease.ts:34–177`) and exec capture join (`packages/exec/src/capture/completion.ts:41–75`). No TS/native public schema change is required by the above internal notifications. Update protocol documentation for internal bounds/ACK details without inventing a version transition or assurance promotion.

Normal release order: root observed -> factual tree-empty -> worker I/O/EOF/accounting results and actual thread exit/join -> retire all process/thread/Job observer registrations and observer threads -> close retained endpoints/primary thread/process/Job handles and effective/MSYS image resources -> release workload Job and PSEC -> send `resourcesReleased:true`. Failed close or unregister preserves its actual handle/context/backing object and original error for later release retry. A previous false response remains historical even if a later response succeeds. Late duplicate release IDs retain existing TS retirement behavior.

Do not leave the old sleep-based Drop as the only cleanup owner. Centralize all post-launch failures, status/transport errors and EOF into the same explicit shutdown event loop with the existing one-shot 5 s fatal-drain bound. `?` must not drop a partially running owner with live callbacks. On a fatal deadline without ACK, never claim release: retain the entire unfinished native capsule (handles, contexts, buffers, threads and PSEC), not just PSEC, until helper process exit tears down the process. Prevent ordinary RAII from closing a handle under a registered wait or freeing active operation storage. Fatal containment is not a successful in-process cleanup and TS must retain/report incomplete. Validate this path with delayed callbacks and failed close/termination injections.

Deadlines/backoffs retained: 10 s cancellation settlement, 2 s MSYS observation grace, 5 s fatal drain, TS 12 s release ACK and 1 s status drain, plus explicitly stop-only synchronous-cancellation backoff. Healthy retained work has no safety lifetime cap. Tree unknown or pending I/O on deadline stays incomplete; no normal-work timer kills a valid retained descendant.
