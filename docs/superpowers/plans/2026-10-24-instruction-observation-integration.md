# IB Actual Source Observation and Settings Integration Implementation Plan

> Root-approved implementation packet. Execute assigned tasks with fresh GPT6Astra implementers and independent review in isolated worktrees. The user authorized continuous parallel work. The observation/factory and settings owners may run independently; the actual request/child integration remains sequential after IC-A. No recursive workers or execution-mode question.

**Goal:** Connect accepted IA to accepted W1 through an owned production observation adapter, persist explicit instruction policy safely, and freeze the actual Session consumer handoff.
**Architecture:** One host-owned FsWatchService feeds one instruction observation owner; each Session owns independent bounded IA source views and scope-bound ports, with retired views retained only while accepted producers need them. Settings supply immutable effective policy; source pending IDs describe reliability only. IC-B subsequently installs this factory in the actual prepared-request path.
**Tech stack:** Existing TypeScript/Node filesystem, chokidar-backed @i-harness/fs-watch, Vitest, existing JSON settings stores; no new runtime library.
**Baseline:** supplied MAIN b7ba78b0, accepted product 4c6aa38b. Source reviewed directly; this document contains future gates, not executed tests.

## Constraints and actual source findings

- IC-A exclusively owns core-session/format/current projection/runtime-context and narrow assembly/request wiring. IB must not edit these files or invent competing current-context DTOs.
- IA contracts.ts/service.ts already capture capability method references and receiver; deep-freeze data only. prepare takes host file/directory descriptors; immutable scope changes require replacement, not mutation.
- IA discovery.ts emits lexical directory + exact candidate/.git interests up to the authorized root, including markers above a discovered Git boundary. service.ts resolves canonical boundary aliases separately and keeps mapping failures unavailable until a fresh interest barrier. Preserve that correction.
- W1 leases.ts shares exact normalized selections within one service only; limits: 128 selections, 64 leases/selection, 16 listeners/lease, 256 roots/acquire. Each entry has its own epoch/revision. Its ready promise stays rejected after first failure even when a later recovered reset is healthy.
- W1 stream.ts DEFAULT_IGNORE is node_modules/.git/.i-harness/dist. Explicit roots and their routing ancestors bypass segment ignores; children remain subject to ignores. Use explicit candidate AND marker roots, not ignore:[] as a supposed override.
- Existing settings watch-settings.ts still calls createFsWatcher and owns retry/fingerprint recovery; layered-store preserves actual changed-path callbacks/conflation. Leave that owner unchanged in IB; migrate it in a separate W2 packet, removing its retry only when W1 takes over.
- SettingsStore.load swallows missing/corrupt input into defaults; normalizeSettings discards unknown keys; single-store rewrites normalized settings, layered-store patches its highest existing source. Neither proves profile age. _revision is section mutation counts, onboarding is an acknowledgment; Desktop workspaces.json/sessions choose a profile path, not policy birth.
- Actual assembly.ts still registers createInstructionsSection({workspace: opts.workspace}); legacy files.ts probes home then .claude, prepending winners so .claude precedes home. IB package tests cannot establish that a model request uses IA.
- Keep 24000 default rendered UTF8 bytes, configurable nonnegative safe maxBytes without a new ceiling, 256 candidate slots and 128 directory depth. No imports, ~/.codex discovery, event-derived authority, model lane, new native watcher or generic bus.

## Task 1: Gap-free W1 to IA observation

- [ ] Add causal RED fixtures against accepted W1: subscribe after ready loses the startup barrier; re-awaiting rejected ready cannot recognize recovered reset; releasing old interests before new ready loses a held candidate creation. Retain failed output and exact source identity.
- [ ] Implement interests.ts: validate/copy/freeze absolute interests against port scope; only local authorized ancestors/candidates/.git and exact configured globals are selectable. Resolve nearest existing ancestors (128-step bound), append missing suffixes, retain lexical paths, and derive canonical routing directories/candidates/markers with the same containment rules as IA. Never resolve arbitrary event paths into new selections.
- [ ] Select directory plus its explicit candidates and .git markers in both verified lexical and canonical forms. Directory coverage detects parent/junction replacement; explicit roots keep missing candidates and markers observable through DEFAULT_IGNORE. Watching a directory does not authorize reading all its children; filter irrelevant descendants before IA publication.
- [ ] Verify the bound from actual discovery.ts: planDiscovery adds both local slots to policySlots BEFORE adding that directory's interest and before discover() looks for a Git boundary. Thus ancestors/.git markers above the found boundary are already charged, including interests retained when a target hits a limit. Let C be admitted global files, G their directories, L distinct admitted local directories: G<=C and C+2L<=256 (root-specific duplicate slot keys only consume more capacity). Lexical watch roots <=C+G+4L<=512; one canonical counterpart/root gives <=1024. No selected/loaded-candidate count is used. This assumes no separately added routing ancestors: W1 handles those internally.
- [ ] Deduplicate/sort those roots deterministically, split into at most four 256-root selections with persistent:false. Validate actual interest shape/count before selection; malformed/oversized interests become unavailable, never silently truncate. During handoff old+new sets may need eight distinct selections; this is a temporary overlap, not an eight-shard steady view. W1's 128-key aggregate cap remains observable unavailable, never eviction.
- [ ] watch.ts contains one PRIVATE per-owner exact-selection route table, not a global watcher registry. Route `{generation, selectionKey, lease, unsubscribe, cursor, status, consumers}` owns exactly one W1 lease and one listener; status is 'starting'|'ready'|'unavailable'|'closed'. The key matches W1's exact normalized roots/ignore/persistent selection, without canonical subset merging. Port shard records reference routes plus their own interest generation; port fanout never adds W1 listeners/leases.
- [ ] Attach a new logical consumer synchronously before consulting route readiness. Creating a route acquires/subscribes W1 synchronously before awaiting anything and handles ready rejection immediately. Joining a healthy route captures its current cursor/state plus a private reset for only the joining port, followed by mandatory disk reconciliation; joining failed/starting routes gets current unavailable/first-outcome state. No reset disturbs already initialized consumers. Retain unchanged route references during update.
- [ ] Detach only the departing logical consumer. Last consumer retirement joins the single W1 close; retain a closing/failed route tombstone, and queue reacquisition behind cleanup rather than opening an overlapping source. W1 alone owns backend retry/recovery. Reentrant fanout uses a captured consumer list plus generation checks; closing one child cannot retire a route still referenced by siblings or accepted-producer views.
- [ ] Each callback first validates route identity/generation, then each retained port shard generation before touching state. Compare epoch/revision only within that shard: duplicate identical notification is ignored, lower cursor/contradiction makes unavailable, higher epoch requires reset. Never compare cursors across selections or expose them as IA revisions.
- [ ] Allocate one monotone safe integer revision per port lifetime. Every published IA event and update state contains the complete current pending set; same revision must mean identical state. All subscribers are isolated. Exhaustion fences the port unavailable rather than wrapping.
- [ ] W1 changed becomes IA changed with matched lexical/canonical paths; reset(initial/subscribe/overflow/recovered) invalidates relevant port dependencies and requests disk reconciliation; unavailable becomes availability:false. Observed parent/junction replacement or uncertain canonical mapping emits reset with available:false, so IA requests a fresh update; matching content events cannot clear that fence. Changes in one unrelated port do not poison another. A failed shard conservatively makes its own whole IA port unavailable because IA's availability field is scalar.
- [ ] update retains old coverage while replacements start; stage new callbacks immediately, coalesce bounded affected paths, and use a dirty/reset bit on overflow. Commit the new interest generation only after each new shard has delivered reset/ready or an unavailable outcome; include every notification received before synchronous final state capture. Then detach removed logical shard references and join last-reference route cleanup before claiming successful replacement.
- [ ] A first failure or terminal FS_WATCH_POLLING/CAPACITY returns available:false boundedly; do not await recovery or repeatedly await rejected ready. Keep the W1 lease subscribed so its later recovered reset can restore state and dirty IA. A ready resolution cannot override a newer unavailable callback; only that shard's current healthy reset/ready generation can qualify coverage.
- [ ] For successful updates, resolve canonical mappings again after new coverage is established. Changed mapping adds/replaces coverage and retries at most three rounds; unresolved/escaping/remapped targets stay unavailable and force a later fresh update. No stale mapping may be promoted by an unrelated content-read success. No healthy retry timer/stat polling; attempts occur only on update or observed reset/invalidation.
- [ ] Identical healthy update returns current state without emitting another reset (otherwise IA's three-build generation loop never converges). Initial/changed selection emits at most the required reset; IA then redoes discovery/read under coverage, so never publish pre-watch disk values as current.
- [ ] Close synchronously fences callbacks/updates, settles startup waiters unavailable, detaches all subscriptions and joins in-flight update plus every last-reference route close using allSettled. Preserve failures and retained cleanup handles for owner retry; no replacement overlaps failed cleanup. Closing one port never closes the host watch service or another Session's leases.

Implementation sketch (private records/helpers are implemented inside watch.ts, not public APIs):
```ts
// Inside one private route constructor only; 100 logical consumers reuse this lease/listener.
const lease = watch.acquire(selection)
const unsubscribe = lease.subscribe(event => acceptCurrentShard(event))
void lease.ready.then(cursor => recordReadyIfCurrent(cursor), error => recordUnavailable(error))
// update awaits the shard's first reset/ready OR failure signal, never recovery.
await firstOutcome
return frozenCurrentState() // no await between final generation/state check and capture
```
