# IH Code Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Deliver a production-reachable programmatic tool execution backend with isolated JS cells and IH-owned tool authority.

**Architecture:** QuickJS/WASM in a worker per cell; a session service owns exec/wait/store and an IH registry broker owns nested effects. Model schemas can be mixed or Code Mode only; lifecycle is assembly-owned.

**Tech Stack:** TypeScript, Node >=22.18, quickjs-emscripten 0.32.0, Vitest, existing core-plugin/core-tools/core-session/output-retention.

**Spec:** `docs/superpowers/specs/2026-10-02-code-mode-design.md`

## Global Constraints

- Work in `D:/frontend-test`, existing `codex/desktop-workbench`; preserve user dirty `packages/desktop/electron.vite.config.ts`. No push or edits to main/reference.
- Use real worker and registry boundaries in tests; do not substitute a fake interpreter.
- Additive session events; nested records never enter inference as separate tool calls. Flush dispatch before effects.
- Default off for existing settings; mixed/only are explicit host settings, no Agent preset UI.
- Every worker/observer/tool producer is tracked and disposed; compression is not process restart.
- Source/heap/CPU/output/store/transfer/concurrency limits are independent; requested yield cannot disable caps.

## Shared interfaces

`CodeModeConfig` contains mode and optional memoryLimitMb/cpuTimeMs/maxActiveCells/maxPendingCalls/maxSourceBytes/maxResultBytes/maxStoreBytes/defaultYieldTimeMs/defaultOutputTokens.

`CodeModeToolDefinition = {name:string; description:string; inputSchema:unknown; outputSchema?:unknown}`.

`CodeModeOrigin = {sessionId?:string; callId?:string; callEventSeq?:number; abortSignal?:AbortSignal}`.

`CodeModeInvocation = {cellId:string; invocationId:string; name:string; args:unknown; origin:CodeModeOrigin; signal:AbortSignal}`.

`CodeModeItem = {type:'text'; text:string} | {type:'image'; image:ImageInput} | {type:'audio'; audioUrl:string}`.

`CodeModeObservation = {cellId:string; status:'running'|'completed'|'failed'|'terminated'; items:CodeModeItem[]; text:string; truncated:boolean; error?:string}`.

`createCodeModeRuntime({tools:()=>CodeModeToolDefinition[],invoke:(call:CodeModeInvocation)=>Promise<unknown>,onEvent?:(event:CodeModeRuntimeEvent)=>void,config?:CodeModeConfig})` returns `exec({code,yield_time_ms?,max_output_tokens?},origin?), wait({cell_id,yield_time_ms?,max_tokens?,terminate?},signal?), cancel(reason?), dispose()`. All methods except tools are asynchronous. Runtime event owns cell started/output/closed metadata. Names/source/options are validated before admitting a worker.

`registerCodeMode(ctx,tools,{session,sessionId?,config?,flush?,maxParallel?})` returns `{schemas():ToolSchema[],cancel(reason?):Promise<void>,dispose():Promise<void>}`. The package index exports the runtime, mount and their public types. AgentDeps optionally supplies `modelToolSchemas:()=>ToolSchema[]`.

## Preflight and rulings

Task 1 owns runtime/types/worker and Task 2 owns broker/catalog/mount; their interface is the definitions above. Task 3 owns hosts and consumes mount/schema APIs; root coordinates manifests and lockfile. All share session event semantics through Task 2. Existing complete baseline is `5d923939`, verify 4,039 passed/10 skipped/0 failed; only the user's Electron config is dirty.

Ruling: preserve old settings' tool exposure with default off and enable mixed via the new flag/config — new installed runtimes remain opt-in; wrong default would change every existing model request.
Ruling: QuickJS/WASM rather than native V8 binding — retain isolated module/async tool semantics while avoiding another Windows native ABI payload; performance claims require measurement.
