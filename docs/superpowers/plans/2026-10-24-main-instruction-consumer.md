# Main observed instruction consumer implementation plan

> **For agentic workers:** Use subagent-driven-development or executing-plans. Execute the connected tasks below in order; root reserves shared files and obtains independent full-range review. Do not replace this with another general research pass.

**Goal:** Make real main-agent requests consume bounded, observed AGENTS.md/CLAUDE.md instructions from the selected saved policy, while retaining the originating view through original request/result settlement.
**Architecture:** One host owns the existing watch/observation services and saved-policy loader; each main Session owns exact source views and private evidence. Existing runtime/context facts carry text once, existing prepared request guards reject observed staleness, and original response/result sources retain view leases. Successful selection consumption is one callback from the real completed response, not another acceptance state machine.
**Tech Stack:** Existing TypeScript packages, SettingsStore.loadObserved, FsWatchService, InstructionService, runtime-context, core-agent managed facts, controlled HTTP/JSONL and Vitest.
**Spec:** docs/superpowers/specs/2026-10-23-v0.1.13-integrated-delivery.md Tasks2/3; docs/superpowers/plans/2026-10-24-current-context-reduction.md C1/C2; accepted IA/IB/W1/W2/P2/S2; source findings in `.superpowers/v0113-integrated-delivery-20261023/{current-instruction-consumer-plan-draft,instruction-consumer-p2-rebase,instruction-host-final-contract}.md`. This promoted plan supersedes those drafts' ack-map/six-callback proposals and stale P2/S2 reservations.

## Frozen structural contracts (control plane only)

```ts
interface InstructionRequestEvidence { readonly kind: 'instruction-request'; readonly version: 1 }
interface RequestContextPin { release(): Promise<void> }
type AcceptedExchange = {
  acceptedSeq: number;
  outcome: Extract<ProducerFactOutcome, {kind:'committed'|'memory-committed'}>;
};
interface SuccessfulInstructionHandoff extends AcceptedExchange {
  candidate: RequestEvidence;
  evidence: InstructionRequestEvidence;
  physicalExecutionReceipt: ExecutionReceipt;
}
interface SessionRequestContext {
  reconcile(signal?: AbortSignal): Promise<void>;
  capture(): InstructionRequestEvidence | undefined;
  current(evidence: InstructionRequestEvidence | undefined): boolean;
  retain(evidence: InstructionRequestEvidence): RequestContextPin;
  succeeded(handoff: SuccessfulInstructionHandoff): void;
  promotedHumanRequest(): void;
  close(): Promise<void>;
}
interface InstructionHost { create(scope: InstructionScope): InstructionService; close(): Promise<void> }
type SavedInstructionState = {kind:'ready';generation:string;policy:InstructionPolicy}
  | {kind:'unavailable';generation:string;reason:string};
interface SavedInstructionPolicyPort {
  current(): SavedInstructionState;
  ready(): Promise<void>;
  subscribe(fence: () => void): () => void;
}
interface InstructionEnvironment {
  host: InstructionHost; policy: SavedInstructionPolicyPort;
  dispose(): void; close(): Promise<void>;
}
type InstructionReadScope = {
  status:'queued'|'reference-only'|'unavailable';
  reason?:'outside-root'|'canonical-escape'|'mapping-unavailable';
};
// FsToolDeps structural callback, using its actual existing ToolExec type:
// observeInstructionTarget?: (target:{path:string;kind:'file'|'directory'}, exec:ToolExec) => Promise<InstructionReadScope>;
// fileReadPage(content,args,policy,instructionScope?:InstructionReadScope): FileReadPage;
// FileReadPage gains only optional instruction_scope with the bounded value above.
```

- `AgentDeps.requestContext?` is the structural port. `RequestEvidence.instructions?` carries only the private token. Use a private WeakMap in the Session manager for token membership, originating view, authority/policy generations, complete immutable candidate/applicable fingerprints and captured pending-selection generation. Neither copied shape, seq, JSON nor a persisted runtime/context record mints a token or producer permission.
- The manager owns selection/views/refcounts, NOT a candidate/acceptedSeq acknowledgment table. Raw acceptance/capture/flush failures remain solely in the existing original response settlement. `succeeded` is a synchronous data-only notification from that real successful closure, never I/O, reconciliation or a source of execution permission.
- Invalid caller-shaped tokens are rejected. Legitimate successful completion may describe a view invalidated after physical issue: it truthfully consumes only that captured selection generation, does not mark its old source currently ready, clear newer pending reads or authorize mutation. Future IE checks the originating still-observed evidence.
- `retain` increments the existing view reference synchronously and returns one idempotent release. A release that drops the last reference joins that view's original close; after a close failure retry the same handle without decrementing twice or reacquiring a new service. Failed cleanup stays unavailable/held; no detached `source.close().then(release)`.
- `createInstructionEnvironment({settingsPath,watch?})` is the explicit saved-profile host factory. Supplied watch remains borrowed. It owns one policy watcher and one observation owner; all its views share that owner. `dispose` fences synchronously, `close` joins retained original jobs/handles with retryable partial cleanup; no parent watch close from a borrower.
- The policy reader may use its own instance of the existing SettingsStore selected by that exact path; it consumes only strict observed instruction policy. It must not silently overwrite another host's execution/provider settings cache through a validation path that does not apply that host's execution checks. This is not a second settings-store implementation. The settingsPath is mandatory on the saved-profile factory; a separate project-only default factory creates no saved-profile reader.
- Direct assembly/service embedders without a selected saved-profile environment use a documented project-only default: enabled=true,maxBytes=24000,globalSources=[],cwd/roots from their actual workspace/authority. No ambient home or legacy fallback. Service owns one lazily created default environment across Sessions; a standalone assembly owns its one default. Explicit environments are borrowed and closed by their real outer host. Desktop/CLI/SDK/ACP always supply the resolved native profile environment below.
