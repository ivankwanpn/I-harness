## Exact owner and private wiring

Keep all public FactOwner/ManagedAction/ReceivedInputSource/CapturedSettlementFact types and ports unchanged. No public release/acknowledge capability is added.

1. `packages/session-persistence/src/coordinator/settlement-fact.ts` remains the sole serial/disposition owner of each authentic capture. Add a private optional retirement policy to `captureSettlementFact`/`retainSettlementCapture`, not to the returned public handle. Suggested internal types are `type InvalidNotIssued = Extract<FactOutcome, { kind: 'not-issued' }> & { code: 'FACT_INVALID_GROUP' }` and `interface CaptureRetirement { accepts(outcome: InvalidNotIssued): boolean; retired(): void }`. The serial owner itself first requires an actually captured group and authentic not-issued/FACT_INVALID_GROUP outcome; only then can it consult this cancellation witness. It owns one additional terminal outcome slot in its existing closure, with no second queue/map. Default captures have no policy and preserve their current behavior.
2. `packages/session-persistence/src/coordinator/source-facts.ts` remains the sole owner of its existing pending Set. Its private `capture(draft, accepts?)` wires an eligible policy into that serial owner and supplies `retired: () => pending.delete(owned)` for the exact owned wrapper. This callback is closed over one handle and never exposed on a public port. It fires once, synchronously at the serial owner's terminal disposition transition. Membership is not decided by a later re-evaluation of mutable history. Generic retain/invalid captures and every non-cancellation family remain committed-only.
3. `packages/session-persistence/src/coordinator/received-input-source.ts` builds this policy only after its existing assertHeld and successful strict DTO validation, and only for a strict closed current cancellation event. Its private operations type gains `cancellationRetirement(event): ((outcome: InvalidNotIssued) => boolean) | undefined`. Assertions/validation precede witness construction; no getter or malformed DTO is evaluated as proof. It immediately calls the existing native capture in the same synchronous turn, with no intervening await or second lowering. Admissions and other source families receive no policy.
4. Add a focused pure private leaf, proposed `coordinator/received-input-cancellation.ts`. Its factory binds the exact owned SessionView at native input-source registration. After held-owner and strict DTO checks, the per-cancellation function synchronously snapshots the inputId primitive and exact immutable currently pending admission object/seq. Explicit inherited/seed-only observations are ineligible. A genuine own pending admission loaded from disk is eligible under the new held owner; no initial-prefix or receiver-registration floor excludes it. Merely loading historical bytes gives no release authority: the authentic newly captured cancellation and its native not-issued disposition plus positive installed disposal proof remain mandatory. No authoritative record/cache is added.
5. `createManagedDocument` only imports this leaf and wires the private factory at its existing received-input-source composition expression, e.g. `cancellationRetirement: cancellationRetirementFor(state.view)`. This adds one wiring expression, not an algorithm, to the large managed-document owner. Public FactOwner/ManagedAction/ReceivedInputSource/CapturedSettlementFact shapes are unchanged.

Alternative rejected: changing stopNotifications/ingress cancellation ordering merely avoids one schedule and misses other legitimate cancellation/promotion races. Generic removal of all not-issued handles breaks required settlement. Exposing a producer-callable release handle creates a bypass. Passing an unqualified `!isPending` predicate lacks original admission/disposition proof. Moving the whole source-facts algorithm into managed-document would grow the wrong owner.

## Retirement rule and drain behavior

The per-capture witness must be ineligible unless the cancellation DTO is strict closed version1, has the correct event type/nonempty inputId/valid optional reason, no accessor/extra/foreign draft field, and the exact currently pending own admission exists at capture time in this same owned view. The admission must be outside the seed/inherited observation region; its being already present when this current owner opened or receiver registered is not itself a refusal. Snapshot primitive identity fields and the immutable managed admission reference/seq; do not retain caller-controlled mutable DTO data as proof. The existing native lowering remains the only capture lowering operation. A malformed or unbound capture cannot be rescued by a later promotion of an unrelated/reused id.

Retire that exact handle only if its authentic returned outcome is **not-issued/FACT_INVALID_GROUP**, the exact original admission still occupies its original seq in the same owned view, it remains the latest admission for that id, and the authoritative committed view now contains a matching **promotion or cancellation after that original admission**, with no current pending instance. The installed immutable owner view supplies the committed disposition; a backend candidate before installation, no admission, mere absence, a later reused input identity or a foreign/unowned snapshot is insufficient. A cold-loaded own admission can qualify only through this same current owned-view and newly captured-operation path.

Reject retirement for pending inputs, malformed/unbound captures, FACT_CLOSED/CANCELLED/PRECONDITION_STALE/RECOVERY_REQUIRED, absent/unknown/conflict/recovery-required/issued keyed results, or any result without that positive original disposition proof. Issued uncertainty retains the same original key/handle and existing reconciliation. No reissue, manufactured commit/receipt or semantic result change is allowed.

The authentic captured-disposition serial owner freezes the **original returned not-issued outcome**, records it as this capture's terminal retired disposition, then notifies the exact source membership callback once. It returns that same truthful outcome; no committed variant/receipt/key or replacement cancellation is created. This is a one-way terminal transition. Subsequent history changes, including reuse of an input id, cannot clear or re-evaluate it.

Every public handle operation (`admit`, `reconcile`, `observe`, `retryAbsent`) enters the existing serial `track` owner. At the head of each serialized operation it executes the original `operations.assertHeld()` before consulting the terminal slot. A retired capture then returns the stored not-issued outcome immediately. It never reads another current disposition or calls native admission/reconciliation/retry. Thus operations queued before retirement also see the terminal slot when their turn arrives; calls after input-id reuse cannot cancel the new admission. If the held owner is lost or the original source has closed, the existing check still throws instead of returning the cache. There is no producer-callable retirement/release/query hook and no second serial chain.

The source callback removes the exact owned wrapper from its existing pending Set at that terminal transition. records.drain must honor this qualified retirement rather than unconditionally feeding the invalid result to committedFactSeqs: after the original reconciliation returns, only a still-pending handle needs the ordinary committedFactSeqs assertion. A concurrently queued operation may observe the same retired outcome, but cannot reinsert or re-admit that handle. Default sources have no policy, so an uncommitted default handle remains pending and still rejects as before. A thrown native operation supplies no qualifying outcome and remains an error. The captured-group guard also prevents a failed lowering/invalid capture from being retired.
