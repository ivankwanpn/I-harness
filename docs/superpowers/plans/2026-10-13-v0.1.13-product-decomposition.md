# v0.1.13 Product Subsystem Decomposition Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 拆分全倉庫過大的產品檔案／函式為有單一入口、明確所有權的子系統，降低後续AI維護的上下文與漏改風險。

**Architecture:** 穩定原公開facade，先抽puredata／projection，再抽narrow-dependency能力模組，最後遷移stateowner與lifecycle。每個review單元保持既有行為，事件／指令語意變更在另外兩份計劃進行。

**Tech Stack:** 現有TypeScript/React/Node/Rust、Vitest、nativequalification與reachability工具。

**Spec:** `docs/superpowers/specs/2026-10-13-v0.1.13-product-decomposition-design.md`

**2026-10-15 integration:** 上下文重構的S/CX對照以 [重合地圖](../../refactoring/2026-10-15-context-decomposition-overlap.md) 及 [ContextEngine框架](../specs/2026-10-15-context-engine-framework.md) 為準。原純結構gate仍保留；本次同一交付可完成拆分與功能，但使用分開提交／驗收，不為等價聲明遮掩故意修正的語義。未重合任務不自動恢復；完成數依實際review更新。

## Global Constraints

- 只拆產品程式：43個基線candidate。**不拆測試檔與工具腳本**；不拆vendor/generated。
- 所有exactinputpaths、AST範圍、imports及testinventory見 `docs/research/2026-10-13-v0.1.13/census.json`；目標子模組見同目錄 `large-files.md`。這兩份是本計劃的規範附件。
- 初次抽取保持publictypes／wire／defaults／error／ordering／Stop／providerprotocol／persistedformat不變；不混入功能修正。
- 每個狀態Map／executionowner／listenerlifetime只能有一個權威；不能把大closure換成shared-anybag。
- 新目錄有單一publicentry與短README，記錄owner、invariants、shutdown順序和testcommands。
- 產品行數／functionspan是檢查訊號，不可minify或刪註解來滿足尺寸；tests不作尺寸gate。
- native suites逐套件執行，`--maxWorkers=2 --minWorkers=1`；不碰liveaccount、profile、已安裝IH。

## 各 review 單元的固定執行步驟

下表每一列是一個獨立Task，不是一個把32組一次改完的commit。列中指定舊檔與新目錄，詳細私有module名字和consumer範圍由規範附件對應列給出；若spec目錄裁定不同，以spec為準並先更新追蹤表。

- [ ] 先執行該列verificationcommand保存baseline；失敗先定位，不能一邊移動一邊把舊failure藏起來。
- [ ] Extract既有puretypes/constants/projections；保留原import façade，再用型別檢查驗證caller不變。
- [ ] 為實際獨立責任抽factory/handler，顯式注入需要的資料與行為；stateowner只移動一次。保留原control flow與dispose順序。
- [ ] 調整產品imports，測試僅必要import/fixture接縫調整；缺少關鍵owner/order覆蓋才增加characterization。不得分拆原測試suite。
- [ ] 同verificationcommand＋affectedtypecheck；檢查wire／event／CLI／UIidentity實際觀測不變，重新跑reachability觀察是否產生新unusedexports或錯誤不可達判斷。
- [ ] 每目錄加README，更新before→aftermanifest，commit `refactor(<subsystem>): separate cohesive responsibilities`，獨立review通過後才移下一列。

