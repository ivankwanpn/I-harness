## Decision

Implement a **non-retiring original-publication prerequisite plus an explicitly retried original generation-close handle**, owned by the existing resident/generation lifetimes. Keep ordinary generation `close` failure memoization for aliases within the original turn; add an explicit recovery entry point that retries only the same retained close capture. Do not merely clear `closing`, do not call render to recover publication, and do not close the lease early.

This is a small cross-owner extension requiring a fresh reservation: the accepted factory deliberately did not expose settlement; its plan explicitly deferred a child-wide settle-before-followup seam to an actual caller decision. The frozen actual consumer supplies that need. The reviewed resident plan's prohibition on Core implementation changes can remain: the recommended Core change is a type-only optional method; Core turn behavior stays unchanged.

## Evidence and authority

1. `session-executor/src/lifecycle/generation-action.ts`, `OwnedGenerationAction.close`: the first close creates `closing`, calls `document.settle`, closes the original clock in finally, and permanently reuses the rejected promise. The initial disposition and timestamp are created there. Four calls in the frozen consumer produced only one settlement capture and no lifecycle drain.
2. `generation-actions.ts`: `document.settle` creates `source.generation.capture(event)` on every invocation. `receipt` deletes a not-issued capture from the lifecycle's `retained` set. Simply making close retryable would remint a capture. This local deletion does NOT prove that the required source discarded the capture.
3. `session-persistence/src/coordinator/source-facts.ts`: the registered source retains its own exact capture wrapper in `pending`; removal happens on committed acknowledgment. Thus the original not-issued generation-close capture still exists at its real source even after the lifecycle-local set drops it.
4. `settlement-fact.ts`: the once-lowered group and serialized receipt slot survive. `reconcile()` uses that group's native status; if latest is not-issued it invokes the same group's admission. If latest is unknown/conflict/install-recovery it reconciles its exact batch key. Committed is consumed; absent is not reissued by reconcile. `retryAbsent` is separate authority. `FACT_PRECONDITION_STALE` remains terminal to admission. These semantics are already sufficient for the observed nonissue; no source/coordinator repair is justified.
5. `managed-document.ts`: quarantine prevents even required admission until the original pending batch is reconciled. Required registered-source admission otherwise survives action Stop and document new-work revocation, and checks that its exact original source/held owner remains valid. Optional action captures do not gain that authority. A recovery hold/source fault can still block optional work after one batch is resolved; clearing quarantine is not equivalent to permission for a new turn.
6. `runtime-context/src/index.ts`: `settleOriginals` freezes flights plus original publications, waits only those accepted flights, reconciles their exact captures, finishes original actions and releases original publication pins. It neither renders nor retires. Terminal publication nonissue/absence discharges publication cleanup but is not proof that a request context was published. Its completion retries failed pin release; a recorded action-finish throw remains retained. Preserve that distinction.
7. `child-host/slot.ts` currently exposes requestContext/retire/close only; runtime.close precedes manager.close. `ResidentPreparation.close` correctly holds the lease behind generation/CodeMode/result acknowledgments. Moving lease.close before generation would erase the intended dependency barrier.
8. `core-agent/src/agent/turn.ts` closes the delegated generation on turn failure before `followup/drive.ts` reaches bodyExit/finally. Core `create.ts` owns separate registered source drains and retains their failure through its document source owner. A fulfilled caught followupChain is not a source-close acknowledgment. The frozen incident is settled rejected debt, not a rawNext deadlock.

## Deterministic attempt/state table

| Entry/state | One authorized attempt | Success | Failure/retention |
|---|---|---|---|
| Core ordinary close, no intent | Freeze original disposition/envelope; capture once; admit once; stop original clock | Mark original close acknowledged | Memoize this attempt result; retain capture/source/clock identity |
| Same close alias or concurrent recovery | Join admitted flight | Same result for all aliases | Same rejection, including falsey values |
| Normal turn finally | bodyExit precedes cleanup; finite original publication prerequisite; ordinary close joins its original result | Drain lifecycle, finish original action | No hidden recoverClose after ordinary close fails |
| Later explicit assembly/entry cleanup | Retire synchronously; body/opening exit; finite publication settlement; recover original close if previous owner close attempted | Continue remaining phases only | Attempt ends immediately at dependent barrier; independent siblings still attempted |
| Publication remains unknown/throws/pin release fails | One original settlement attempt | None | No generation recovery or lease/manager/document release |
| Publication committed/known absent/nonissued cleanup | Finish/release original pin, without render | Permit required generation cleanup | Does not authorize physical request or count as publication success |
| Close known not-issued/RECOVERY_REQUIRED | Same native capture reconcile/admit under still-held required source | One original close fact installed | No new capture; stale/closed/invalid remains debt |
| Close unknown/conflict/install recovery | Reconcile original capture/key once | Acknowledge installed original slice | Unknown stays debt; never infer nonissue |
| Close absent | Observe retained absence | None in this repair | No implicit retryAbsent or replacement close |
| Close acknowledged | Return success idempotently | Remaining lifecycle/source phases may retry | Never reclose acknowledged generation |
| Next genuine inbox | Non-retiring predecessor/publication/finished-source barrier, then revalidate currentness | Original new inbox follows existing admission/clock path | No new status/source/generation/model/input; keep original debt |
| Teardown before first request | If no publication, settleOriginals is finite no-op; if no generation, skip absent phases after acquisition exits | Normal remaining cleanup | No artificial first request/render/generation |

A cleanup attempt is the outer original owner's explicit call, not an arbitrary promise catch. The first actual close result may predate that owner's finally. Do not treat every ordinary close invocation as permission to retry. A later external attempt after completed rejection is the retry boundary. A concurrent disposer joining finally observes the same failed attempt even if backend acknowledgment arrives meanwhile; the next explicit call can recover. This trades one deliberate boundary for deterministic no-hidden-retry semantics.

## Ownership and ordering proof

Publication recovery is reached only through the original preparation's retained lease and original slot/runtime. That runtime holds its exact optional source/action/capture and publication pin. It cannot create new captures because settleOriginals never calls render. Reconciliation of an issued publication remains valid after abort/revoke because it uses the held original receipt, not optional new-work admission. A known optional nonissue is cleanup only.

The original generation source was registered before the runtime failure. Its required capture owns the exact once-lowered close draft and original source admission. After publication reconciliation removes the quarantine, native reconcile on that same nonissued capture can admit the original terminal fact even after Stop. Required admission still checks the held source, owner and document. No generation clock/currentness predicate is substituted: terminal settlement deliberately does not run current(), while new bind/reserve/issue still uses unchanged original clock guards. The frozen trustedAt/disposition is not refreshed on retry. Expired/invalid clocks cannot acquire new model permission.

Generation acknowledgment precedes lifecycle release/action finish. Resident CodeMode and original result obligations remain barriers. Lease.close then performs runtime.close → manager.close. Only afterward can original document/context be released. Assembly host/root runtime/root manager/document/environment/result-store barriers remain as reviewed. Failed source drain, capture failure, blocked checkpoint, unknown append and pin release remain different outstanding obligations. A successful publication reconciliation cannot erase a retained late source failure.

## Alternatives and unresolved limits

A lease settlement seam alone cannot overcome a cached rejected generation promise. Resetting close alone remints captures and loses deterministic attempt boundaries. Calling lifecycle.drain first can recover the source's retained capture, but risks releasing it before producer acknowledgment and does not clear the producer's cached rejected close; reject that ordering. Early lease.close retires/releases dependencies before producer acknowledgment; reject it. A general coordinator reconcile or source re-registration discards the ownership proof. Adding a generic retry option to close could work but makes ordinary Core/finally aliases too easy to turn into hidden retries; the explicit recoverClose capability is easier to audit.

Frozen evidence proves the original failure and native nonissue recovery mechanics, not the proposed full sequence. The optional Core type addition, new lease capability, and next-inbox exact-document barrier require independent scope/design approval. Source-capture absence is intentionally fail-closed: granting original retryAbsent would be a separate design decision. Publication action.finish throws are sticky in the frozen runtime and are not converted into retryable finish by this proposal. The historical simultaneous-result incident remains unattributed; passing retained-artifact controls do not explain it. No claim is made that every source fault becomes recoverable after publication acknowledgment.

Primary acceptance risk is alias accounting across Core failure cleanup, normal finally and concurrent external disposal; the explicit recovery boundary and causal controls above must be reviewed before implementation. Product remains frozen until root assigns the narrow repair.
