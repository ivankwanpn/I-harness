# Desktop D0–D1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a locally running I-harness Desktop shell with ZCode-style workspace, session, timeline and task views backed by SDK wire, enabling executable prompts only after the separately approved backend host connects the existing sandbox.

**Architecture:** Add one frontend package, `packages/desktop`. Electron main owns one SDK subprocess per active workspace and a narrow IPC boundary; preload exposes typed methods; React renderer projects paged SDK events into a bounded timeline. The user has approved one new backend package, but it is designed and implemented in a separate plan; until it reports the existing sandbox mode is wired into the service, this plan's existing SDK connection is for initialization and read-only inspection only. Approval replies and file diff review belong to later D2–D3 frontend tasks.

**Tech Stack:** TypeScript 5.9, Electron 44.4.5, electron-vite 5.0.0, Vite 7.3.6, React/React DOM 19.3.0, `@tanstack/react-virtual` 3.14.13, Vitest 3.2, Testing Library 16.3.3, jsdom 30.1.1. The pinned public package versions were checked against npm on 2026-09-25; electron-vite 5 accepts Vite 7. Electron's [security guide](https://www.electronjs.org/docs/latest/tutorial/security) is the reference for the renderer boundary.

**Spec:** `docs/superpowers/specs/2026-09-25-desktop-workbench-design.md`

**Backend dependency spec:** `docs/superpowers/specs/2026-09-25-desktop-gateway-design.md` (the new package has separate user review and implementation; this plan does not implement it)

## Global Constraints

- Work only in the experimental clone `D:\frontend-test`, on local branch `codex/desktop-workbench`. Do not push or create a PR; `origin.pushurl` remains `no-push://disabled`. Do not modify `D:\I-harness-main`.
- Add **one frontend workspace package**, `packages/desktop`; keep its main, preload, renderer, adapters and design tokens internal. Do not import private external `@zcode/*`, `@opencode-ai/*`, or `@deepseek-ai/*` packages. Public general-purpose dependencies are allowed.
- Desktop connects through SDK wire. The separately approved new backend package is **outside this frontend plan**; do not implement it here. No existing SDK method or CLI change, approval reply, question reply, generic file-diff service, provider-settings service, or browser/terminal service is authorized by this plan.
- The existing `i-harness sdk` host does not pass `sandbox` to `createSessionService`. Tasks 1–6 may use it for handshake, listing and other read-only inspection; **do not enable `session/prompt` in the UI until the new host demonstrably reuses the existing sandbox and reports a wired mode**. `i-harness run` and `session-executor` already implement sandbox; do not create another sandbox engine.
- Preserve honest capabilities: `listingUnavailable` is not an empty list; model-unconfigured is not ready; cold `session/tasks` may truthfully be empty. Do not add controls for D2/D3 operations before their contracts are approved.
- Renderer has no Node access. Use `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, validated IPC sender and typed allowlist. Serve only bundled local renderer content.
- D0–D1 are dev-mode experimental deliverables; signed installer and self-contained production CLI/runtime are D4 work, not hidden requirements of this plan.
- Follow test-first cycles for behavioral code. Before each local commit run the changed package's relevant test/typecheck/build gate; never infer success from a previous run.

```ts
export type DesktopRequest =
  | { kind: "workspace/open"; path: string }
  | { kind: "workspace/list" }
  | { kind: "workspace/sandbox/state"; workspaceId: string }
  | { kind: "session/list"; workspaceId: string }
  | { kind: "session/dashboard"; workspaceId: string }
  | { kind: "session/create"; workspaceId: string }
  | { kind: "session/history"; workspaceId: string; sessionId: string; afterSeq: number; limit: number }
  | { kind: "session/prompt"; workspaceId: string; sessionId: string; prompt: string }
  | { kind: "session/cancel"; workspaceId: string; sessionId: string }
  | { kind: "session/queue"; workspaceId: string; sessionId: string }
  | { kind: "session/tasks"; workspaceId: string; sessionId: string }
  | { kind: "session/model/state"; workspaceId: string; sessionId: string }

export type DesktopEvent =
  | { kind: "sdk/notification"; workspaceId: string; method: "session/event" | "session/status"; params: unknown }
  | { kind: "sdk/disconnected"; workspaceId: string; message: string }

export interface DesktopBridge {
  request(request: DesktopRequest): Promise<unknown>
  onEvent(listener: (event: DesktopEvent) => void): () => void
}
```

## Task 5: History cursor, overlap and disconnect projection

**Files:** Create `src/renderer/session/event-window.ts`, `test/event-window.test.ts`.

**Interfaces:** Produces:

```ts
type WireEvent = HistoryRange["events"][number]
interface EventWindow { cursor: number; events: WireEvent[]; live: WireEvent[]; connection: "online" | "offline" }
function applyHistory(state: EventWindow, page: HistoryRange): EventWindow
function applyNotification(state: EventWindow, event: WireEvent): EventWindow
function markDisconnected(state: EventWindow): EventWindow
```

`cursor` is the **next unread index** returned as `nextSeq`, not the last displayed `seq`. The SDK's first event has `seq: 0` and `history({afterSeq:0})` includes it; tests must pin this boundary.

- [ ] **Step 1: Add failing tests:** first page with seq 0/1 and `nextSeq:2`; a live seq 2 arriving before the overlapping history page; duplicate seq 2 shown once; offline retains rows; a later page merges seq 2/3 without moving the cursor backwards; an event without seq remains in `live` only.
- [ ] **Step 2: Run** `pnpm --filter @i-harness/desktop test -- test/event-window.test.ts`. Expected: fail because functions do not exist.
- [ ] **Step 3: Implement** immutable reducers using seq-keyed merge and sorted output; `applyHistory` advances cursor only to the page's `nextSeq`, `applyNotification` does not advance the durable cursor, and missing-seq notifications never become a replay checkpoint. Keep only the loaded history window; do not preload all sessions.

```ts
export function applyHistory(state: EventWindow, page: HistoryRange): EventWindow {
  const bySeq = new Map(state.events.filter((event) => event.seq !== undefined).map((event) => [event.seq!, event]))
  for (const event of page.events) if (event.seq !== undefined) bySeq.set(event.seq, event)
  return {
    ...state,
    cursor: Math.max(state.cursor, page.nextSeq),
    events: [...bySeq.values()].sort((a, b) => a.seq! - b.seq!),
    live: state.live,
    connection: "online",
  }
}
```

`applyNotification` merges a sequenced event into `events` using the same seq-keyed rule, or appends an unsequenced event to `live`; it does **not** advance `cursor`. `markDisconnected` only changes `connection` to `offline`. The first-page test must prove seq 0 survives.

```ts
export function projectTimeline(events: readonly WireEvent[]): TimelineRow[] {
  const rows: TimelineRow[] = []
  const toolIndex = new Map<string, number>()
  for (const [index, event] of events.entries()) {
    if (event.type === "tool/call") {
      toolIndex.set(event.callId, rows.length)
      rows.push({ id: `tool:${event.callId}`, kind: "tool", name: event.name, output: undefined })
    } else if (event.type === "tool/result" && toolIndex.has(event.callId)) {
      const rowIndex = toolIndex.get(event.callId)!
      const previous = rows[rowIndex]
      if (previous?.kind === "tool") rows[rowIndex] = { ...previous, output: event.output }
    } else if (event.type === "step/end" && (event.refused || event.truncated || event.empty)) {
      rows.push({ id: `step:${event.seq ?? index}`, kind: "outcome", flags: { refused: event.refused, truncated: event.truncated, empty: event.empty } })
    } else if (event.type === "user/message" || event.type === "assistant/message") {
      rows.push({ id: `message:${event.seq ?? index}`, kind: "message", role: event.type === "user/message" ? "user" : "assistant", text: event.text })
    } else if (event.type !== "assistant/chunk") {
      rows.push({ id: `event:${event.seq ?? index}`, kind: "other", label: event.type })
    }
  }
  return rows
}
```
