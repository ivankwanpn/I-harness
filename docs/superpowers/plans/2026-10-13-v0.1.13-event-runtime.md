# v0.1.13 Internal Event Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 IH 內部狀態通知、可靠完成交付及無固定狀態輪詢的介面更新。

**Architecture:** 每個 domain 保留實際執行所有權；每 Session completion 子系統保存工作事實並經既有 Inbox／lane 交付。UI 使用 scoped revision snapshot，與模型喚醒分離。原生 backend 的真實輪詢另設平台 gate。

**Tech Stack:** TypeScript、Node、既有 Session 日誌／persistence、Electron／React、fs-watch、Vitest、既有原生 sandbox。

**Spec:** `docs/superpowers/specs/2026-10-13-v0.1.13-event-runtime-design.md`

## Global Constraints

- Google 截圖是概念例子；不新增外部 Webhook／郵件功能，不引入訊息 broker 依賴。
- 有所有權的 producer 不因 observer release 重跑或取消；工具與原生沙箱權限保持完整。
- critical fact flush 成功後才交付；每個 source attempt 固定 inputId；同 Session 只有原本的一條模型 lane。
- Stop 有持久化世代，晚到事件與重啟不可復活舊世代。
- 產品／CLI／測試／SDK import 從子系統公開入口進入；不跨目錄讀私有 implementation。
- 結構計劃先完成相關 module 的等價拆分。下列舊路徑是 v0.1.12 的定位點；實作按該計劃的 target manifest 修改，不能重建一份舊實作。
- 原生 suite 逐個執行，使用 `--maxWorkers=2 --minWorkers=1`；不動使用者的 live profile／模型帳戶／正在執行的 IH。
- 當前文檔階段沒有實作；所有測試名稱和新增介面均為待建立項目。
