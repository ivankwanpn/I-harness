## Binding decisions

- LP01: Existing ContextStore, original protected workspace mutation turn, actual physicalBytes and original files/index remain the sole storage/quota truth. No service-lifetime free-byte/permission cache, second durable reservation, total-ref cap or weaker integrity check.
- LP02: Task1 records actual existing I/O using test-only scoped wrappers and removes the duplicate physical inventory in one admitLegacyIndex operation. Both quota predicate and SQLite ceiling use the same real total; safe arithmetic, index/journal headroom and actual before-growth refusal stay. A private pure shared quota predicate may avoid duplicate arithmetic; no public diagnostics/API or runtime telemetry.
- LP03: Task2 performs one complete original-authority preflight before any expiry deletion, then one streamed committed-row effect pass in that SAME turn. Every accepted deletion still checks current canonical commitment, actual expiry and exact original slot/inode/content. Full-budget cleanup uses no new membership scratch/cache or quota reserve. Funded-but-unproven refs remain preserved/refused. Current canonical map membership prevents duplicate effects, not an unbounded new dedup graph.
- LP04: Task3 may admit the exact finite aggregate growth of original funding once in its existing turn, then actually allocate/sync/readback every reserve and verify actual inventory before any target grant. Two bounded metadata passes, no mutable free-byte debit/credit system. Include partial prefixes, independent rewrite capacity, canonical padding, journal, application pending and true hardlink alias relationships. Original per-open identity and live policy remain real.
- LP05: Unknown/partial write, changed identity/content or lost turn invalidates reused admission/proof. Retain original files/handles, join cleanup and inventory actual retained state on the next authorized attempt. No planned refunds, stale proof revival, source re-export or whole-owner rollback. Passive reconciliation cannot allocate missing work.
- LP06: Keep existing cancellation semantics. Cooperatively stop new preflight work at real boundaries; issued fsync/rename/terminal transitions must settle or retain honest debt. No fake timeout rollback, new polling, native lock cancellation API or interruptible clear/delete contract. Actual Stop and source/target guards remain checked around current awaits.
- LP07: Prove improvement with actual structural I/O counters before scale timing. Funding batch target≤2 inventories plus separately labeled index admission; expiry≤2 graph walks independent of E. Per-page O(P×F) work remains separately visible. Do not suppress real slot/native checks to meet counters.
- LP08: Freeze these controlled Windows-host checkpoint ceilings before the later expensive measurement:101 distinct-ref owner≤5s;1001 owner≤60s;1001 hot expiry≤30s. These are not achieved results or whole-version usability acceptance. A miss remains open and requires causal follow-up; do not raise the threshold after a miss. General R6 archive/projection/100MiB/user-flow obligations still apply. Root reserves a single1001 run only after bounded controls pass.

A failure-path count may exceed a success structural ceiling if actual re-inventory is needed; it must be labeled and proved, never optimized away. Root integrates reviewed work.
