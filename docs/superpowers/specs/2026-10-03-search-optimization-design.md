# IH bounded content search design

2026-10-03. User approved implementation of the proposed grep/ripgrep follow-up, then explicitly selected search optimization as this round's scope. This extends the existing search/tool/project-file flows. Work stays in `D:/frontend-test`, branch `codex/desktop-workbench`, baseline `eb7d757c`; protected main/reference checkouts and the existing dirty Electron configuration remain untouched.

## Goal and scope

Deliver cancellable, bounded model `grep`/`glob`, discoverable search options and honest partial-result metadata, plus human Desktop content search across current project folders with correct file/line navigation. Preserve existing tool names and the existing filename explorer. The approved research priorities authorize this design/implementation; no repeated execution approval is needed. Other providers, cold subagent reconstruction, OCR, Git expansion and reminder/wake work are outside this round.

## Evidence and approach

The shipped `@vscode/ripgrep` binary is rg 15.0.0 with PCRE2 10.45/JIT. Actual tiny probes confirmed matching-file-only JSON begin/end, partial stdout with exit2, UTF-16 BOM conversion, invalid UTF-8 Base64 records, and explicit-file `--max-filesize` bypass. Thus a result cap after full capture or a stat followed by direct rg file arguments is insufficient for hard read/output limits.

Use three composable units:

1. Add opt-in foreground raw streaming to the existing sandbox-aware Exec service, leaving capture/spill/promotion/background defaults intact.
2. Put model filesystem enumeration/reads in a fixed private Node helper launched through the current scoped Exec. It reads bounded bytes from open descriptors and searches each byte snapshot through fixed rg stdin children (up to four), with shared budgets and cancellation.
3. Human Desktop content search uses its existing current-project authority and pinned directory/file readers. It feeds only checked bytes to the same fixed stdin matcher. This is an explicit human file-reader authority, not a fallback around an unavailable model sandbox. No arbitrary command, file argument, preprocessor, config or network action is exposed by this reader.

## Global requirements and limits

- Node floor remains >=22.18; use existing declared platform/provider capabilities and fail closed for unavailable model confinement.
- Keep model glob's default returned100 and grep's default returned250; maxResults may be lowered or increased only within1000.
- Default/hard timeout30000ms (requested range100..30000), candidates1000, searched file-content input32MiB, per-file content input1MiB, combined serialized result hard256KiB, helper engine raw1MiB and outer runner raw1MiB, max four active rg children. Model returned-result default is32KiB to protect context; explicit maxResultBytes may choose4..256KiB. Human Desktop uses the256KiB bounded ceiling. These ceilings include result metadata/diagnostics, not just match strings. Requests may lower ceilings. The content-byte count is the bounded reader's physical file-content reads, not an invented count of rg's filesystem metadata/ignore discovery I/O, which is instead deadline/output bounded.
- Candidate paths/frame buffers are bounded256KiB; one pending JSON/NUL frame cannot exceed the raw cap. Diagnostic count16, each bounded; match/context preview text is cropped with an explicit textTruncated indication.
- Four-way reads reserve aggregate input allowance before awaiting I/O and reclaim unused reservation. A read request never exceeds its reservation or per-file remainder. Positive-length read returning0 proves EOF; hitting a limit without EOF is incomplete, even if a pre-read size happened to match.
- Engine raw admission (enumeration + all inner rg stdout/stderr) is capped independently from outer runner raw bytes. Clip crossing buffers before parsing/forwarding, discard/drain afterward, and stop all owned work. No producer may claim total child-generated bytes are capped, since OS pipes can already contain data.
- Desktop shares all budgets/deadline across project roots. Its pinned walker additionally retains the existing3000 entry/depth32 ceilings. Distinguish entries, candidate names, attempted/read/completed files and proven EOF; do not call matching-file JSON events a scan count.
- No same-name `rg` model tool, shell-string/xargs fallback, raw user flags, hidden export/allowlist workaround, remote paid request, real user-data deletion or old rejected-temp cleanup.

## Exec streaming contract

Add `ExecStreamRunOptions` with `stream: {maxBytes:number,onStdout(chunk:Buffer):void|'stop'}` and `backgroundAfterMs?:never`, and an explicit `run(cmd, options):Promise<ExecResult>` overload. Retain existing one-arg and promotion overloads. `ExecResult.stream` is optional and contains bytesRead/bytesAdmitted `{stdout,stderr}` and stopReason `consumer|output-limit|aborted|timeout`.

Streaming returns stdout empty; stderr retains every admitted stderr byte within the combined cap so existing runner classification remains meaningful. Raw buffers have no CRLF or chunkwise UTF-8 normalization. Callback errors trigger cleanup then reject. Abort/timeout/consumer/output stop is idempotent and awaits child close. In bounded mode only, POSIX spawn creates an owned process group (`detached:true`, piped stdio), so the existing negative-pid kill can cover the helper's children. Windows retains owned taskkill /T /F and waits for cleanup. Helper children stay in the group and await all closes; no `process.exit` with live children.

`createScopedExec` forwards all overloads explicitly and continues to apply current standing policy/cwd. Model helpers use `process.execPath` and a fixed shipped `.mjs` URL, bounded JSON input, and existing Electron Node-mode environment. Add a bounded raw-byte stdin option for the fixed matcher without widening model shell schema; preserve legacy string input. Disallow mixing string and raw input.

## Search options and public result

Shared serializable query: nonempty pattern (max4096 characters), mode `regex|literal`, case `sensitive|insensitive`, before/after context0..10, include/exclude arrays (<=16 patterns, each<=512 and combined<=4096 characters), hidden boolean, respectIgnore boolean, regexEngine `default|pcre2`, multiline boolean, encoding `auto|utf8|utf16le|utf16be|windows1252|latin1`, and bounded maxResults/maxResultBytes/timeout. Effective filter metadata distinguishes engine ignore from pinned project-ignore semantics. No arbitrary flags. Verify actual binary capabilities, returning an explicit unavailable/error for unsupported requested features.

Keep existing model pattern/path/include inputs valid; add new fields and an explicit description of Rust regex, filtering and limits. Model defaults preserve prior hidden/ignore choices (glob includes hidden/ignored; grep respects engine filtering) and disclose them in results. Model absolute/relative path convenience remains governed by current standing policy. Avoid whole-tree modified-time sorting in bounded enumeration; disclose discovery/arrival ordering and sort only retained Desktop rows.

Result retains `matches` and optional `error`, adds status `completed|limited|cancelled|timed-out|error`, partial/truncated booleans, reasons array, stats (candidateFiles, attemptedFiles, readFiles, completedFiles, eofFiles, inputBytes, engineRawBytes, runnerRawBytes), effective filters/limits and bounded diagnostics. A completed empty result is distinct from interrupted/limited/error emptiness. Exit1 is normal no-match; exit2 preserves valid matches and reports diagnostics. Invalid regex is validated by the same scoped rg with empty stdin even when there are no candidates; it is not validated with JavaScript regex. Validation stdin is excluded from file statistics.

Preserve whitespace in raw match text, removing only the declared record terminator for preview. Decode JSON text/Base64 correctly; invalid or unrepresentable file paths produce partial diagnostics rather than an empty/guessed navigable path. Use private per-file task identity to map stdin results to source paths; never trust `<stdin>` from rg as an original file. Context/multiline submatches become bounded line/range data. Convert transcoded UTF-8 byte offsets to UTF-16 code-unit positions in the displayed BOM-stripped/CRLF-normalized text; never use original rg bytes as editor offsets.

## Human Desktop authority, filtering and lifecycle

Add a separate capability `desktop-project-content-search` and project-file content-search/cancel/preview requests. Main owns selection `{workspaceId,sessionId?,projectId?}` and requestId; renderer labels/path lists do not grant access. Resolve current members, capture the real runtime, recheck after startup and before publishing/opening. The pinned root's final path must equal the catalog's stored canonical member path before capture; check leaf handle containment before reading and retain directory pins. Root/leaf replacement before and during capture must reject without reading outside bytes.

Main registers per-window/selection/request jobs before startup. The job stores captured runtime/subjob handles so cancellation still reaches owned work after membership withdrawal. Search/cancel are separate RPCs because dropping a Promise or stale result does not stop the server. Cancel checks original owner/request, not newly resolved membership; search/open/preview still require current membership. Unmount/replacement/timeout/window shutdown cancels and drains jobs. Backend deadline30s fits the current SDK60s default; keep drain bounded and cancel on request failure. Pinned reads request no extra over-budget probe byte: count==requested limit without proven EOF is partial; count<requested proves the reader reached EOF.

Human filtering explicitly supports `專案忽略檔`: bounded pinned `.gitignore`, `.ignore`, `.rgignore` in root/subdirectories, <=20 files/64KiB each, with defined per-directory precedence (`.rgignore` > `.ignore` > `.gitignore`), deeper rules and ignored-parent behavior. Use explicit maintained `ignore` and `picomatch` dependencies, not a hand-written gitignore imitation. This policy does not claim host-global git config/parent ignore behavior. Incomplete unreadable/oversized policy returns partial/error and is never silently treated as complete. Include/exclude and hidden controls operate on exact relative names; VCS/private/dependency exclusions remain disclosed. Candidate enumeration uses pinned human traversal; it never substitutes unchecked rg directory traversal.

## Desktop result navigation and preview

Add filename/content mode to the existing project explorer. Content mode has pattern, literal/regex and case controls; an Advanced disclosure holds context, include/exclude, hidden/ignore, engine/multiline/encoding and limits. Submit explicitly; provide Stop, loading, partial/limited/cancelled/errors and summary. Results group by current root label and retain `{workspaceId,path}`; click adds transient line/UTF-16 range/navigation nonce. Result paging is local over the bounded immutable returned set; a fresh query reruns against current files and is not a stable filesystem cursor.

Keep draft/tab identity exactly `{workspaceId,path}`. Normal editable UTF-8 files reuse the existing editor/draft/CAS save. Reveal the selected range once per navigation token, without moving the user's cursor on every keystroke. Preserve dirty drafts; disclose that on-disk match positions may differ from unsaved content. Do not replace a dirty draft with search preview.

For UTF-16/other supported encodings or normal reader unavailable/truncated cases, provide a bounded read-only pinned search preview with text, startLine, encoding, snapshot SHA, changedSinceSearch, readonly:true and truncation boundaries. The preview is centered on requested match with<=32KiB text; line gutter/selection uses startLine. It cannot save, create a revision, overwrite a draft or claim original-byte offsets. Revalidate root membership before preview and open, including formerly valid withdrawn roots.
