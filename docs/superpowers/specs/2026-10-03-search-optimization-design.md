## Approved implementation decisions

The design incorporates the user's external reference policy and the verified Windows provider capabilities. The sections below describe the implemented architecture.

**External reference policy.** The user explicitly clarified that projects/workspaces outside the active project are often supplied for analysis: external files may be read, but must not be modified. Provide a `參考位置（唯讀）` absolute-path input without registering it as a workspace or write root. Content search accepts optional top-level referencePath, mutually exclusive with project workspaceIds; reference results carry separate absolute reference identity with readonly:true/external:true, never a fabricated workspaceId or absolute ProjectFileRef.path. Dedicated external-read/external-preview routes accept top-level absolute path and existing selection/owner. They have no SAVE variant and do not ingest the editable draft store. Project-bound root/leaf aliases resolving outside may be intentionally read through pinned actual handles, but return readonly/external metadata. Preserve file identity, regular-file and byte validation; outside location alone is not a read-denial reason. SAVE/editable access still checks the original catalog canonical write root and opened edit handle containment, before any write. Absolute project SAVE and redirected external SAVE fail. Existing model absolute reads continue under current standing policy; no global Shell/FullAccess redesign or unproved OS-wide write guarantee is claimed by this search/file-viewer task.

**Confined sibling orchestration.** Actual Windows provider tests intentionally deny all second-generation CreateProcess attempts. The nested Node-helper→rg design would regress working workspace-write/read-only search, so it is replaced by first-generation siblings through current scoped Exec: rg enumeration; fixed no-spawn Node fd reader; fixed rg stdin matcher. Each operation is independently confined and owned/cancellable. The parent relays only bytes returned by the confined reader; it performs no filesystem stat/read bypass. Do not relax provider DACLs, use an unconfined fallback or accept a documented loss of ordinary search functionality. Four-worker and shared byte/deadline limits apply to this orchestration.

Reader stdout is bounded raw content relay charged to searched-content input32MiB/per-file1MiB, with bounded private EOF/read stderr metadata. It is not double-counted as JSON/result raw traffic. Keep enumeration and all matcher stdout/stderr under the aggregate1MiB engine raw cap before parsing; control/result runner traffic has its independent1MiB cap. Reserve reader allowances before concurrent operations. Reader helpers spawn no children. Model matching is serialized to enforce the shared stdout/stderr allowance with the existing Exec stream contract; at most four reader helpers are active. Human matching has at most four fixed stdin children. Sibling process close/drain and abort propagation remain mandatory, including Code Mode cell stop. The code-mode/runtime.ts correction only awaits actual owned termination/drain; CPU clocks/budgets and permission semantics stay unchanged.

True Latin1 decoding can expand a physical snapshot of at most1MiB into UTF8 stdin of at most2MiB. The raw stdin transport therefore accepts at most2MiB, with an actual near-boundary Latin1 fixture and rejection of the next byte. This derived transport allowance does not change the1MiB physical file bound,32MiB aggregate physical reads, result limits, or either1MiB raw result/control budget. Other encodings feed their original bounded bytes to rg.

## Evidence and approach

The shipped `@vscode/ripgrep` binary is rg 15.0.0 with PCRE2 10.45/JIT. Actual tiny probes confirmed matching-file-only JSON begin/end, partial stdout with exit2, UTF-16 BOM conversion, invalid UTF-8 Base64 records, and explicit-file `--max-filesize` bypass. Thus a result cap after full capture or a stat followed by direct rg file arguments is insufficient for hard read/output limits.

Use three composable units:

1. Add opt-in foreground raw streaming to the existing sandbox-aware Exec service, leaving capture/spill/promotion/background defaults intact.
2. Run model enumeration, fixed no-spawn descriptor readers, and fixed rg stdin matchers as separately confined first-generation commands through current scoped Exec. The parent reserves and relays bounded reader bytes, with shared budgets and cancellation, without filesystem stat/read calls.
3. Human Desktop content search uses current project membership and pinned readers, plus an explicit read-only reference location for an external file/folder. It feeds checked snapshots to the same fixed stdin engine. This human reader has its own authority; it exposes no executable, argv, preprocessor, config or model-sandbox fallback.

## Global requirements and limits

- Node floor remains >=22.18; use existing declared platform/provider capabilities and fail closed for unavailable model confinement.
- Keep model glob's default returned100 and grep's default returned250; maxResults may be lowered or increased only within1000.
- Default/hard timeout30000ms (requested range100..30000), candidates1000, searched file-content input32MiB, per-file content input1MiB, combined serialized result hard256KiB, engine raw1MiB and runner control/result raw1MiB. Model readers use at most four workers with one active matcher; human matching uses at most four children. Model returned-result default is32KiB to protect context; explicit maxResultBytes may choose4..256KiB. Human Desktop uses the256KiB bounded ceiling. These ceilings include result metadata/diagnostics, not just match strings. Requests may lower ceilings. The content-byte count is the bounded reader's physical file-content reads, not an invented count of rg's filesystem metadata/ignore discovery I/O, which is instead deadline/output bounded.
- Candidate paths/frame buffers are bounded256KiB; one pending JSON/NUL frame cannot exceed the raw cap. Diagnostic count16, each bounded; match/context preview text is cropped with an explicit textTruncated indication.
- Four-way reads reserve aggregate input allowance before awaiting I/O and reclaim unused reservation. A read request never exceeds its reservation or per-file remainder. Positive-length read returning0 proves EOF; hitting a limit without EOF is incomplete, even if a pre-read size happened to match.
- Engine raw admission (enumeration + all matcher stdout/stderr) is capped independently from runner control/result raw bytes. Reader file-content relay is charged to physical input instead. Clip crossing buffers before parsing/forwarding, discard/drain afterward, and stop all owned work. No producer may claim total child-generated bytes are capped, since OS pipes can already contain data.
- Desktop shares all budgets/deadline across project roots. Its pinned walker additionally retains the existing3000 entry/depth32 ceilings. Distinguish entries, candidate names, attempted/read/completed files and proven EOF; do not call matching-file JSON events a scan count.
- No same-name `rg` model tool, shell-string/xargs fallback, raw user flags, hidden export/allowlist workaround, remote paid request, real user-data deletion or old rejected-temp cleanup.

## Exec streaming contract

Add `ExecStreamRunOptions` with `stream: {maxBytes:number,onStdout(chunk:Buffer):void|'stop'}` and `backgroundAfterMs?:never`, and an explicit `run(cmd, options):Promise<ExecResult>` overload. Retain existing one-arg and promotion overloads. `ExecResult.stream` is optional and contains bytesRead/bytesAdmitted `{stdout,stderr}` and stopReason `consumer|output-limit|aborted|timeout`.

Streaming returns stdout empty; stderr retains every admitted stderr byte within the combined cap so existing runner classification remains meaningful. Raw buffers have no CRLF or chunkwise UTF-8 normalization. Callback errors trigger cleanup then reject. Abort/timeout/consumer/output stop is idempotent and awaits child close. In bounded mode only, POSIX spawn creates an owned process group (`detached:true`, piped stdio), so negative-pid termination covers the owned group. Windows retains owned taskkill /T /F and waits for cleanup. All owned commands reach close before the search settles; the fixed reader starts no descendants.

`createScopedExec` forwards all overloads explicitly and continues to apply current standing policy/cwd. The reader uses `process.execPath`, a fixed shipped `reader.mjs` URL, bounded JSON input and existing Electron Node-mode environment. The bounded raw-byte stdin option serves the fixed matcher, including the derived Latin1 allowance above, without widening model shell schema; legacy string input remains. Mixing string and raw input is refused.

## Search options and public result

Shared serializable query: nonempty pattern (max4096 characters), mode `regex|literal`, case `sensitive|insensitive`, before/after context0..10, include/exclude arrays (<=16 patterns, each<=512 and combined<=4096 characters), hidden boolean, respectIgnore boolean, regexEngine `default|pcre2`, multiline boolean, encoding `auto|utf8|utf16le|utf16be|windows1252|latin1`, and bounded maxResults/maxResultBytes/timeout. Effective filter metadata distinguishes engine ignore from pinned project-ignore semantics. No arbitrary flags. Verify actual binary capabilities, returning an explicit unavailable/error for unsupported requested features.

Keep existing model pattern/path/include inputs valid; add new fields and an explicit description of Rust regex, filtering and limits. Model defaults preserve prior hidden/ignore choices (glob includes hidden/ignored; grep respects engine filtering) and disclose them in results. Model absolute/relative path convenience remains governed by current standing policy. Avoid whole-tree modified-time sorting in bounded enumeration; disclose discovery/arrival ordering and sort only retained Desktop rows.

Result retains `matches` and optional `error`, adds status `completed|limited|cancelled|timed-out|error`, partial/truncated booleans, reasons array, stats (candidateFiles, attemptedFiles, readFiles, completedFiles, eofFiles, inputBytes, engineRawBytes, runnerRawBytes), effective filters/limits and bounded diagnostics. A completed empty result is distinct from interrupted/limited/error emptiness. Exit1 is normal no-match; exit2 preserves valid matches and reports diagnostics. Invalid regex is validated by the same scoped rg with empty stdin even when there are no candidates; it is not validated with JavaScript regex. Validation stdin is excluded from file statistics.

Preserve whitespace in raw match text, removing only the declared record terminator for preview. Remove a BOM only at the beginning of the whole file; retain embedded U+FEFF in later lines and context. Decode JSON text/Base64 correctly; invalid or unrepresentable file paths produce partial diagnostics rather than an empty/guessed navigable path. Use private per-file task identity to map stdin results to source paths; never trust `<stdin>` from rg as an original file. Context/multiline submatches become bounded line/range data. Convert transcoded UTF-8 byte offsets to UTF-16 code-unit positions in the displayed BOM-stripped/CRLF-normalized text; never use original rg bytes as editor offsets.

## Code Mode composition and context economy

The user additionally emphasized existing Code Mode as a way to reduce token/context use. Search remains the same registered tool and current-policy broker path in mixed/only modes, including deferred discovery and role restrictions. A cell can consume bounded structured results, filter/group/deduplicate them and emit only selected path/line evidence; these operations do not justify bypassing search/read/result limits. Direct model calls use the32KiB result default; explicit larger4..256KiB requests inside Code Mode remain capped and may be reduced by current output-retention rules. Do not change global retention simply to force a demo.

Verify actual Code Mode search/filter composition and model-visible emitted output versus owned nested traces. The current mixed/only workspace-write fixture uses20 files ×12 rows:240 nested matches are retained, while grouping emits ten references in less than1000 bytes. Saving token/context is conditional on emitting less content; no percentage or guaranteed saving is claimed. Stopping a cell during its owned search propagates broker ToolExec.abortSignal through the separately confined readers and matchers, preserves permission/authority checks, and produces no late resurrection or follow-on tool call.

## Human Desktop authority, filtering and lifecycle

Add capability `desktop-project-content-search:1` and project-file content-search/cancel/search-preview/external-read/external-preview requests. Main owns selection `{workspaceId,sessionId?,projectId?}` and requestId; renderer labels do not grant project write access. Resolve current members, capture the real runtime, recheck after startup and before publishing/opening. Pin the observed canonical read target and require the opened handle identity to match the target checked before open. Retain directory pins and regular-file checks. An intentionally selected external reference or alias returns readonly/external metadata; an unexpected identity replacement fails before reading its bytes. Save still requires the original catalog canonical write root and actual edit-handle containment.

Main registers per-window/selection/request jobs before startup. Optional client requestId on preview/reference-read requests supports owned cancellation on replacement, unmount and request failure. Captured runtime/subjob handles remain available after membership withdrawal; cancellation checks the original owner/request and waits for drain before acknowledgement. Project save/remove and session ownership mutation boundaries revalidate captured scopes and drain affected jobs, including a job already stopped but still draining; unchanged scopes continue. The renderer refreshes its root cache when current IDs or paths change. Backend deadline30s fits SDK60s. Window shutdown cancels and drains every owned search/read/preview. Pinned reads request no extra over-budget probe byte: count==requested limit without proven EOF is partial; count<requested proves the reader reached EOF.

Human filtering explicitly supports `專案忽略檔`: bounded pinned `.gitignore`, `.ignore`, `.rgignore` in root/subdirectories, <=20 files/64KiB each, with defined per-directory precedence (`.rgignore` > `.ignore` > `.gitignore`), deeper rules and ignored-parent behavior. Use explicit maintained `ignore` and `picomatch` dependencies, not a hand-written gitignore imitation. This policy does not claim host-global git config/parent ignore behavior. Incomplete unreadable/oversized policy returns partial/error and is never silently treated as complete. Include/exclude and hidden controls operate on exact relative names; VCS/private/dependency exclusions remain disclosed. Candidate enumeration uses pinned human traversal; it never substitutes unchecked rg directory traversal.

## Desktop result navigation and preview

Add filename/content mode to the existing project explorer. Content mode has pattern, literal/regex and case controls; Advanced holds context, include/exclude, hidden/ignore, engine/multiline/encoding, limits and `參考位置（唯讀）`. Submit explicitly; provide Stop, loading, partial/limited/cancelled/errors and summary. Project hits group by current root label and retain relative `{workspaceId,path}`. Reference hits use separate absolute readonly targets and a transient viewer, with no workspace registration or editable draft. Click adds transient line/UTF-16 range/navigation nonce. Result paging is local over the bounded immutable returned set; a fresh query reruns against current files and is not a stable filesystem cursor.

Keep draft/tab identity exactly `{workspaceId,path}`. Normal editable UTF-8 files reuse the existing editor/draft/CAS save. Reveal the selected range once per navigation token, without moving the user's cursor on every keystroke. Preserve dirty drafts; disclose that on-disk match positions may differ from unsaved content. Do not replace a dirty draft with search preview.

For UTF-16/other supported encodings or normal reader unavailable/truncated cases, provide a bounded read-only pinned preview with text, startLine, encoding, snapshot SHA, changedSinceSearch, readonly:true and truncation boundaries. Text is at most32KiB in both UTF8 and UTF16 storage and is centered on the requested line. Invalid or incomplete encoded prefixes display an explicit replacement-character warning even when the preview is not truncated. The gutter/selection uses startLine. The viewer cannot save, create a revision, overwrite a draft or claim original-byte offsets. Revalidate the current project binding before preview/open, including a formerly valid withdrawn root.
