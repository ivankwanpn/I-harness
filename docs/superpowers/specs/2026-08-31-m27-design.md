## 1. R-A3 崩潰恢復修復鏈（M）

**目標**：載入時修復 torn tail + 打開未閉的 turn + 缺失 tool result 合成——dsh `core/session/src/repair.ts`（interruptedTurnClosers 合成 closers + missing tool error）語義。

**機制源**：dsh repair.ts；codex backfill（啟動掃描/重建）。
**IH 化**：
- `session-persistence` 載入閘後：讀到最後一個 `turn/start` 無配對 `turn/end` → 合成 closed-markers（`step/end`+`turn/end`+`agent/error`? 用 `turn/end` + log-only 標記）。
- 缺失 tool/result：最後一個 `tool/call` 無 `tool/result` → 合成 `tool/result`(error: TOOL_INTERRUPTED? 沿用 M10a TOOL_TIMEOUT 語義 → `tool/result` output `{ error: "TOOL_ABORTED_BEFORE_DISPATCH" }`——M10a 已有先例)。
- 與現有 torn-tail 修補（write-behind/backend repair）不同：這是 **log 語義修復**（closers），不碰檔案層。
- 邊界：只修「最後一個打開序列」；已閉檔不碰；失敗 → fail-closed（保留原 log+報錯,不靜默改寫）。
- 測試：構造 torn session(JSONL 手工截斷/事件序列缺 closers)→ load → 斷言 repair 後 log 關閉且 deriveMessages 可投影。

## 2. R-A8 上下文預算工具（S）

**目標**：模型可查剩餘上下文預算（codex `get_context_remaining` + `#context` token 佔位）。
**IH 化**：新工具 `context_remaining`（或名 `get_context_remaining`）掛 core-tools 目錄：
- 響應：`{ window: number, used: number, remaining: number, percentage: number }`——估算源 = `@i-harness/token-meter` 的 `estimateTokens` + AgentDeps 的 contextWindow（M15 catalog 已有 per-model window）。
- `#context` 特殊 token：system prompt 區段（動態區已有 A4 快照機制——在動態 context 區加一行）。
- fail-closed：無 token-meter 或無 window 知識 → 工具禁用（不在目錄）。
- 測試：mock session 事件流 → 斷言估算與窗口響應；語法佔位替換。

## 3. R-B6 skills 影子選擇器 + 隱式調用 policy（M）

**目標**：codex shadow selector（離線對照：BM25/ngram 檢索器選中哪些技能）+ 隱式調用 policy 門控（`allow_implicit_invocation`）。
**IH 化**：
- 影子模式：在 `skills` 包內加「selector 報告器」——每次 skill_search 查詢同時跑候選檢索器（BM25 現有 + 特定抽取器），產出「若用 X 會選中哪個」報告（telemetry 事件 `skill/selector-shadow`，不改變行為、無副作用——確定性）。
- 隱式 policy：`skills` 註冊表加 `allowImplicitInvocation`(來源:plugin-registry 的 plugin manifest 或 settings)——`false` 時僅 `skill_get`（顯式調用）可用。
- 插件技能根：plugin-registry materialize 已產 `skills/<id>` 目錄 → skills 發現器加「plugin 層」來源（M26 E4 已做 overlay——檢查其發現器是否接受該目錄根,補測試）。
- 測試：影子報告斷言（查詢→報告事件）；policy 門控行為開關。

## 4. R-C4 stdio 外部 SDK（M）

**目標**：NDJSON JSON-RPC 2.0 stdio 子進程 SDK——dsh `sdk/protocol+client+server` / codex TS SDK 形狀。
**IH 化**：
- 新包 `packages/sdk`（`@i-harness/sdk`）三子檔：
  - `protocol.ts`：`JsonRpcLineTransport`（NDJSON frame, -32700 等錯誤碼, malformed 忽略）+ `initialize`/`session/prompt`/`shutdown` requests + 通知 `session.event`/`session.status`。
  - `server.ts`：掛在 `SessionService`（C 區產物）——`@i-harness/sdk/server` 入口:spawn 一個 `cli web` 等價裝配? 不——**in-process server 形態**:`createSdkServer(SessionService)` 返回 JSON-RPC 處理器;`cli` 產 `i-harness sdk` 子命令(stdi io 直通)。
  - `client.ts`：`run(input, opts)`/`session(id)` 高層 API（spawn `i-harness sdk` 子進程 → handshake → stream）。
- 事件形態：`session.event` 通知承載 telemetry 事件（已 13+ 碼;C6 已擴——直接序列化）。測試用回環（in-process caller? client 的 spawn 需要 sdk 子命令;測試用 child_process + 真裝配 mock 模型）。
- Windows 優先（stdio 無洞跨平台）。
- 依賴：零新增（node:child_process/stdio）。

## 7. H-2 node-pty 噪聲壓制（S）

**目標**：每 PTY kill 刷 `Error: AttachConsole failed`（node-pty conpty_console_list_agent win32 quirk,exit 0）。
**IH 化**：terminal 包 spawn 時掛 `process.stderr`?—— 不:那是 node-pty 內部 fork 的輸出;壓制:在 `kill()` 前訂閱/或 ignore 匹配該訊息的 stderr 透過 env `TERM`? 現實方案:**包裹 spawn 的 stderr tap**(node-pty SpawnOptions 無;用 `pty.process` 的 stderr?node-pty 無 stderr 暴露)——用**事件替身**:依賴上游 fix 或 monorepo patch?最實際:**在 windowsPlatform 的 spawn 後 add `process.on`?**不行。
**更乾淨**:調研確認錯誤來源(conpty_console_list_agent 是 fork 的 agent 進程,其 stderr 繼承父)——若繼承父進程 stderr 到 dev/null 或 filter:在 terminal 包 spawn **前** redirect?不可行(全進程)。
**落地方案**:wrapper:terminal 包在 `attachConsole` 前設 `process.env`?—— 標記「**調整為:僅在 win32 + 診斷日誌中 suppress 匹配該模式的 stderr 行(在 TerminalService 的錯誤匯報路徑中過濾)**」:即 PTY 的錯誤回報(若包含 AttachConsole failed)標記為已知噪聲並排除在工具錯誤輸出外。加註釋指向 upstream issue。**如果調研發現完全無法攔截 → 記錄為 upstream 等待,降為文檔註記**。spec 中標明這項的「可變實現」屬性與上游依賴。
