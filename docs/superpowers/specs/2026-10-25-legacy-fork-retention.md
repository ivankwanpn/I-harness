# Legacy fork retention owner design

Status: root-approved F1-L1 owner slice, 2026-10-25. This consumes accepted F1-L0 at MAIN2e5a8ae9. It does not complete public SDK/CLI/Gateway/Desktop fork callers. The root rulings below resolve the earlier draft proposals.

## Scope, files and deliverable

One writer owns `context-output/src/{types,index,service,store}.ts`, cohesive new `legacy/{fork-types,fork-codec,fork-pages,fork-transfer,fork-disposition,observed-read}.ts`, necessary `legacy/query.ts` bounded size counting, and tests. Keep each new module responsible for its named owner concern; no generic registry/framework or second quota/store. Store remains the canonical file/maps/SQLite owner, not a facade over a new persistence layer.

Add a narrow core structural companion `core-session/src/conversation/seed-retention.ts` plus its existing index export/internal seed-selection reuse: derive typed legacy ref coordinates and child anchors using the same B1 boundary/branch/turn selection metadata. It cannot render/export payload or change B1 codecs. The L1-13 read-only preparation facts extension is the only B2 change; no new bootstrap transaction, receipt owner or persisted format. Integration tests consume actual persistence/B2/F0 and actual ContextOutput services; production public-fork controller and actual host read wrappers are F1-C responsibilities. No assembly/model/instruction edits in L1.

Deliverable: host-only transfer APIs which bind to an actual B2 reservation, publish selected legacy membership, reconcile cold original effects and enforce observed read/search, clear/delete/TTL and quota. A real B2 positive reaches READY then reads/searches retained legacy data after source.clear/close and cold reopen. This is owner-slice acceptance; no shipping public-fork or whole B2.3 credit.

## Closed data and actual interfaces

Existing BootstrapInvocation, completed selection, safe identity/clock/digest rules are reused. All records reject extra/undefined/accessor/symbol/invalid fields. IDs/coordinates use existing bounded identity rules; original descriptor strings are never bounded by a new8192/64KiB policy cap. Full metadata hash streams lexical/data-only ContextResultRef through `streamJsonData`; domain is `ih.legacy-ref.metadata.v1\0`, byte count excludes domain. Do not join strings, clone descriptor objects or substitute body revision for metadata hash.

```ts

  metadataDigest:string; metadataEncodedBytes:number; expiresAt:number }
type LegacyAnchor = {kind:'manifest';seq:0}
  | {kind:'seed-group';manifestSeq:0;ordinal:number};

  turnDomainDigest:string;totalTurns:number;unframedPrefix:boolean }
```

`planDigest=SHA256(domain+'\0'+canonical bounded root)`; use separate fixed domains `ih.legacy-fork.binding.v1`, `.page.v1`, `.plan.v1`, `.applied.v1`, `.disposition.v1`. Root embeds full binding; applied and dispositions verify their hashes against it. Target IDs equal invocation.targetSessionId; targetDocumentId equals targetSessionId. Repeated ref IDs require identical full commitment tuples; preserve repeated original observations as rows, grant each distinct ref only once. Empty selection requires an exact empty root/applied, never absence interpreted as empty.

Add the following **host-only**, non-tool/non-wire service APIs, exported at the existing ContextOutput entry. Opaque scopes are registered in the existing service lifetime; no caller-shaped object is accepted as an issued scope:

F1-C must construct actual CLI/Gateway services with true and wire their real tool read/search wrappers. ## Namespace, pages, binding and warm prefix continuation

Under actual `ContextStore.directory`, use `legacy-fork-v1/<H(full invocation)>/{binding.json,pages/<level>-<firstRow>.json,plan.json,applied.json,revoke.0,revoke.1}`. binding.json is `{version:1,kind:'legacy-fork-binding',binding}`; it fixes one actual manifest before any page. A different binding/hash or foreign pending sibling conflicts. Expiry slots are `legacy-expiry-v1/<refId>/<metadataDigest>/{expiry.0,expiry.1}`. Use existing owned-path/exact immutable pending publication primitives for bounded JSON; never use random temp rollback as original transfer reconciliation.

No plan/page/owner publication occurs during registration or before B2 provides its **actual** manifest. Host targetPreparation.confirm first performs existing project/F0 preparation and validates coordinator.inspectBootstrap's original reservation+manifest; then calls confirmLegacyForkTransfer with that request, under the original callback lifetime. ContextOutput compares exact invocation and binds manifest once. It cannot compute a surrogate manifest from source labels or caller digest. B2 remains final receipt owner; inspection is only identity evidence. Dependencies keep their accepted managed closure/digest; legacy confirmation belongs to targetPreparation, including the empty managed-artifact case.

Leaves≤100 rows, directory fanout1..100 with uniform decreasing levels (only a one-child whole root collapses), root/page encoding≤64KiB; counts/ranges/levels/digests/EOF are strict and safe. No total-ref cap and no unbounded root hash list. A leaf contains only bounded commitment/address fields, so long source metadata does not enlarge it. Stream source observations deterministically by typed source coordinate and inherited parent row ordinal, preserving exact order; bounded directory frontier plus derived SQLite staging can track distinct-ref consistency. No complete rows array or encoded full plan in memory. Charge all staged/pending/final bytes to the actual L0 physical quota.

Structural companion reuses B1 resolveSeedBoundary/selectSeedHistory/historyTurns/historyVisibility. Local candidates are only actual typed context/result-ref facts within the same completed window/current branch; metadata after turn/end but before next turn/start follows the existing boundary. Map framed extents to a sound selected B1 group anchor; unframed prefix may use manifest anchor. Duplicate/ambiguous seq, straddling or unrepresentable anchor refuses. Nested live observations come from verified source plan/application/current canonical membership and actual manifest; rebase extents/anchors using the same metadata selection, retain original coordinate and immediate via. No text sniff, raw prefix copy, source ancestor archive replay or native carrier permission.

Freeze helper name `createLegacyRetentionSelection(view:SessionView,selection:Extract<SeedSelection,{kind:'completed'}>)`. It returns `{kind:'refused',reason:SeedRefusal|'legacy-anchor-unsupported'}` or `{kind:'selected',turnDomainDigest,totalTurns,unframedPrefix,local():Iterable<{ref:Extract<SessionEvent,{type:'context/result-ref'}>['ref'],original,extent,anchor}>,inherited(extent:TurnExtent,anchor:LegacyAnchor):{kind:'omitted'}|{kind:'included',extent,anchor}|{kind:'refused',reason:'legacy-anchor-unsupported'}}`. Core defines these structural shapes without importing ContextOutput. Domain digest streams the selected B1 turn-domain metadata with `ih.legacy-fork.turn-domain.v1\0`. It is a metadata selector, not an exporter/compiler; future F1-C consumes the same helper. Registration captures SessionView/AbortSignal/functions by validated host descriptors without recursively treating them as JSON or cloning managed proxy data; persisted records use the closed JSON codecs only.

Warm partial-page retry is explicit: registration may be newly acquired, but host must retain the **same actual original source witness** and immutable original operation/B2 request. Validate identity/count/readiness and current policy before rewalking. Rebuild only structural selection metadata and stream ContextResultRef commitments; validate every existing bound page prefix against the newly generated exact page bytes before continuing its pending/missing suffix. A final directory/root must match all original pages/counts. This pure metadata walk may start at row0; it never calls a producer, B1 payload export/render/compile, model/tool/input or changed-source reconstruction. No original source witness => no warm writes, even if persisted count/digest appears equal. Unchanged source with changed actual store metadata also blocks. Keep source guards current across all awaits.

Cold/source-absent reconcile only walks existing exact final binding/pages/root/applied/dispositions, validates EOF/counts, and checks canonical target membership/current scope. It does not fill pages/directories/root/application/owners, select refs or call source hooks. Binding/pages without applied are incomplete, not empty/ready. B2 missing semantic payload remains payload-required even if legacy pages are complete. Known original capture/cache never takes new capture; truly absent/new policy remains F1-C's accepted B2+legacy absence routing.

## Confirm algorithm and unknown publication

Confirm acquires the ready L0 store outside quota, validates scope/request and walks metadata/current source authorization outside service serial/quota where callbacks might recurse. Actual source observation is already captured; private membership/visibility checks use only pure guards and store metadata, never authorize/public-service recursion. Register the whole attempt before its first await; it remains joined through cleanup. Stage bounded binding/pages under shared mutation turns with before/after guards. Do not hold quota while resolving a host observation or starting a legacy open.

After complete root/EOF/anchor validation, stream distinct refs again from confirmed pages: compare full streamed selected-versus-actual metadata digest/size/id/revision/expiry, check actual canonical readable membership/current source observation, and verify body integrity with bounded reads/hash (no full body copy for fork). Recheck before each target publication. All reserve slots described below must exist/fund before the first target owner addition. Add target to **current canonical owners.json** under L0 turn, preserving unrelated current owners; use durable sync/readback. Existing addOwners rollback is not this protocol.

After all canonical target owners confirm, publish/confirm bounded applied bindingDigest+planDigest+counts. Reconcile applied against canonical state; never infer it from SQLite or reconstruct missing owners from it. If any I/O was issued but confirmation fails, keep exact original records/lease debt and return unknown. TargetPreparation returns confirmed only after actual applied confirmation + target guard, then B2 may issue seed/completion. A source/target guard failure permanently invalidates this scope, not the underlying grant data.

Owner-ledger unknown write: current target present can confirm its effect; absent target/no disposition is incomplete. Warm authorized continuation may merge that same original target into current owners. Never replay an old whole-owner-array image over source.clear/another target's updates; continue an old pending image only if its expected prior ledger still matches, otherwise use a freshly authorized merge or block. Passive never adds. Plan/application missing or only pending blocks; no constant confirmed port or receipt reconstructed from target ID.

## Funded monotone disposition slots, clear/delete and TTL

**Freeze physical reservation, not a second logical quota:** before any target owner addition, allocate and sync/read back two fixed-size slot files for this grant's root revocation and two for each distinct committed ref's expiry tuple (existing exact tuple may be shared). Slot capacity is computed from the **actual bounded binding/commitment and maximum encoding of its finite disposition variants**, including checksum/header/padding; it is not64KiB per ref or an arbitrary allowance. Include both slots, their paths and plan metadata in the existing physical inventory. Real allocated zero bytes count as physical file size; no sparse/intended reserve claimed as funding. Quota/IO refusal before all slots exist leaves no new target grant.

Slot0 initially contains checked generation0/live payload; slot1 is exact zero reserve. Disposition changes once to generation1/revoked or expired by writing only inside the already-funded inactive slot, fsync then exact readback/checksum. It never grows/truncates files or needs an unreserved temp copy. Existing immutable JSON helpers remain for immutable records; add only this small fixed-slot disposition codec/IO in fork-disposition.ts. Nonzero torn/foreign generation1 is unknown and fences access/regrant; do not fall back to older live slot. Retry with actual clear/delete/TTL authority completes the exact original tuple; neither application nor index rebuild resolves unknown disposition to live. Logical generation1 is permanent; files are not reused for a different grant/ref.

Root revoke payload is `{version:1,kind:'legacy-fork-revoked',bindingDigest,planDigest}`. Expiry payload is `{version:1,kind:'legacy-ref-expired',workspaceId,refId,revision,metadataDigest,metadataEncodedBytes,expiresAt}`. Bind slots to these tuples; immutable marker identity cannot be borrowed by a recapture with same body revision but changed metadata/expiry. Expiry can acknowledge historical applied grants after manifest/body GC, but cannot read/regrant or recreate owners. Missing live manifest without exact expiry disposition blocks.

Service clear/global clear runs its existing L0 transition, closes admission to affected attempts and joins them before owner turns. For each affected transfer **target**, commit revoke before removing its canonical owner/SQLite rows/bytes; source.clear removes that source's own ownership and does not revoke grants to other targets. Legacy deletion integrates into the existing documentDeletions subscription alongside managed releaseDocuments: synchronously mark deleted/retire scopes, join original attempts, then revoke matching targets under shared turn before legacy owner removal. Preserve independent managed cleanup attempts; no nested owner.mutate from an already-held turn.

Prune/remove paths first write exact expiry for each referenced commitment when expiry is the cause, then remove canonical legacy data according to existing expiry semantics. Source-less owners still require strict observed-recipient enforcement. Empty owner ledgers stay authoritative tombstones; application never recreates owners. A new raw capture with same refId/body revision after expiry has different metadata commitment and cannot revive the old grant. Temporary project/broker revocation, Stop or host-scope ABA is **not** a persisted clear/delete tombstone: old scope remains invalid, but a new real authorized scope can requalify preserved grants when canonical binding/targetSourceDigest still matches. Persist no ephemeral revision that prevents legitimate cold/reconfigured reads.

Each created disposition slot's funded capacity is included in plan/application validation. `configureDiskBudget` cannot lower below existing physical storage/reserves; fixed slot mutation never creates fresh quota demand during clear. Filesystem failure still returns unknown; reserving bytes is not a guarantee against device errors. Garbage collect obsolete plan/slot metadata only after actual target deletion/tombstone and no dependent inherited record needs it; L1 may conservatively retain it under quota. No background eviction/second quota accounting is introduced.

## Ordinary read/search, startup and close

Public unobserved read/search in strict mode denies noncreator access before owns. Observed path requires actual READY binding for semantic-fork recipients, exact plan+applied/page proof, canonical current target owner, no revoke/expiry, actual targetSourceDigest/current scope and branch-visible anchor. Creator/local raw refs follow their existing policy through localVisible; a source-less inherited ref cannot bypass membership. Missing hint/root cannot select old owner shortcut. Deny before returning body even when plan/partial owner grant exists pre-READY. Empty managed closure supplies no legacy proof.

Private lookup is a ContextStore metadata read: no run/serial/mutate, grant, authorize, visibleRefsFor or host scope lookup. Derived SQLite hint `(complete binding,refId)->leaf,row,path` only locates candidates; verify root/page hashes and actual metadata commitment/canonical ownership/disposition. A missing/stale hint denies or triggers a bounded owner-controlled metadata rebuild outside the read job, never permits bypass. Actual host captures read observation before invoking readLegacyObserved/searchLegacyObserved, keeps current callbacks alive, and performs any fresh async archive/metadata policy checks before/after the service job rather than inside quota/job callbacks.

Startup under L0 lifetime/shared turn loads/validates original roots/dispositions, canonical arrays and actual manifests before pruning transfer-related data, then rebuilds the same SQLite index/hints. Do not synthesize an owner from plan/applied. Unknown/corrupt roots cannot justify GC; fail relevant recovery/prune rather than silently shortening membership. Ref metadata comes only from actual live manifest, not plan reconstruction. Search keeps existing candidate/result/byte budgets and partial reasons; use streaming size counting to reject a metadata-heavy hit without constructing a giant serialized descriptor. No maxReadBytes/schema cap on retention.

Service close synchronously retires new transfer/read-scope admission, aborts guards and joins each original attempt/slot/publication before L0 store/shared owner closes. closeLegacyForkTransfer retires capability then joins its attempts; no missing grant/page work is performed by close. Retain cleanup debt and original outcome on failure. Host F0/project callback must await scope close before exiting; no guard survives callback. No model/action/received-input/settlement source is created for a fork.

## Funded canonical owner-ledger replacement

Disposition slots alone do not fund canonical owners.json replacement. **Use a pre-funded per-ref rewrite file plus a temporary hardlink predecessor**, preserving valid canonical JSON and actual allocated rewrite capacity across the rename crash cut. A reserve-only rename→recreate sequence is insufficient: after a crash another managed writer could consume the freed quota before recreation. The predecessor keeps that storage present; no owner array is limited to64KiB or passed to boundedJson/immutable JSON helpers.

For each L1-tracked ref use existing `owners/<id>.json` plus `<id>.rewrite` and temporary `<id>.previous`, with a small original rewrite intent bound to ref/operation, expected prior/next **semantic array** hashes/counts and capacities. Hash/size and write owner arrays through streaming JSON over current owner IDs; no giant JSON string and no stale whole-array rollback. Intent contains no second owner array. All tracked-ref mutators, including ordinary addOwners/source restoration/clear, route through this one ContextStore writer once installed; an unrelated grant cannot silently outgrow its funded reserve.

Before a new owner addition, fund capacity C=max(current canonical file bytes,next encoded owner-array bytes): extend the old canonical file only with JSON whitespace, sync/read back, and allocate/sync rewrite capacity C. Both files are physically present before grant; partial whitespace append leaves the old array valid. Reserve required small journal/disposition bytes too. Insufficient actual quota refuses before the owner addition. Shrinking owner removal needs no larger array or file. Ownership/currentness checks remain those of L0 and the original transfer, not reserve filenames.

Commit under one L0 turn: (1) confirm actual old array/intent and both capacities; (2) create `<id>.previous` as an actual hardlink to canonical and verify device/inode identity; (3) stream the new array into rewrite, pad only with JSON whitespace to C, fsync and validate full semantic hash/EOF; (4) atomically rename rewrite over canonical; (5) verify new canonical semantics and that previous is now a distinct old inode; (6) rename previous to rewrite, reusing that already-allocated old file as the next scratch reserve. Never alter previous while it still aliases current canonical. The canonical name always denotes a complete valid owner array, so a crash cannot lose unrelated owners through a half-written replacement.

**One necessary shared-quota adjustment:** physical inventory must count a hardlinked file's bytes once by its actual device/inode, not once per directory entry; add this narrowly to existing `artifact/quota.ts` inventory, with real hardlink tests. Otherwise a metadata alias falsely requires another full ledger's quota. This is the same physical inventory/owner, not a second quota or logical reservation scheme. Before swap, current+previous are one inode and rewrite another; after swap, new canonical and previous are the two distinct funded inodes. There is never a gap in the two-file capacity for another writer to consume. If reliable hardlink identity/creation is unsupported, refuse tracked transfer setup before any owner addition; do not replace the predecessor with an unfunded copy.

Crash/readback states are exact: canonical=prior, previous aliases it, rewrite partial/complete ⇒ original pending replacement, no committed new array; passive never finishes it. Canonical=next, previous distinct, rewrite absent ⇒ owner replacement committed; retain journal and move that exact previous file to rewrite during actual owner recovery/cleanup, without adding owners or allocating data bytes. Canonical=next with reserve restored ⇒ verify then finish journal cleanup. Any hash/inode/alias ambiguity fences further mutation and returns original unknown; no arbitrary file wins by mtime. Warm grant continuation still needs its actual original source capability; completing storage cleanup alone confers none. Applied may publish only after canonical additions and reserve restoration confirm. Passive may observe an already committed owner effect but cannot publish missing applied/new grant work.

After a successful shrinking replacement, reclaim surplus in safe order: truncate **only verified trailing whitespace** of new canonical to its exact encoded length, sync; then shrink the independent rewrite reserve to that length, sync. A crash between them leaves reserve≥canonical capacity. Semantic hashes exclude only trailing JSON whitespace, so this reclamation cannot masquerade as a changed owner set. Do not truncate reserve first or zero-extend a canonical JSON file. Failed phase/IO/lease cleanup remains attached to its original intent until actual confirmation; reserve restoration must not be hidden by L0's swallowed serial tail.

Normalize permission revocation to one payload `{version:1,kind:'legacy-fork-revoked',bindingDigest,planDigest}` for target-clear/delete/global-clear. Cause may be diagnostic evidence, not a permission field. Exact revoked bytes are deterministically reconstructible from original binding/plan, so a cold partial inactive slot does not depend on recovering a lost reason string. Nonzero invalid slot remains unknown; an actual clear/delete request may complete the same deterministic payload, passive read/adoption cannot write it. Ephemeral project revocation still does not create this tombstone.

Directory correction: allow **1..100 children**, uniform child level exactly parent.level−1 and contiguous ranges, including a rightmost single-child directory; collapse a one-child root only when it is the entire tree.101 leaf pages must form level1 directories of100 and1, then a level2 root with2 children. Do not force collapse of the rightmost node and produce mixed levels. Add a10001-observation page control (may reuse one valid ref with distinct typed source coordinates), plus missing/rightmost/truncated-page refusal.

Additional files/tests are limited to the existing quota inventory and cohesive private owner-ledger rewrite helper/test. Required causal cuts: full configured quota with actual remove-owner rewrite; huge owner array above64KiB; grant growth refusal before publication; crash immediately before/after canonical rename and before reserve reuse; other managed writer after that crash cannot consume held rewrite capacity; whitespace reclamation cut; hardlink unsupported/foreign alias; unrelated-owner preservation; revoke confirmed but ledger rewrite unknown. Root approves this predecessor strategy and the dual-slot disposition subject to the binding rulings below.

## Binding root rulings for implementation

- L1-01: implement all three phases as one connected owner task with one full-range independent review. Existing public fork remains F1-C; helper/codec tests alone cannot close this owner task. Real B2/F0 READY, cold reconciliation, source-clear read/search and mixed managed/legacy closure are required.
- L1-02: approve the actual pre-funded dual slots and inode-preserving predecessor strategy. One deterministic revoked payload covers every explicit clear/delete cause; diagnostic reason does not alter permission bytes. Unknown/torn terminal slots never fall back to live. Ordinary scope revocation is temporary policy, not a data tombstone.
- L1-03: use ONE physicalBytes implementation for managed and legacy inventory. This is an explicit accounting correction: count hardlink aliases once only when actual bigint-safe nonzero device/inode identity is reliable; unknown identity is conservatively counted per path. Keep the existing32-slot tree-wide listing/stat bound, symlink refusal, safe overflow and joining of already-started I/O on failure. It measures retained file payload sizes, not allocated NTFS clusters or immunity to device-full errors.
- L1-04: before installing tracked transfer ownership, prove actual filesystem hardlink support and identity on the owned files. Missing/zero/unsafe/foreign identities or unsupported hardlinks refuse before any target owner addition; never substitute an unfunded copy. Test real aliases, distinct files, conservative unknown identity, interrupted predecessor rename and another managed writer after a crash cut. Do not change quota by inventing a separate reserve counter.
- L1-05: old canonical owner arrays remain valid JSON and can exceed64KiB. Stream their hashes, padded writes and readback; apply no bounded metadata-envelope limit to them. All mutations of a tracked ref use this original rewrite owner. Unresolved per-ref rewrites cannot be overwritten by another stale merge.
