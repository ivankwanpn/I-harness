## 已確認範圍

## 設計方式與取捨

採用既有 Desktop 元件、IPC、gateway 和 IH 執行 owner，擴充可驗證的操作契約。視覺參考 DSH `D:/agent-complete/deepseek-harness-dsh-v0.2.0-rc.2`、ZCode `D:/agent-complete/ZCode-main` 及使用者提供的 Codex 畫面；保留已有授權說明。主要入口放在對話標題列、Composer 和右側工作面板，設定維持現有分組。此方案便於把既有功能連到日常操作。

另一種方案是一次替換整個工作台，會增加會話／草稿／執行 owner 切換風險；另一種是只加更多子分頁，會繼續加深入口。本輪使用既有工作台和明確的直接入口。

## 全域約束

## 八個交付批次

### A. 輸入與導航

新任務使用完整 Composer；輸入、附件、模型及推理先保留為草稿，只有明確送出才建立會話並以耐久 admission 清空。`@` 選擇器提供專案檔案和可見會話的有界搜尋，插入可辨識引用。`/` 選單支援上下、Enter/Tab、Esc 及 IME，整合現有工作流程／設定／壓縮操作。Composer 權限選單顯示有效核准與沙箱，讀取／保存現有 API。標題列／工作面板直接進入 Goal/Plan、Team、背景工作與代審。不可用設定分類保留並說明前置條件。

### B. 多資料夾檔案與編輯

工作面板新增專案檔案樹、有界檔名搜尋及檔案分頁。根目錄名稱和相對路徑共同呈現；第二資料夾的檔案可讀、編輯及檢查成果。草稿放在面板生命週期外，保存修訂與原內容，跨面板關閉／工作區切換保留。關閉未儲存分頁提供保存、保留草稿、捨棄。重讀／外部衝突均明示；不把錯誤讀取或缺少檔案變成新檔案。

### C. 會話管理與搜尋

命中搜尋後載入包含指定 seq 的歷史視窗、標記命中並提供前後歷史載入。列表增加批次封存／還原、永久刪除及移動專案。永久刪除涵蓋本會話保存的相關文件，不刪除工作區來源檔案；活躍執行、待處理輸入／互動或活躍子代理先拒絕並解釋。跨專案移動須持久化成功後才更新分組，保存對話內容，重新根據目的專案計算執行範圍；不搬移來源檔案或繼承舊執行權限。子代理和代審不可藉批次管理混入普通列表。

### D. 初次設定與本機偏好

無工作區也可管理全域提供商、模型、憑證及模型探索；儲存與既有 gateway 使用同一配置契約。增加自動標題開關，於後續標題工作採用。通知中心保存已產生的本機通知並可回到可见會話，不增加喚醒排程。About 顯示實際 app/runtime 版本、可複製診斷資訊及目前更新機制狀態，不增加自動更新／公開發行。

### E. 資源與記憶編輯

技能可建立、編輯及從本機 SKILL.md 匯入到 workspace/global 層；插件內容保持來源可辨識並以複製方式建立本機版本。命令定義及本機 Hook handler 可編輯／驗證，必須接入實際執行所用 registry，不能只保存不生效。Hook 內容改變後重新判定信任。既有記憶筆記可 revision-checked 編輯與批次整理，保留明確 forget 確認；不宣稱已有自動記憶生成。

### F. 附件內容與草稿

單一 plus 選檔／貼上入口保持一致。新增 PDF、現代 Office（docx/xlsx/pptx）及 ZIP 的有界文字讀取；其他格式明示不支援。解析不執行巨集、腳本或外部連結，不把 archive 內容解壓到使用者資料夾；檔案數、輸入／展開量和輸出都有界。顯示格式、截斷及失敗原因。未送出的圖片、引用及文字附件存於自有草稿區，成功耐久 admission 後才清理；重啟可恢復，過期及 quota 有明確清理策略。

### G. 執行檢視與診斷

新增 Code Mode off/mixed/only 設定、當前有效模式、cell 狀態、程式／輸出／巢狀呼叫軌跡及有權時的停止操作。Code Mode 保存事件只做檢視，歷史不轉為 live。工具／環境診斷頁顯示 direct/deferred 工具、角色 allowlist、實際 Shell、執行檔／版本及未設定／未安裝／不可用／未測。Agent PTY／程序和背景工作提供 owner、活躍／歷史、可用輸出與權限下的附接／輸入／signal／resize；未實作 backend 的控制明確拒絕，不擴大沙箱。

### H. 記住核准規則

提供規則列表、作用範圍、有效期限、撤銷與新增。單次核准可明確勾選記住，預設不勾選。匹配用準備後的工具／可執行檔身分及已驗證參數；shell 前綴必須根據解析的 argv／命令結構驗證，不能以字串 startsWith 放行串接命令。保存規則不能繞過 sandbox、Plan Mode、角色限制、hooks 或撤銷後的工具 binding；沒有足夠匹配證據即要求核准。

## 驗收

每批以有意義的行為測試及 focused types 驗證，必要時實際檔案／JSONL／程序測試。各批獨立審查，最後凍結來源執行完整 `pnpm verify:all`、新便攜包及實際 Electron 點擊驗收。驗收逐項對照八批，包含新任務草稿、第二根檔案、衝突／草稿恢復、搜尋 seq、冷歷史零執行、永久刪除隔離、批次／移動、無資料夾設定、資源編輯生效、解析界限、Code Mode 狀態及規則撤銷。
