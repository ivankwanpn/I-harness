# v0.1.13 AGENTS.md／CLAUDE.md 與每會話上下文設計

狀態：研究後提案，尚未實作。基線 `460a2aee`。完整現況與來源見 `docs/research/2026-10-13-v0.1.13/instruction-files.md`。

## 目標

把已存在的兩種檔名載入能力，補成有明確目錄作用範圍、可診斷、支援子代理與歷史生命週期的 IH 指令子系統。所有模型與協議共用，不為 Codex 訂閱、OpenAI Responses、Chat Completions、DeepSeek 各造一個 loader。

不能只在父 system prompt 多貼一段文字。每個真正執行模型的 Session 應擁有自己的生效快照、已交付 revision 和 nested target 集合；檔案讀取快取可以共用，生效狀態不共用。

## 現況問題

- `instructions/src/files.ts` 已讀 AGENTS／CLAUDE，每目錄 AGENTS 優先；但往上找至磁碟根，沒有明確 project boundary。
- cache 在判斷前已讀完整內容，且使用所有檔案的最大 mtime／總大小，可能回傳舊內容。
- 24,000「bytes」實際按 UTF-16 字串切，讀檔也沒有上限。
- runtime-context 被捕捉在父 Session 的閉包；child pre-step 往父 scope 冒泡，不能給 child 建立正確快照。
- 只比較最後 raw snapshot，compaction／rewind 隱藏它後可能不再注入。刪除 instructions 但 skills 仍存在時，舊規則沒有清楚被撤回。
- 未提供來源診斷；深層檔案／其他 project roots／Code Mode 的原生寫入沒有自動載入適用指令的接縫。

以上為讀碼發現；實作先加重現測試，不把研究報告稱為已執行的失敗證據。

## 選擇的政策

1. **保留 per-directory winner**：`AGENTS.md` 優先，沒有才用 `CLAUDE.md`。同目錄兩者不默默合併；診斷顯示 shadowed。空的有效 AGENTS 仍是明確 winner，避免 v0.1.12 語意偷偷改變；非法／不可讀 candidate 顯示錯誤，不悄悄切成另一份規則。
2. 廣至窄排序，各來源帶 `scopeRoot`／`scopeDirectory`。更深規則只適用其子樹；不是看到過一次就成為整個 project 的全域要求。檔案內容是模型指引，不能提高沙箱、批准、provider system/developer 指令的權限。
3. host 提供 allowed project roots；取包含 cwd 的最具體已授權 root，再與可確認的 Git root 相交。無 Git 時使用選定 workspace；不掃磁碟根。Git worktree 的 `.git` file 要正確處理。其他已授權 roots 在實際 target 活化時載入自己的 chain。
4. globals 為 host 明確傳入的有序路徑。新配置原生位置是 `join(resolveHarnessHome(), 'AGENTS.md')`，其次同目錄 CLAUDE fallback。舊配置的 home／`.claude` 來源以一次性 migration 保留為明確 `globalSources`，畫面可關閉；隔離 `IH_CONFIG_DIR`／測試預設不讀 ambient home。不得自動加入 `~/.codex`。
5. 根範圍改為明確 project boundary 是版本行為變更；診斷列出原先會讀、現在在界線外的 ancestor，不複製／修改使用者規則檔。
6. 本版只承諾兩個檔名的 Markdown 與作用範圍。不聲稱完整模擬 Claude Code：`@imports`、`.claude/rules`、`CLAUDE.local.md`、managed policy、auto memory、AGENTS.override 暫不自動解譯／搜尋；遇到 import 樣式可提示未展開，不偷偷讀遠端／家目錄。這些不是本次三項目標的必要前提。

## 子系統結構

```text
packages/instructions/src/
  index.ts                 公開型別、建構入口
  discovery/               boundary、候選選擇、canonical identity
  snapshot/                bounded reader、快取、budget、render
  observation/             來源 invalidation 與 ref-count watch
  diagnostics/             loaded/shadowed/truncated/error DTO
packages/runtime-context/src/
  index.ts                 公開 section service
  sections/                每 Session 的 section/revision owner
  delivery/                snapshot、replace/clear、模型可見性
packages/session-executor/src/context/
  index.ts                 main/child 共用 factory
  instructions.ts          host policy、source、快照接線
  targets.ts               原生工具 target 預檢與 model epoch
  lifecycle.ts             restore/compaction/rewind/dispose
```

目錄依責任拆，只有需要獨立狀態或測試的單元才再分檔。不增加泛用 VFS／全域 prompt bus。instruction resolver 不讀整個會話日誌；runtime-context 不自行找檔案；Desktop 不重新解析來源。

## 新介面

```ts
interface InstructionScope {
  cwd: string
  roots: readonly string[]
  globalSources: readonly string[]
  enabled: boolean
  maxBytes: number          // 預設 24000，整個 rendered UTF-8 budget
}
type SourceState = 'loaded' | 'shadowed' | 'truncated' | 'unreadable' | 'outside-scope'
interface InstructionSourceStatus {
  path: string
  scopeDirectory: string
  kind: 'AGENTS.md' | 'CLAUDE.md'
  state: SourceState
  bytes: number
  contentHash?: string
  message?: string          // bounded，沒有全文
}
interface InstructionSnapshot {
  revision: number
  fingerprint: string
  text: string
  bytes: number
  sources: readonly InstructionSourceStatus[]
}
interface InstructionService {
  prepare(paths: readonly string[]): Promise<InstructionSnapshot>
  snapshot(): InstructionSnapshot
  invalidate(paths?: readonly string[]): void
  subscribe(listener: () => void): () => void
  close(): Promise<void>
}
interface SessionContextHandle {
  prepareTargets(paths: readonly string[], mode: 'read' | 'mutate'): Promise<void>
  beforeModelRequest(): Promise<void>
  acknowledgeModelSnapshot(requestId: string, fingerprint: string): void
  close(): Promise<void>
}
```

`prepare` 是 initial／dirty／新 target discovery 的按需同步，不是定時輪詢。`snapshot` 不做磁碟 I/O。事件只使相關來源 dirty；下一個模型邊界或明確請求重建一次。重建期間又變更就追加一輪，不能丟 dirty bit。

reader 在開啟 regular file 後 bounded read；global＋ancestor＋active targets 合計最多 256 個來源，深度最多 128，超出回顯示錯誤且不宣稱完整載入。使用 UTF-8 安全邊界截斷，headers 和 truncation marker 計入 24,000 上限；zero 禁用且不讀內容。每檔 stat／hash／canonical identity，事件使快取失效；不再以 max/sum 判斷。恢復 watcher 作一次 reconcile，沒有每一步全量 stat 作 fallback。

symlink／junction 的實際 target 必須仍在核准來源界線內；canonical identity 去重，但保留 lexical path 作作用範圍。來源失效／撤權立即移除；暫時讀取故障可保留有標記的 last-known-good，mutation 必須等待可靠快照或向模型回傳可處理故障，不能假装已讀到最新規則。

## 正確的 Session 與歷史生命週期

新版本 `runtime/context` 事件保存 `{version:1, sections:[{id, revision, fingerprint, text, sourceRefs}]}`，代表完整當前 snapshot；空 sections 明確 clear，移除單一 section 也是真正移除。event projection 只把最後有效快照放到模型上下文，舊快照保留在審計日誌但不再同時生效。

main、no-fork child、all-fork child、有限歷史 child、重建 child 都使用 `session-executor/context` factory。parent hook 檢查 payload Session identity；child 不得 append 到 parent log。child 從自己的 workspace／roots 和 globals 政策建立規則，fork history 不能代替這個步驟。

模型上下文推導／compaction／rewind 使用有效事件視圖判斷最新快照；若被 shadow 或回退，每次請求前重新建立當前上下文。checkpoint／摘要不是目前檔案的權威。舊 `i-harness/runtime-context` user messages 可以讀取，但第一個 v1 snapshot 後不再作現行規則；不刪除歷史。

每個模型 request 記錄實際附帶的 fingerprint，重試同一 request 使用同一內容；檔案更新只在下一個安全邊界生效。不得每次請求加入時間戳或無意義 revision 文本，避免快取前綴反覆變動。三種模型協議測試同一語意，無 provider 私有 header。

## 深層指令必須先被模型看到

僅在 read 後載入規則不足以承諾「寫入前已遵循」。本版納入 target-aware 原生工具流程：

- Fs read／list／edit／write／apply_patch 提供由工具實作解析、正規化的 target descriptor；不能由任意模型 JSON 宣稱 authority。維持既有 sandbox／approval 順序與檢查。
- 整個原生 mutation batch 在任何 write 前，先收集全部已知 target chain；如果出現模型尚未看過的新／已變更規則，保存新 snapshot，回傳明確可恢復的 `INSTRUCTIONS_REPLAN_REQUIRED`，原寫入不執行。下一個 provider request 見到新規則後由模型重新決定工具參數。
- scheduler 必須特別識別這個 disposition，不能把它誤當 policy refusal 或讓一半 mutation 先執行。其他不相關的已派出工具仍正常 drain；不回滾已合法完成的副作用。
- Code Mode 在新規則需要模型解讀時，停止該 cell 的後續執行並回交外層，已開始的巢狀工作依 owner 收尾；JavaScript `catch` 不能清除這個 host replan fence。不得重新執行原 cell。新程式由模型重建。
- shell 只自動處理 host 可確認的 command cwd；任意字串中的 `cd`、腳本、重導向、程式生成的路徑不聲稱可靜態完整解析。提供 `instructions_get({paths})` 供模型明確活化 target，再規劃 shell。prompt 和診斷必須說明此界線。
- 不在每個讀取中把所有兄弟目錄規則變成全域；已活化 target 的 scope 標籤隨快照保存，來源刪除／membership 撤銷要清除。

## 可觀察性及遷移

在既有診斷／會話資訊中新增「專案指令」來源表：載入／被遮蔽／截斷／錯誤／界線外，展示作用範圍、版本、byte 數，支援明確 refresh。顯示的是 assembly 使用的同一份 snapshot，並沿用事件設計的 revision 訂閱；不可每秒重新讀檔。

配置加 `instructions.enabled`、`instructions.maxBytes`、`instructions.globalSources`；globalSources 僅接受 host／使用者配置，專案指令內容不能反過來改來源權限。設定未儲存草稿保留；model child 的來源表仍經 lineage／visibility 驗證。

## 驗收

1. AGENTS-only／CLAUDE-only／同目錄同時存在／跨層混合的實際 model request 與來源表一致。
2. 相同時間大小、舊檔同長修改、新增高優先 candidate、刪除 fallback 切換、emoji／CJK 邊界、巨大檔案、zero、錯誤來源都可重现且不超 budget。
3. 磁碟根／其他 sibling root／junction escape 不自動升格為指令；合法 worktree 和多 root 作用範圍正確。
4. no-fork／fork／restore child 各有快照，child pre-step 不改 parent；compaction／rewind／partial clear 後實際 request 只含當前規則。
5. 直接寫、patch 多檔、parallel batch、Code Mode read-then-write／catch、source 修改競態：模型看見新規則前零 mutation；恢復後不重播已完成操作。
6. 正常 idle／未 dirty 的 pre-step 沒有重讀全部檔案；watcher 失效有明確診斷和恢復 reconcile。
7. CLI／Desktop／子代理／三種協議同一套資料來源；不以渲染測試代替真正 request 內容斷言。
