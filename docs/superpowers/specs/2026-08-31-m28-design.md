## 2. R-B13 apply_patch AST 驗證

**目標**：patch 內容中的 shell 命令（apply_patch 分割 `*#` 執行模式——以現有實現為準）進行語法解析驗證——tree-sitter 防注入加固（codex `apply-patch/src/invocation.rs` 同思路）。
**機制源**：codex（tree-sitter + tree-sitter-bash AST 驗證命令注入）。
**IH 化**：
- `packages/fs` 的 apply_patch 執行器：若工具接受 `command`/shell 部分（檢查現有 apply_patch 是否支持嵌入命令——**若現有實現無命令嵌入，本項降為「無驗證面 → 記錄為防線已足夠」**並停止——spec 第 2 行已標風險：調研在前）。
- 若有命令面：引 `tree-sitter`（原生,Windows prebuild 可用）+ `tree-sitter-bash`；解析失敗 → 拒絕（fail-closed）。
- 測試：惡意/畸形命令（`rm -rf` 語法合法但區分注入模式）vs 正常 patch;語法解析失敗 → PatchError。

## 3. R-B9 fs watch

**目標**：檔案變更事件流（opencode parcel-watcher 語義;chokidar 實現——dsh settings-file 同選型）。
**IH 化**：
- 新子包 `packages/fs-watch`：`createFsWatcher({ roots, ignore })` → `{ events, close }`；`events` 為 `{path, kind: "add"|"change"|"unlink"}` async iterable。
- `ignore` 尊重：現有 gitignore 掃描器（`.gitignore` 尊重資料已存在於 fs 包?—— 檢查;無則 chokidar ignored 陣列內置 `node_modules/.git/.i-harness/dist`）。
- 接線（可選）：assembly 的 `WatcherSettings`——**默認不掛**（無消費方）;供 host（web/其他）訂閱;A4/A5 仍 turn 前檢查（不改）。
- 測試：tmp 目錄變更→事件;ignore 列表過濾;dispose 停止。

## 4. R-C7 ACP server

**目標**：automation-only ACP（dsh `acp` 同定位——presentation/human 面留 UI 層）。
**IH 化**：
- 新包 `packages/acp`：`createAcpServer({ service: SessionService, version })` → 返回 ACP handlers（官方 SDK 的 `@agentclientprotocol/sdk`：`ndJsonStream(process.stdin/out)`）——支持 `initialize/authenticate/serverInfo`、`session/new|list|resume|close|setConfigOption`（子集）、`session/prompt`（掛 service.submit + 事件轉 transcript?—— **v0：prompt 唯 fire-and-forget or await?** dsh 是 await 式;我們 `session/prompt` 回 `{messageId}`（admission 回執）與 SDK client 相同（SDK 有 ad-hoc `HarnessSession`…… 精確對齊 dsh acp 的觸面：`session/prompt` 回 sessionUpdate）。
- permission：`session` ACP 的 requestPermission 決策——把 A 區 guardian/approval 面接上:ACP `session/requestPermission` → 進程持有 pending → host 回應（stdin/stdout 同 mux?）**v0：許可面 = 僅回 allow-once（auto-approve 注入 controller）**——標記為 v1 增項。
- CLI：`i-harness acp`（stdio 直通）。
- 測試：官方 SDK client 子進程回環（new/prompt/cancel）——mock 模型。
