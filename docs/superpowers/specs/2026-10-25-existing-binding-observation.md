# Existing-session metadata and binding observation design

This is a prerequisite of the approved F1-C public semantic fork/strict-reader work. Root approves one connected persistence-owner task; it does not authorize public fork DTOs or host readers yet. Product0.1.13-rc.1, Session12 and all existing persistence formats stay unchanged.

## Binding decisions

- ER01: Add optional withExistingSessionBindingObservation<T>({sessionIds,signal?},callback) to the actual coordinator. sessionIds is a closed dense distinct safe-ID set of1..64 existing sessions, matching the established lineage bound. Returned observation exposes only guarded metadata(id), binding(id), assertCurrent. Metadata is actual current backend profile; binding is the exact derived desktop-session-project key read through the strict observed-document backend. Captured JSON is immutable.
- ER02: Reuse the same F0 observation owner, affected-ID/key indexes, actual session claims/document leases, pending/deleted/retiring admission, AsyncLocalStorage self-wait checks, original acquisitions and cleanup. Use distinct fork/read scope kinds; read has NO invocation/target and NO bootstrap exemption. Only an actual fork scope preserves its exact original invocation exemption.
- ER03: Validate/copy before acquisition; register the scope before the first await; sorted session pins then sorted derived document leases; actual profile under short released session lanes; strict document read; callback outside all lanes/docChain. Guards check actual held identities and admission before/after awaits. Invalid/accessor/proxy/unknown input must not acquire or invoke getters. Missing/archived/deleted/unavailable session never becomes absent binding success.
- ER04: Metadata/binding mutation, delete, managed-document retirement/release and coordinator close synchronously revoke affected scopes before joining them. Metadata/project ABA never revives an old scope. Self-overlap/mutation/close/bootstrap refuses before pending work can deadlock or revoke its own outer callback. Independent work and disjoint nested scopes remain supported.
- ER05: Register late-acquired resources before an after-await guard may throw; retire synchronously, release document locks then temporary claims, attempt independent cleanup, preserve persistent adopters. Actual original cleanup debt survives failure. Known pre-release failure retries the same handle; consumed-held uncertainty cannot become a successful no-op. Read cleanup diagnostics carry frozen sessionIds, never a fabricated invocation. Callback primary errors/results remain represented correctly.
- ER06: Capability has exactly the existing supported locking/strict backend/Windows-or-Linux gate. No tolerant getDocument fallback, fake lease/receipt, arbitrary document snapshot, new project registry or new lock export. Windows qualification does not imply another platform was run.
- ER07: This callback does not freeze managed fact append, establish READY, refresh managed headers, authorize project roots or implement context-output visibility. An actual append control must demonstrate that boundary. Later host readers open and validate actual READY view outside this callback, combine current metadata/broker policy, and guard actual view/currentness around predicate/body/search work.
- ER08: Preserve all original F0 tests and exact target-only behavior. New method/types must be reachable through the real coordinator, but this prerequisite is not a completed production reader or public fork rollout. No SDK/CLI/Gateway/Desktop/ContextOutput/core-agent changes in this task unless a causal root ruling assigns them.
