# v0.1.13 產品程式子系統拆分設計

狀態：研究與設計，尚未改產品程式。基線 `460a2aee`。

歷史狀態補充：上述是最初設計時點；截至2026-10-14，S1–S19已完成27個原檔並暫停，見[追蹤表](../../refactoring/v0.1.13-decomposition-map.md)。2026-10-15使用者要求將上下文重構與原拆分重合責任合併交付，依[重合地圖](../../refactoring/2026-10-15-context-decomposition-overlap.md)執行；本設計的責任分離、尺度、所有權、測試／工具腳本排除與完成gate繼續適用，不需把同一責任重複拆兩次。

## 使用者要求與精確範圍

0.1.13 必須處理全倉庫過大的產品程式，不限事件驅動或指令功能碰到的檔案。目的是降低後續 AI 代理開發與維護時的上下文負擔、漏改／誤改和隱藏耦合。**測試檔和工具腳本不拆分**；只允許為產品改動作必要 import／fixture 接縫調整，或補實際缺少的驗證。第三方／產生檔不拆。

量測完整紀錄見 `docs/research/2026-10-13-v0.1.13/large-files.md`；實作範圍機器清單是同目錄 `census.json` 的 43 個 `candidateAnalysis` entries。

| 指標 | 基線 |
|---|---:|
| 產品程式檔 >=800 physical lines | 15 |
| TS function/component >=250 lines | 46 spans，跨38檔；包含巢狀重疊 |
| 大檔／大函式聯集 | 42產品檔 |
| 額外高密度 SessionManager | 1檔（函式185行、20,560字元） |
| 本版需要逐項處理的產品檔 | **43檔，32個子系統組** |

行數含空白／註解，不把它當複雜度分數；AST span及密度補充發現短但壓縮嚴重的程式。原生 runner 有內嵌測試，測試原地保留，拆產品部分。清單是基線，若新增實作又產生大檔也要納入最終檢查。

## 採用方案

**一個子系統一個目錄，一個公開入口，狀態所有權留在該子系統。** 先移動既有責任、不改行為，再在獨立 commit 加事件或指令功能。拒絕兩種替代方案：只按行號剪成多檔；一次重寫所有核心並同時改協議和行為。前者只是移動耦合，後者無法隔離回歸。

外部使用 `index.ts` 或原 factory façade；內部模組分辨 types、policy、pure projection、state owner、producer、lifecycle。不建立 `utils.ts`／`helpers.ts` 堆積區，不向每個模組傳入整個巨大 mutable context bag。不把一個 closure 內的Map複製成兩個權威store。

大型factory是組裝入口，不應繼續包住數百行業務邏輯。抽取需具體narrowdependencies，例如：

```ts
interface CompletionAdmissionDeps {
  readonly ownerSessionId: string
  isOpen(): boolean
  flush(): Promise<void>
  scheduleAdmitted(inputId: string): void
}
// 不接受 deps:any、整個 SessionService 反向穿透，或共享所有私有 locals。
```

## 全部子系統

逐檔 paths、函式邊界、現有 consumers、目標私有模組與測試入口已在 `large-files.md` 的「Concrete production subsystem map」及「All 43 production candidate files」兩表；它們是本設計的規範附件。

32組包含：Settings、Session model/projection、Provider catalogue/runtime、五種provider adapters、Plugin scope、Tool registry、Hooks、MCP supervisor、Shell、Exec/supervisor、Native PSEC runner、Code Mode、Code Retrieval、Compaction、Persistence、Session query、Subagent、Team、Session assembly/service、Core agent/batch、SDK、CLI、Gateway host/router、Project scope、Subagent catalogue、Coding Plans、Desktop IPC、Runtime diagnostics、App、Workbench、Composer、SessionManager。

### 跨三份計劃的目錄裁定

- `session-executor/assembly/` 負責組裝；`service/` 負責submit/queue/state façade；`lifecycle/` 持有assemblycache／publication／close與generation fence。三者透過狹窄介面共用同一owner，不各建Map。
- `session-executor/completion/` 是事件計劃的新責任；`context/` 是指令計劃的新責任。純拆分階段先抽出接縫，不預先實作新語意。
- `settings/schema/`／`normalize/`／`storage/`／`observation/` 為唯一位置；不在事件計劃再造第二watch store。
- `core-session/events/` 定義型別與schema；`projection/`讀取權威事件。新的work/runtime-context事件在這些模組擴充，facade不再堆所有union處理。
- gateway使用既有domaincontrollers；新的 `observation/`、`workspace-observation/` 只是協調訂閱／版本，不成為第二份domain資料。
- 原有 import 路徑在第一輪保留薄 façade；真正不用的過渡 exports 必須移除，不能為通過reachability製造假consumer。

## 每個子系統的交付內容

1. 目錄入口只匯出實際需要的contract／factory；維持package exports相容。
2. 一份短README：責任、publicAPI、主要狀態owner、啟停順序、不可破壞的不變量、相關測試指令。這是給後續代理快速定位的維護地圖，不是大量重複程式碼註解。
3. 變更依賴只能向下，不能形成新cycle；internal path只有同子系統能直接import。
4. teardown由原owner管理，先revoke/stopadmission、join、再release；抽取不能改掉listener註冊時序、preparedcallidentity、原生handle／worker生命週期。
5. Provider adapters各自保留request／SSE／usage／cache／retry差異，不因拆分把協議強行統一。
6. React抽取保持component identity、keys、retained hidden form、draft／pending action所有權；不得以改hook依賴方式隱含改行為。

## 尺寸與完成標準

建議工作尺寸：產品模組約150–400行、function/component通常不超過120行、組裝facade約150–250行。這是review提示，不是讓人靠壓縮程式／搬註解達標的硬配額。

完成必須有43檔的before→after manifest：每檔移出哪些責任、到哪個子系統、剩餘尺寸、公共介面、測試證據。所有>=800產品大檔要移除巨型職責；所有longfunction/density候選要有實質分解或具體的單一演算法／純資料例外證據。不能只標「已看過」結案，例外在發佈報告明列。內嵌測試不納入產品budget，也不為改行數搬走。

不得刪除測試、放寬timeout／permission／assertion／reachabilitybaseline以假裝結構等價。工具腳本不是拆分對象；如其source-pattern檢查因產品路徑搬移而失效，只更新被查核的owner路徑／結構契約，保存原判斷力。

## 驗證與遷移

- 每slice先跑受影響既有suite，移動後同suite與typecheck；必要characterization是針對未被覆蓋的所有權／順序，不寫逐行鏡像測試。
- 對協議／檔案格式／CLIstdout/errorcode／eventsequence以同fixture比對實際輸出；TS編譯成功不能代替語意相等。
- 原生code須nativebuild/tests與實際受支援driverfixture；source-only mocks不代表完成。
- 每組commit與review獨立。功能語意變更在事件／指令計劃另列commit，能單獨回退純結構變更。
- 所有43候選完成後重新量測，確認沒有搬到另一個巨型檔案；全倉庫imports／reachability、固定HEAD verify:all和打包entrypoints一起驗證。

## 排除

不拆測試檔／audit腳本，不改第三方vendor，不更換框架，不為資料量大的generated文件套行數限制，不做與本版三目標無關的功能改寫。
