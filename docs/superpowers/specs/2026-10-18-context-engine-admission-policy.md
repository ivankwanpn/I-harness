## One active decision owner

ContextEngine owns a pure decision over the exact selected prepared candidate, actual purpose, captured binding, measured input, sourced limits and resolved local policy. Token-meter remains the measurement and B2 calibration owner. Adapters own protocol validation, output-floor/ceiling facts and final encoding. F4 owns actual generation allowance, deadlines and transport issuance. Persistence owns the existing durable facts and recovery.

Activate the shared decision in main, changed-input recovery, summary, isolated/child approval and title. Direct audio uses an explicit honest compatibility decision over its real payload and F4 media action. Preparation, assessment and observations cannot send/authenticate/count, spend or replenish a generation allowance, execute a tool or publish a replacement.

Decisions distinguish admitted capacity, compatibility authorization with named unchecked dimensions, required reduction in a known failing dimension, and blocked input. They do not promise provider acceptance. A strict caller may reject compatibility authorization. Binding/protocol validation failures never become ordinary unknown-capacity compatibility.

Capacity compatibility is not transport permission. F4's real selected-client/prepared-terminal ownership and execution-domain checks still apply. A neutral-only custom assessment may truthfully describe unknown dimensions without making an arbitrary custom execute callback eligible for managed physical or local-test execution.

Only one active capacity calculation may remain. Remove the existing main legacy assessor arithmetic, private summary fit/safety calculations, reduction bridge/proposal threshold calculations and auxiliary clamps at activation. Stateless compatibility facades are permitted only for real existing consumers and must reflect the active decision honestly.

## Capacity domains and unknown facts

Track numeric provenance separately from capacity semantics. A known generic context number alone does not prove whether the provider couples input and output. Sourced capacityDomain is shared-context or input-only; absence is unknown.

- Proven shared context uses its active window and the equations below.
- Proven input-only capacity checks input against its independent limit, and output separately. Do not subtract an output cap from an input-only limit.
- Unknown provider coupling may preserve existing subtraction only as the named local planning assumption ih-legacy-shared-capacity-assumption-v1. Mark provider coupling unchecked; do not describe that assumption as verified provider capacity.
- Missing active window is not supplied by a generic maximum ceiling. A configured active window above a sourced ceiling requires an explicit conflict decision; do not silently certify it.
- Complete legal local input with unknown capacity may use ih-unknown-capacity-compat-v1, with no capacity percentage or ratio-based compaction target.
- Neutral-only custom preparation also declares unchecked protocol/projection coverage. Missing remote or incompatible provider-held context and malformed native state remain blocked.
- Complete local media with unpriced token cost remains distinct from incomplete remote input. Unknown is never zero tokens, a positive hard-fit claim or a fabricated audio-to-token conversion.

Capacity, input estimate, HTTP body bytes, SDK command size, provider-reported usage, cache counters and billing are different domains. A command-size or component estimate cannot certify an exact HTTP-body limit. A sourced body limit remains independently enforced even if token capacity is unknown. No provider count-request fallback is introduced by E.

## Equations and local defaults

Let W be the applicable shared planning window, H=ceil(W*h), R the actual bounded wire output cap or an explicit unsupported output budgeting allowance, and I the selected candidate's labelled estimate.

For bounded output or an explicit unsupported allowance:

    sharedInputBudget = W - R - H

For omitted/provider-managed output:

    sharedInputBudget = W - H
    output bound = unknown

Combine a shared budget with any independently known input limit by taking the smaller applicable value. Input-only capacity does not acquire shared subtraction. Negative available room or a required output floor conflict is not a successful zero-cap decision.

Main and changed-input recovery retain h=.10 from their existing safety policy; summary retains h=.05. Approval/title explicitly adopt ih-aux-inherited-main-safety-v1 at h=.10. This auxiliary rule is a new local inherited policy, not a claim about their previous implementation. Existing explicit reserveRatio maps to h=1-reserveRatio with additive bounded-output semantics.

For effective input budget B:

    hardFits   = I <= B
    trigger    = floor(triggerRatio * B)
    target     = floor(targetRatio * B)
    softNeeded = I >= trigger
    targetReady = I <= target

Default triggerRatio=.8 and targetRatio=.7 provide local hysteresis; they are not measured optimal values. Preserve an explicit trigger number under the new B denominator. If an absent default target conflicts with that explicit trigger, derive targetRatio=.875*triggerRatio. An explicit target must satisfy 0<targetRatio<triggerRatio<=1. Validate real config and per-model overlays before effectful preparation or model issuance. Expose targetRatio through the actual configuration path, not an unused internal field.

auto:false disables soft work only. Hard overflow and confirmed recovery still use their real bounded path. Hard-fit, reduced-over-target and target-ready are distinct outcomes. Only the selected complete final candidate may supply these results.

## Reduction and durable soft-work state

Reuse accepted C3 selected-source, private full-request reassessment and guarded publication. Do not recreate prefix filtering, a synthetic second session, prune-before-summary publication or a ready-producing legacy fallback.

Relevant input/byte reduction is measured between exact final candidates under comparable evidence. A changed payload hash or smaller output cap alone is not reduced input. Unknown estimates cannot prove monotone input progress. Final target readiness uses the same policy as the main admission decision.

One eligible semantic work key permits one soft reduction sequence. Work keys use accepted closed exchanges, newly admitted relevant human/child/tool-result input, protection/source state and actually relevant policy/binding values. Action/attempt, diagnostics, budget/usage observations, unrelated settings and global revision counters are not semantic advances.

Default cooldown becomes three accepted closed-exchange advances, including tool cycles within one human turn. Preserve explicitly supplied minTurnsBeforeRecompact as human-turn cooldown. Add the new exchange control through the real config owner; conflicting simultaneous controls are rejected. Hard overflow/confirmed recovery bypass soft cooldown without renewing F4 allowance.

Persist soft-sequence start and terminal outcome through the existing managed document and closed versioned facts. Count one failed reduction sequence, not each physical summary retry/piece/quality round. Three failures open the breaker; changed eligible work permits at most one further sequence without resetting failure history. Only committed target-ready completion resets it. Merely changed or reduced-over-target results, publication unknown, diagnostics and reopen do not reset failures or create free work.

Summary source split/merge stays finite within C3/F4's one sequence and summary physical limit. It must not recursively compact its own session, publish intermediate summaries, obtain another lease or renew the allowance.
